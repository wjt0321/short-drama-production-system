# 开源短剧提示词与「演员调度 / 运动学合同」研究（2026-10）

> 目的：从已核实开源仓库与官方模型卡里，找出"演员在画面里到底怎么动"的实证做法；
> 把这些做法汇成一份「运动合同」——任何平台写提示词时都应满足的硬条件。
> **本文件不搬运任何仓库的完整模板**（许可证情况见 §1.1：MIT / LGPL-3.0 / 仅 Go-Ai-Studio 无 LICENSE）；
> 只抽取「开源短剧实际验证过」的最小可观察机制，写到本体系自己的提示词层。

## 〇、一句话

**"告诉模型『不倒退 / 不滑步』是没用的；模型不理解否定。**
**告诉它『头先动 → 肩转 → 髋跟上』才会动。"**

任何交互动作（走 / 跑 / 拿 / 推 / 转身 / 接触 / 落座 / 翻找 / 持物移动）的提示词，
必须包含 **9 项运动合同字段**——见本文件 §二。

## 三、本次核实的「实证 vs 推导」区分

> 用户反复提到"车轮耦合"——这是真实证，还是凭直觉？
> 下面把每条结论区分清楚，避免把"看起来对"当成"验证过"。

### 3.1 真实证（来自仓库 README / 卡口）

- **CFG=1 + 不要负向约束**：Wan2.2 5B 与 H3 官方卡口都明示；
  写入 `no text` 会让模型产生 text，因为模型不理解否定，只复制关键词。
- **首帧冲突直接走样**：H3 与 Wan 仓库的 issues 都报告过：
  如果首帧已"完成态"（车已停下 / 椅子被坐住），模型不知道从哪开始动。
- **multishot motion 分段**：H3 卡口明示"`motion_segments` 与 `camera_segments` 必须分写"；
  把动作和摄影机写同一段会让运动被相机运动吃掉。

### 3.2 合理推导（轮子耦合、脚步声等）

- **车轮耦合 / 持物步态**：huobao 与 LocalMiniDrama 仓库的范例里
  **手→把→臂→车体→轮**链路写得很完整；
  这是因为手与把接触、把松脱，车不会停也不会动。
  但**没有仓库做过对照实验**证明"写了耦合就好，不写就坏"。
  本体系把它列为"高置信做法"，不当作"硬科学"。
- **转身 = 头→肩→髋**：动画 / 动作捕捉资料里一致的做法，
  但 I2V 模型是否真的能区分，没有量化实验。
  本体系写为"正向机械示例"，不当作唯一答案。
- **脚步声 / 接触重试**：在 5 秒生成里基本听不到；
  本体系写"脚步声可参考"，但不列为硬要求。

### 3.3 不建议写成硬规则（缺实证）

- "转身必须 0.6 秒以内完成"——任何秒数限制都来自单模型单次实验。
- "转身必须先慢后快"——没看到实证。
- "车轮角速度必须匹配车速"——可读性差，模型大概率忽略。
  本体系只要求**方向与速度一致**，不要求数值精确。

## 二、9 项运动合同（必填）

> 任何含人 / 道具 / 接触 / 移动 / 转身 / 拿取的镜头，提示词必须给出以下 9 项。
> 短镜头或纯氛围可压缩其中 1–2 项，但必须显式说明哪一项不写及理由。

### 2.1 屏幕坐标与向量

- 主体在画面里**绝对坐标**：`左侧 1/3 / 中央 / 右侧 2/3`，
  不要写"附近"。
- 位移方向用**屏幕向量**：`向右 → / 向画面深处 ↘ / 向上 ↑`，
  不要写"往前走"——模型分不清摄影机方向和世界方向。
- 起点 vs 终点坐标都要写：`从画面左 1/3 移到画面右 1/3`，
  不是"移动一段距离"。

### 2.2 主体初始朝向 / 朝向变化

- 起始：脸朝画面右 / 背朝镜头 / 侧身 45°；
- 过程：始终面朝画面左 / 转身 180° 朝向镜头；
- 不要写"他看了看"——必须写"视线从画面右侧物体转向镜头"。

### 2.3 移动方向与世界坐标

- 世界方向：`向画面深处走 / 镜头前方右侧走 / 远离镜头走`；
- 不要写"他走过街道"——必须写"他沿画面右侧从前景走向远景"；
- 与摄影机方向的关系：摄影机跟拍 = 主体相对画面位置近固定，但世界位移；
  摄影机不动 = 主体在画面内坐标发生明显移动。

### 2.4 脚步 / 重心

- 行走：起步脚（左 / 右）、承重脚、落脚方向；
  "左脚迈出 → 右脚承重 → 左脚落稳"；
- 转身：先头 → 后肩 → 再髋；
- 不要写"他走了几步"——纯文字版"走几步"在 I2V 里基本不生效。

### 2.5 手 - 道具接触点 / 承重 / 解除

- 接触点：哪只手 / 哪根手指 / 哪个部位接触道具哪一处；
- 承重：道具重量在手上体现的方式（手指弯曲 / 掌心下压 / 道具悬挂在指尖）；
- 解除：何时松手 / 物体何时离开手；
- 不写"拿起杯子"——必须写"右手拇指与食指夹住杯柄，
  中指与无名指承杯底，抬起后小指外伸保持平衡"。

### 2.6 道具 / 轮子从属运动（车轮耦合）

- 手把 / 车把 → 手 → 臂 → 主体躯干位移 → 轮子转动 → 远景后移；
- 写字 / 翻书 → 笔尖 / 书页跟随手指运动；
- 不写"推车走了"——必须写"左手握住车把上缘，
  右手握下缘，双臂前侧向后推；
  主体随之前倾；车轮从右向左转；
  远处墙面依次左移 → 视觉上前进"。

### 2.7 摄影机方向与主体相对速度

- 摄影机不动：主体在画面里位移明显；
- 摄影机跟拍：主体在画面里位置近固定，但远景在动；
- 反向移动：摄影机向左推，主体向右走 → 视觉上主体相对摄影机向右滑出画面。

### 2.8 轴线 / 视线

- 轴线：角色之间的左右关系；
  "男主始终在画面左侧，女主始终在画面右侧"；
  跨越时给"转身 / 过肩 / 空间重建"。
- 视线：看向谁、往哪个屏幕方向看、何时回看；
  不写"他们对视"——必须写"男主视线由画面右侧的女主移回镜头"。

### 2.9 结束状态

- 终点坐标 + 朝向 + 与下一镜接力关系；
- 与起始状态**必须有可见差异**——同样的姿态视为未设计。

## 三、关键平台 / 卡口的具体做法

### 3.1 Wan2.2 5B TI2V

- **CFG=1**：禁写任何 "no / never / doesn't"。
  写"无字幕"反而会出字幕。
  **正确**："画面内**没有任何**字符 / **保持**门牌空白"；
  若平台支持，把"没有任何字符"放在正向标签 `integrated_multimodal_description` 里。
- **不要把摄影机动词和动作动词堆同一段**。
  `push in while the woman walks` 在 Wan 上会让动作被推镜吃掉。
- **首帧冲突**：若首帧是"她已坐到椅子上"，模型不能给出"坐下过程"——
  改 FLF2V（首帧坐前，末帧坐后），或重做首帧（站姿起步 → 坐下过程）。

### 3.2 H3 Multishot / I2VA

- **多镜分段**：`motion_segments` 与 `camera_segments` **必须分写**。
  同一段里写"摄影机先推 + 主体走过来"会让两者互相牵制。
- **首尾帧可接管**时不要用文字硬拧：
  当镜头要"从 A 到 B"且 FL2VA / FLF2V 可用，优先用首尾帧做，
  不要在 I2VA 提示词里硬写"B 状态是什么样"——硬写会让模型偏离 A 状态的中间过程。
- **motion-only 段**：把"动作过程"放到 `motion_segments`，
  不要和摄影机混在 `overall_soundscape` / `integrated_multimodal_description` 里。

### 3.3 Toonflow（世界坐标 + 相机）

- 把**摄影机当成世界空间里的对象**：
  position `(x, y, z)` + FOV `vantage / focal`；
  主体在世界空间的位置是 `(x, y, z)`；
  摄影机看主体的 target 是 `(x', y', z')`。
- 这样写的好处：转身 / 走位 / 持物移动都能用坐标验算。
- 当 I2V 不支持坐标，就用屏幕坐标（§二.1）。

### 3.4 huobao（火孢 / 车轮耦合示例）

- 推车 / 持物移动必须写**链式运动**：
  手把方向 → 踏步方向 → 身体方向 → 车轮方向 → 远景视差方向，
  五项方向一致才推得动。
- 反例：闭合钥匙只写"推车"会让车停或人倒退。
