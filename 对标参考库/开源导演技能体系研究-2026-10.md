# 开源导演技能体系研究（2026-10）

> 调研日期：2026-10-13
> 调研目的：为「通用型、不耦合、不强绑、不绑定供应商、渐进式」的导演方法层寻找可借鉴的开源实现，避免重复造轮子，也避免把外部仓库的耦合直接搬进来。

## 一、结论摘要

1. 外部确有成熟的导演类 skill 项目，最成熟的是 **DirectorSKILL**（MIT、纯 Markdown、零依赖）。
2. 它们的**最有价值产出是 schema 与纪律**（风格如何变成机器可读字段、情绪如何变成物理量、风格之间如何用反例区分），而不是它们的**具体数值**。
3. 它们的数值几乎都面向**真人电影宽银幕**（分镜平均 12–40 秒、画幅 1.85:1–2.39:1），与短剧「竖幅 9:16、1–8 秒一刀、前 3 秒钩子」差异巨大。**schema 可借，数值必须重写。**
4. 因此本体系采取 **「借结构，不借内容；借纪律，不借数值；不转载原文」** 的收敛方式，做法与 `01-创意与剧本/短剧编剧引擎.md` 既有先例一致。

## 三、DirectorSKILL 深度结论（`observed`）

### 3.1 概况

- 仓库 `wuwangzhang1216/DirectorSKILL`；License **MIT**，版权行 `Copyright (c) 2026 wangzhang-wu`（`official`）。
- 纯 Markdown，无可执行代码、无依赖、无安装步骤；CI 仅做 markdownlint 与链接检查。
- 自述为 director / previs supervisor，输出模式 A–J，管线 10 步（v2 扩到 13 步）。

### 3.2 最大价值：导演风格的机器可读 schema

其 20 个风格模块统一含一段机器可读 YAML「风格参数」，字段结构（`observed`，摘录字段名而非数值）：

```text
style_id / lens_kit_mm
camera{ prefer / avoid / motion_budget / height }
shot_size_bias / composition
lighting{ key_quality / key_ratio / motivation / signature }
palette{ dominant / accent / saturation / contrast }
editing{ avg_shot_length_s / transition_bias / coverage_style }
sound{ music / ambience / dialogue / silence_use }
performance{ register / blocking }
aspect_bias
ai_video{ clip_duration_s / prompt_bias / risk }
negative_prompt_adds
```

**为什么重要**：本体系《导演视觉圣经》的基线卡是散文化描述，缺机器可读字段，Agent 难以稳定继承；缺少 `ai_video.risk`——而「风格能否落在生成模型上」正是 G0 立项最容易漏判的一环。

### 3.3 三种可迁移的抽象手法

1. **反例定义法「这不是什么」**：用「不是 X，差异在焦段/光比/机位高度」把风格逼出可辨识度。本体系风格卡目前只有正向描述，容易趋同。
2. **情绪词 → 可执行物理量**：不给「压抑」这类词，给眨眼间隔秒数、光比数值、镜速、焦距对应画幅宽度。与本体系提示词硬闸同向，可细化。
3. **固定对照场景**：同一拍戏在全部透镜下各写一遍，用于横向比对与自检（「只看产出能否说出用了哪个透镜」）。

### 3.4 其他可借鉴的纪律

- **15 项漂移轴清单**（脸/发/服装/道具/污损/伤妆/光向/时段/天气/地理/屏幕方向/视线/机位高度/色调/镜头感）及各轴高风险时机——可与本体系 G2 身份锚**图像条件**互补：图像条件管骨相，清单管其余各项。
- **identity string 契约**：一段 30–50 词、逐字粘贴（不转述、不为特写缩短）的角色完整重述。
- **motion budget 运动预算**：主体/相机/环境/时长共用一份有限预算，超支即用连贯性支付；把「这镜会不会崩」变成生成前可量化预判，补上本体系目前只有「失败后重抽」的事后补救缺口。
- **能力优先（capability-first）路由**：明确「不要记工具，要记控制面」，并自标能力快照会过时。与本体系 `AGENTS.md` §一.1「能力层思维」同构。

### 3.5 明确不吸收的部分

| 不吸收 | 理由 |
|---|---|
| 20 个透镜的全部数值（平均镜长 12–40 秒、`lens_kit_mm`、`aspect_bias` 宽银幕） | 面向真人电影宽银幕，与短剧竖幅 9:16 / 1–8 秒刀 节奏相反；数值必须按短剧重写 |
| 12 族平台能力矩阵 | 自标快照会过时；本体系铁律是能力以实测登记进《能力登记.md》，不照抄外部矩阵 |
| 大规模 film craft 正文（blocking / cinematic-language / lighting / genre-playbooks 等） | 体积大、对 AI 短剧边际价值低，违反渐进式加载纪律；只按需摘字段级结论 |
| slow cinema 向透镜（塔可夫斯基、伯格曼、费里尼、马力克、侯孝贤、毕赣等） | 与短剧「前 3 秒钩子、长短刀交替」方向相反；仅作可选参考 |
| 任何原文段落 | 不转载外部原文；只吸收结构、字段名与纪律，表述全部重写 |

### 3.6 许可与合规约束（必须保留）

- MIT 允许修改、合并、再发布、商用，**条件是保留版权声明与许可文本**。
- 该仓库另有一条**非许可条款的内容合规约束**：其风格模块不授权复制任何真实电影的具体镜头、台词、角色、剧情或受版权保护的表达。本体系吸收其结构时**同样只吸收抽象方法，不复制任何真实影片的具体表达**，与本体系合规自发要求一致。

### 3.7 geegl/directorskills 结论（`observed`）

- 形式：10 本书（《救猫咪》《电影导演大师课》《大师镜头》Vol.1–3、《电影镜头设计》《电影摄影》《调色师手册》《大师场景》《声音设计》）蒸馏为 **97 个 skill**，另加 1 个跨书摄影机镜头锚定附录。

- 许可：MIT（作者自署），但**其 MIT 只能覆盖作者自身贡献，无权授权第三方书籍著作权**：每个 skill 含一段 ≤150 字原文引文，且完整标注书名与章节。**这是本候选唯一的明确版权暴露点。**

**吸收边界（写入体系时必须遵守）**：

1. **不复制其一字引文**。本体系只需要「怎么拍」，不需要「原作者怎么写的」。
2. **不照搬其 skill 命名**。其命名带书籍来源标记，直接进体系会引入与 G0–G6 平行的第二套命名，违反「一套体系、一处维护」。
3. **只吸收方法论内核并重写**，在思想启发处注明「改编自 X 的方法论」，不建立字面继承关系。
4. **不整包 vendor**：97 个 skill 中对短剧真正高价值的不足三分之一，整包引入 70% 是上下文噪音，且与渐进式加载纪律冲突。

### 3.8 版权与合规的统一处理

- 两个候选均为 MIT，但**都只对各自作者自己的贡献有效**：不得转述为「外部内容可自由复制」。
- 统一纪律：**只吸收结构、字段名、判断维度与自检问题，全部用本体系自己的中文表述重写**；不复制原文段落、不照搬命名表、不搬运案例。
- 真实影片的具体镜头、台词、角色与剧情：一律不进入本体系（与既有的合规自发要求一致）。

### 3.10 两个工程化参考实现（专项调研结论，`observed`，2026-10）

另有两个体量更大、工程化更完整的同赛道仓库，结论如下。二者的共同点是**都不做「名导演风格建模」**：按其正文口径，导演能力被组织为**类型/形态视觉语言**与**决策纪律**，而非某个导演的招牌技法拆解。这一点直接影响本体系的取舍——**导演风格基线仍须本体系自建**，不能指望外部现成供给。

#### `zenstory-ai/drama-skills`（MIT；11 个 skill）

| 项 | 事实 |
|---|---|
| 许可 | MIT（根 LICENSE + 每份 SKILL.md 内联 `license: MIT`），可商用、可改、可闭源衍生 |
| 耦合 | 不绑宿主（Claude Code `/`、Codex `$` 同源正文）、不绑供应商 |
| 供给结构 | 入口路由 skill + 10 个阶段 skill；`skills/` 占约 44% 体积，分布健康 |

**它最值得吸收的四点**（**只吸收结构，正文一律自写**）：

1. **决策级路由表**。其索引文件是四列——`主题 / 负责环节 / 何时读取 / 不适用边界`，覆盖约 40 个决策主题，并明说「只做两件事：把决策路由到负责环节、定义规则分级与冲突优先级；**不复制任何规则正文**」。本体系当前的路由是**文件级**（问题 → 方法文件），它是**决策级 + 显式不适用边界**，能回答「这件事该不该由这一环负责」——比文件级更高一层，值得按同构方式补进本体系路由层。
2. **供应商解耦写成了硬边界**。原文口径是「供应商凭据不进入项目，项目文件与各 skill 都不绑定供应商」；具体做法是把模型名做成**按需只读的方言文件**（一模型一份），未点名则走通用档案，并**明令禁止拿相近模型的语法套用**。这与本体系 §八.2 同思想，但**表述更硬、分层更干净**：「凭据不进项目」可直接采纳为本体系硬边界。
3. **创作者权属 + 状态机**。项目级配置里，视觉方向 / 制作档案 / 交付面 / 节奏档案各自带 `status`，只有创作者接受后才由入口提升生效，且**子环节不得直接改写归创作者所有的配置**。这个「权属 + 状态」模型可补强本体系《能力登记.md》与关卡锁定语义（谁有权冻结、谁能改写）。
4. **反面清单式硬闸门**。付费生产前的把关不是泛泛的「需用户确认」，而是**逐一枚举不算确认的项**（预览、继续指令、预算说明、既有接受状态都不构成本次生产的确认）。这种**列失败模式**的写法比正面要求更难绕过，值得在本体系硬闸中推广。

**其余可取**：`## 按需知识`（触发场景 → 引用文件映射表）作为渐进加载的显式写法；三态参考图准备度（已有路径 / 计划挂图 / **明确文生视频**）并规定**普通「无」不等于文生视频授权**；失败时「退回最早的责任环节」的层位回退；`REF-` 类槽位把「用途 / 控制范围 / 不得控制范围」写进引用语法本身。

**不吸收**：内置 Dashboard 与本地 CLI 工具链（与本体系目录流程重叠，且引入服务进程与 Python 运行时依赖）；其题材卡 / 形态卡正文（与本体系 `01`–`07` 阶段知识库重叠）；每 skill 内置变更记录副本的做法。

| 项 | 事实 |
|---|---|
| 许可 | Apache-2.0 + 明确的商用声明（允许个人与商用、衍生物不必开源、无额外版税与署名要求）；有第三方来源声明与第三方字体许可 |
| 耦合 | 不绑宿主（declared host-neutral）、不绑供应商（需求写成宿主**能力**而非工具名） |
| 体积性价比 | **极差**：约 299.5 MB 中约 99.4% 是 `docs/` 下的研究过程媒体（mp4/png/blend/gif），**真正的技能面只有约 804 KB**。→ **不要整仓取用**，只按需取少量文本文件 |

**它最值得吸收的两点**：

1. **把导演理论做成「有出处 + 分档标注」的推理底座**——这是本次调研的单项最高价值发现。该文件开篇即声明「它不是语录库，而是把经过核实的导演理论转成可执行决策」，其来源纪律要求**不得编造导演方法、影史论断、书籍论断或案例**，并强制三档标注（`已核实` / `推断` / `假定`），无法核实的断言标 `待查证` 且**不得作为承重规则**。它的七根支柱按**技法维度**切分（导演意图 / 影片形式 / 表演逻辑 / 剪辑逻辑 / 声音逻辑 / 信息逻辑 / 身体化逻辑），引用的是理论家的**可执行原则**而非某导演的视觉签名。→ **三档标注法与本体系「实测 / 推断分离」同向且更细，可直接采纳**；七支柱的**维度切分方式**可作为本体系导演方法层的组织参考。
2. **「不得用代理物冒充成品」的验收门**。其预演模块规定：截图、编辑器界面、工程文件、参数表、静态关键帧、2.5D 推拉**均不能替代可播放成品**；动作密集的打斗必须先通过**骨骼约束 + 武器约束 + 共享接触点 + 单动作门**，未通过则**拒绝或标为诊断**，不得用体块位移冒充打戏。→ 这与本体系「只把真实证据写成通过」同构，且**给出了具体的中间物黑名单**，可作为本体系验收闸的补强措辞。

**其余可取**：合同式机器可读清单（把「过关证据」与「分发状态」拆成**两个字段**，结构上防止「已打包 = 已验收」的误读）；`standalone` / `cannot` 字段用机器可读方式声明**本环节不做什么**以约束越权扩写；把「文件有效 / 已加载 / 记录行为 / 已看输出 / 用户接受」区分为**五档认识论状态**（比本体系现行四档更细）；资产合同里把已批准项与锁定特征写成机读字段；把「能力层互不依赖」从文本约束升级为**可执行校验脚本**；用脚本从单一真相源**生成**派生文档以根除漂移。

**不吸收**：约 297 MB 的研究媒体；双语多份指南与多语言镜像；发布工程（打包 / 校验和 / 站点流水线）；类型视觉包（与本体系视觉资产体系重叠）；需要额外三维软件本体的预演链路（**只借其验收纪律，不引入工具链**）。

#### 对上一节结论的修订
