# 成片与字幕

字幕做两件事，两层都过才叫做完：先保证**内容对**（文本、时间码、断句、门禁——§4.0、§4.2、§4.7），再保证**进得了画面**（样式、安全区、烧录——§4.1、§4.3–4.6）。

## 1. 任务定位

**负责**：镜头排序与节奏、卡点剪辑、字幕制作（内容规范 + 视觉样式 + 烧录）、全片光学统一层、导出规格、成片质检。

**不负责**：重新生成镜头（回 04 视频生成）；改剧本与台词（回 01-创意与剧本 / 02-分镜与镜头）；换音色与重配音（回 05-音频）。出现这些问题时，指出问题并说明应回到哪一环，不要在这里硬补。

## 2. 剪辑节奏

### 2.1 镜头密度

| 内容类型 | 镜头密度 | 单镜平均时长 |
|---|---|---|
| 横屏电影感短片（**默认**，快切开场） | 12–30 个/分钟，按段落非均匀 | 1.5–5 秒（短刀为主，长刀收束） |
| 横屏网剧/正剧 | 8–15 个/分钟 | 4–7 秒 |
| 电影（长镜风格） | 4–12 个/分钟 | 5–15 秒 |
| 竖屏短剧（爽剧/复仇，备选） | 15–25 个/分钟 | 2.4–4 秒 |
| 竖屏情感/慢类型（备选） | 10–15 个/分钟 | 4–6 秒 |

> 口径说明：`02-分镜与镜头/分镜工作流.md` §13.7.2 的"单集镜头数"指**叙事镜头**（分镜稿里的动作单元）；这里的镜头密度指**成片剪辑切换点**（一个叙事镜头可切成多个特写/反应/角度），两者口径不同，不矛盾。

> **标杆实测（2026-10）**：两部实测成片——17 分钟长片全片平均 12.2 镜/分钟，但开头 30 秒约 44 镜/分钟，单镜中位数仅 2.6s，靠"0.07–1s 碎镜 + 15–60s 长镜"的极端对比出节奏；33 镜每分钟的短片则走另一种密度。**密度不是均匀的，是短刀碎镜 + 长刀留白的对比。**

- 横屏默认开场用快切，把"短刀+长刀"对比做出来。短刀从生成段里裁，不把生成段全长接进成片。连续三个镜头都只是「对着人说话」，回到分镜重拆这场的刀；不为了凑镜型硬插一段没有因果的空镜。叙事片若多数画面行没有裁切，或成片帧差静止占比超过 50%、连续静止超过 5 镜，G6 不通过。检查：`python tools/check_assembly_usage.py <项目目录>`。同场回切用硬切。协议见 `AGENTS.md`「成片生成裁决」。
- 密度不是均匀分布的：开篇 3 秒钩子段用快切（1-1.5 秒/镜），中段对白段放慢，爽点/情绪点前再加速，收尾用长镜留白。
- 竖屏短剧低于 12 个/分钟观众会感到「拖」，高于 25 个/分钟信息来不及消化。

### 2.2 卡点剪辑

把镜头切换点落在 BGM 的节拍上，是最省力的节奏手段（横竖屏通用）：

1. **先给 BGM 打拍**：确定 BPM 与小节线（常规 4 拍一小节），在时间线上标出重拍。
2. **按情绪段决定卡点密度**：
   - 平推段：切换点落在小节线（每 4 拍）
   - 升温段：落在每 2 拍
   - 高潮/爽点段：可 1 拍一镜快切
3. **对白段不卡点**：说话时给说话人，说完切到听的人的反应。把卡点强加在对白上，观众会看不清口型，也听不清台词。
4. **优先级**：台词落点 > BGM 节拍 > 视觉对称。三者冲突时让位给台词。

### 2.3 爽点停留与反应留白

- **爽点镜头必须停够**：动作结果镜头延长 0.3-0.5 秒，让观众看清「打到了 / 拿到了 / 说出口了」。最常见的失误是证据特写只给 0.4 秒就切走，观众没看清字，爽点等于没爽。
- **反应镜头给留白**：反派震惊、女主落泪这类反应镜头给 0.5-1 秒，不要急着切。
- **留白只给一次**：同一情绪不重复给两遍，第二遍观众只会觉得拖。
- 反过来，**不需要结果的镜头不要留恋**：转身、走路、开门的过程可以掐头截掉一半。

### 2.4 每集结尾

- **剪在情绪最高点**：反转揭晓的瞬间、抬手未落下的巴掌、门被推开还看不见人、一句狠话说到一半。
- **不要剪在情绪落地之后**：说完话、转身走远、镜头拉空——那等于告诉观众「可以关掉了」。
- 最后一镜比常规镜头多留 0.5 秒悬停，再加 0.3-0.5 秒定格或黑场，给观众一个「想知道后面」的间隙。
- 结尾钩子的**类型**由 01-创意与剧本 / 短剧编剧引擎 的钩子设计决定（悬念钩 / 冲突钩 / 身份钩），剪辑只负责把它剪得最锋利，不自行改变钩子类型。

### 2.5 情绪呼吸与场间过渡（横屏电影感短片的必修课）

竖屏爽剧可以一路硬切，电影感短片不行。全片硬切无呼吸是"分开来都对、合在一起空洞"的第二大根因（第一大是生成层的跨镜断裂，见 02-分镜与镜头 / `跨镜连续性与帧链法.md`）。三条低成本高回报的修法：

- **情绪后定格呼吸**：重情绪镜头落点（和解、诀别、死里逃生、真相揭晓）的末帧 freeze 延长 0.8–1.2 秒再切。观众需要这一拍消化情绪，音乐也需要落点。实现上直接冻结末帧即可（克隆末帧续段），音频同步 pad 静音，不要回放。
- **场间叠化**：跨场硬切（地点/时间跳变）改 8–12 帧（24fps 下约 0.35–0.5 秒）叠化。叠化是"时间在流动"的视觉签名，对蒙太奇与跨场跳转尤其有效；同场内的动作衔接仍用硬切，别滥用。
- **声音桥接**：场与场之间用 J/L-Cut（§8.3）把环境声或音乐提前/延后 0.3–1 秒，画面跳切时声音不断，连续性就从耳朵先建立起来。

**尺度提醒**：定格每次 1 秒上下、全片三五处即可；叠化只给场界，不进单场；多了就成 PPT。

## 3. 剪辑指令模板

给 AI 剪辑助手或剪辑师下达指令时用结构化指令，缺任何一段都会得到一版需要重剪的成片。

### 3.1 素材清单表

| 镜号 | 文件名 | 时长 | 内容摘要 | 台词 |
|---|---|---|---|---|
| S001 | S01.mp4 | 3.2s | 女主独自站在雨夜街口，回头看向车灯 | 无 |
| S002 | S02.mp4 | 2.8s | 黑色轿车停在她身后，车窗缓缓降下 | 无 |
| S003 | S03.mp4 | 4.5s | 男主递出文件，女主手抖着接过 | 「这是亲子鉴定」 |
| S004 | S04.mp4 | 1.6s | 特写：文件上「亲子鉴定」四个字 | 无 |
| S005 | S05.mp4 | 3.0s | 女主抬头，眼眶通红，咬唇不语 | 无 |
| S006 | S06.mp4 | 3.5s | 男主转身走向车，背影拉远 | 「明天，我来接他」 |

要求：逐镜连续不跳号；时长与实际文件一致；同一场景的镜头标注出来（便于统一调色与音效）；没有台词的镜头也要保留行。

### 3.2 结构规划

- **顺序**：默认按镜号正序；需要调整时写明哪几镜互换、为什么。
- **转场**：逐镜明确转场方式（硬切 / 淡入淡出 / 叠化 / 划像 / 推拉 / 闪白 / 甩镜 / 声音先入 / 无转场）。默认「硬切」，转场是稀有资源，用得越少越有力度。
- **变速**：写明哪个镜头需要变速及倍数（如最后一镜 0.8x 放慢），以及变速是否变调。

### 3.3 节奏要求

写明四项：目标时长 / 镜头密度 / 卡点段落 / 爽点停留位置。不要只写「节奏紧凑一点」——这是无法执行的要求。

### 3.4 必留镜头与可弃镜头

- **必留**：承载关键信息的镜头——证据、身份揭示、关键决定、情绪转折。删了观众看不懂。
- **可弃**：纯过场、重复情绪的反应、能被其他镜头覆盖的交代性画面。
- **超时时的删除顺序**：先删过场镜头 → 再删重复反应镜头 → 最后压缩解释性台词。**任何情况下不得删除证据镜头与身份揭示镜头。**

### 3.5 可直接复制的指令模板

```text
角色：资深电影感短片剪辑师

目标：把下列镜头素材剪成横屏短片（默认 16:9，1920×1080；竖屏项目改为 9:16），目标时长 [X]，直接可发布。

一、素材清单
（逐行：镜号 / 文件名 / 时长 / 内容摘要 / 台词）

二、结构规划
1. 顺序：[默认按镜号正序，或写明调整]
2. 转场：[逐镜写明；默认硬切]
3. 变速：[哪些镜头变速及倍数]

三、节奏要求
1. 目标时长：[X 分 X 秒]
2. 镜头密度：[15-25 个/分钟]
3. 卡点：[哪几段卡 BGM 节拍、BGM 文件；对白段不卡点]
4. 爽点停留：[第 X 镜延长 0.3-0.5 秒；第 Y 镜反应镜头停留 1 秒]
5. 结尾：[停在哪一镜的哪一帧]

四、必留与可弃
必留：[镜号列表及理由]
可弃：[镜号列表]
超时处理顺序：过场 → 重复反应镜头 → 压缩解释性台词（不得删证据与身份揭示镜头）

五、输出要求
先输出时间线（镜号 + 入点 + 出点 + 时长）供我确认，确认后再执行剪切，不要直接渲染成片。
```

最后一段是关键：**先要时间线，再要成片**。让剪辑执行者先给出结构方案，避免整片剪完才发现节奏方向不对。

## 4. 字幕

### 4.0 低成本字幕分层

本体系默认采用清晰、统一、可批量维护的字幕，不制作高成本电影级动态图形系统。字幕在画面完成、配音时间确定后进入后期；不交给视频生成模型直接生成长句和关键文字。

| 类型 | 用途 | 默认做法 |
|---|---|---|
| 对白/旁白 | 观众理解说话内容 | 普通字幕轨，统一字体、位置、描边和出入方式 |
| 关键词 | 反转词、数字、身份词或重点物件 | 少量变色或加粗；一句最多一个，非必要不做 |
| 片名/章节 | 片头、转场、片尾 | 简单淡入/淡出或固定位置，不做复杂粒子和跟踪 |
| 场景文字 | 招牌、屏幕、信件、卷轴等画内文字 | 后期单独叠加；需要透视/遮挡时只做必要处理，关键文字不交给视频模型 |

字幕事件表每行可使用：`类型 / 文本 / 入点 / 出点 / 位置 / 样式 / 动画 / 强调词 / 避让区域 / 声音同步 / 备注`。普通对白默认样式；关键词只填需要强调的词；片名/章节与场景文字不混入对白字幕轨。

低成本流程：配音完成 → 识别或手工建立时间码 → 校对文本和断句 → 普通字幕入轨 → 必要关键词变色 → 必要片名/章节或场景文字叠加 → 检查避让 → 完整回放。只用现有剪辑工具、字幕轨或 ffmpeg 即可；封装字幕适合可切换版本，烧录字幕适合发布平台。

不做的事：每句话弹跳/缩放、频繁辉光和粒子、复杂跟踪、无意义的变色、用字幕动画掩盖画面或剧情问题。字幕始终让位于脸部、手部、关键道具、证据画面和主要动作。

### 4.1 两个字幕目标经常打架：drama / movie 两套预设

| 目标 | 含义 | 对应的字幕形态 |
|---|---|---|
| **有效** | 观众在嘈杂环境、静音刷到、倍速播放时，依然接收关键信息 | 大、醒目、关键词突出 |
| **好看** | 字幕是画面构图的一部分，不抢戏、不廉价 | 小、克制、与光学统一层（§5）协调 |

**短剧信息流场景偏"有效"，电影感场景偏"好看"。**
本文件给两套预设，按发行渠道选，**不在同一片里混用**：

| 预设 | 适用 | 字幕性格 |
|---|---|---|
| `drama`（信息流短剧） | 竖屏平台、静音播放率高、前 3 秒定生死 | 粗黑大字、白字黑粗描边、关键词上色 |
| `movie`（电影感） | 横屏/竖屏精品短片、作品集、参赛 | 小字、细描边、零强调色、绝对克制 |

**判断口诀**：观众大概率不开声音 → drama；观众会戴耳机安静看 → movie。

### 4.2 基础门槛（两套预设共用）

| 项目 | drama（信息流短剧） | movie（电影感） |
|---|---|---|
| 行长 | 单行 ≤ 15 汉字；超出断两行，最多两行 | 单行 ≤ 20 汉字；最多两行 |
| 断行 | 在**语义边界**断（主谓之间、标点处），不在词中间断（"备份/母亲"可以，"备/份母亲"不行） | 同左 |
| 标点 | 句尾不加句号；问号和叹号保留——它们带情绪 | 同左 |
| 信息密度 | 一行一个信息单元；两句话压一行 = 观众得暂停读，倍速下必丢 | 同左 |
| 时间对齐 | 入点落在"语音前 0.2 秒 ~ 语音后 0.1 秒"窗口内；出点比语音晚 0.2–0.4 秒 | 入点同左；出点比语音晚 0.2–0.5 秒（读到句意为准） |
| 行间距 | 两行字幕之间至少留 2 帧间隙，防止视觉粘连 | 同左 |
| 一致性 | 全片/全剧字幕位置、字号、颜色、出入方式统一，不要每集换样式 | 同左 |

- 无对白的纯音乐段不放"……"凑字幕；没有台词就不出字幕。
- **同一片内入点取法固定一端**（宁可统一早 0.1–0.2 秒让观众先读到，或统一与语音同步、最晚不晚于语音后 0.1 秒），不要两种混着用。
- 口径说明：原《剪辑字幕与成片》给的是"比配音早 0.1–0.2 秒出现、晚 0.2–0.5 秒消失"，原《字幕视觉规范与烧录》给的是"入点比语音晚 ≤0.1 秒、出点晚 0.2–0.4 秒"。合并后统一为上表的口径：**入点取窗口内任一端并全片固定，出点按预设取 0.2–0.4（drama）/ 0.2–0.5（movie）**。

### 4.3 位置与安全区

| 画幅 | 字幕基线位置 | 安全区与避让 |
|---|---|---|
| 竖屏 1080×1920 | 距底 **280 px**（drama）/ **200 px**（movie） | 底部 15–20% 是平台 UI 区（标题、按钮、进度条），字幕绝不能进去（等价口径：距底 ≥15% 屏高，1080×1920 下约 290 px）；顶部 10% 同样避开 |
| 横屏 1920×1080 | 距底 **60 px** | 两侧各留 5% 安全边距；避开人物面部（原口径"距底边约 8–10% 屏高"更保守，1080p 下约 86–108 px，与 60 px 二者择一、全片统一；字幕压住面部时上移） |

- 字幕位置**全片固定**。字幕跟着构图上下跳是业余感的直接来源。
- 例外：字幕压住关键表情/动作时**临时上移**，并在事件表"备注"列记录，事后复查。
- **字幕不得遮挡关键画面**：证据特写、手机屏幕、面部表情处，字幕应上移或暂时隐藏（隐藏时靠后期回补）。遮挡一次关键信息，前面所有铺垫都白做。

### 4.4 字体、字号与描边

字体只规定**性格**，具体字体文件由实现环境映射（去耦，不绑字体名）：

| 角色 | 字体性格 | 参考映射（Windows 已验证可用） |
|---|---|---|
| drama 主字幕 | 粗黑体、字面宽、中宫大 | 思源黑体 Bold / 微软雅黑 Bold |
| movie 主字幕 | 常规黑体，笔画干净 | 思源黑体 Regular / 微软雅黑 |
| 旁白/独白（可选第三样式） | 与主字幕同族、字重或颜色微差 | 同族 Light，或 85% 不透明度 |

**禁用**：楷体/宋体等衬线体做信息流短剧主字幕（细笔画在手机屏上糊）；花体、手写体（除非片型本身就是手账风）；一片超过两个字重。

字号与描边：

| 参数 | drama | movie |
|---|---|---|
| 字号（竖屏 1080×1920） | 64–72 px | 44–48 px |
| 字号（横屏 1920×1080） | 54–60 px | 42–46 px |
| 字色 | 纯白 | 纯白（或 95% 白，防死白） |
| 描边 | 黑色、3–4 px | 黑色、1.5–2 px |
| 阴影 | 浅投影或无 | 无 |
| 背景条 | **不用**（廉价感来源） | 不用 |

- **通用区间（未选预设时）**：横屏 1920×1080 下 44–60 px；竖屏 1080×1920 下 42–56 px（约屏宽 4–5%）；以能一眼看清为准，宁大勿小。
- 描边的意义不是装饰：白字压在白衣、天空、高光上必须有描边才读得出。**描边粗细按字号比例走（约字号 5%），不按像素拍脑袋**；不要只靠半透明色块（会挡住画面信息）。

### 4.5 关键词强调（仅 drama 预设）

短剧字幕"有效"的核心技术：**爽点词、反转词、数字、人名第一次出现时上色或放大**。

- 标记法：在字幕事件表"文本"列用 **【关键词】** 标出，烧录时自动转成强调色
- 强调色：**金黄**（`#FFD700` 系）为默认；**一片只用一个强调色**，与风格卡强调色一致最佳
- 密度：**一句话最多 1 个变色词**；**一片的强调词密度 ≤ 15%**，一集里变色 3 次以上就不叫强调了，观众会失去敏感度
- 用途限定：只用于反转词、关键数字、身份词
- movie 预设下【】标记一律忽略——电影感靠表演和镜头强调，不靠字幕

### 4.6 落地管线：事件表 → ASS → 烧录

三步，每步可独立检查：

```
字幕事件表.md（G6 已审）
   ↓  tools/subtitle_burn.py（转换）
subtitles.ass（样式 + 时间轴，可人工微调）
   ↓  ffmpeg ass 滤镜（烧录）
成片_字幕版.mp4
```

#### 4.6.1 硬烧 vs 软挂

| 方式 | 做法 | 什么时候用 |
|---|---|---|
| **硬烧**（推荐默认） | 字幕渲进画面像素 | 竖屏平台（平台不保证软字幕样式）、发出去就不可控的一切场景 |
| 软挂 | 字幕作独立轨封装进容器 | 需要多语言切换、需要观众可关字幕的长视频平台 |

短剧默认硬烧。软挂只在外部字幕文件随片交付时用（见 `多语言版本管线.md`）。

#### 4.6.2 已验证实现（本地环境）

体系本地已验证的零新增依赖组合：**字幕事件表 → `tools/subtitle_burn.py` → ASS → ffmpeg（libass 滤镜）硬烧**。
ffmpeg 与中文字体（思源黑体/微软雅黑/黑体）本地均已具备，无需安装任何东西。

```bash
# 1) 生成 ASS（不碰视频，可随时重跑）
python tools/subtitle_burn.py 项目目录 --preset drama --make-ass

# 2) 硬烧到成片
python tools/subtitle_burn.py 项目目录 --preset drama --burn

# 3) 自检（验证转换器本身，不需要视频文件）
python tools/subtitle_burn.py --selftest
```

参数要点：
- `--preset drama|movie`：选 §4.4 哪套参数；默认 drama
- `--video 路径`：默认找项目 `06-成片/` 下最新渲染的 mp4
- `--out 路径`：默认输出 `06-成片/成片_字幕版.mp4`
- 烧录是**重编码**，约等于再渲染一遍的时长；画质参数默认 CRF 18、音轨直拷

#### 4.6.3 手动微调口

生成的 `.ass` 是纯文本，任何文本编辑器可改：
- 改样式：文件顶部 `[V4+ Styles]` 段，每行一个字幕样式
- 改单条：`[Events]` 段逐行，时间是 `时:分:秒.厘秒`
- 微调后重新执行第 2 步即可

## 5. 成片光学统一层

### 5.0 为什么要补这一层

AI 出片的廉价感，**主要不来自构图，而来自成像**。模型输出的画面有三个共同的"数字味"特征：

1. **全画面同等清晰** —— 没有景深分离，主体和背景一样锐，观众一眼看出是"渲染"；
2. **零颗粒、零噪点** —— 纯净得像屏幕截图，缺少胶片/传感器介质的随机性；
3. **色彩直出** —— 没有色调分离（暗部偏冷、亮部偏暖），没有高光滚降，高光不死白。

真人剧组靠摄影机的**镜头 + 胶片/传感器 + 后期调色**三重介质消除这些。AI 流程没有物理介质，所以必须**人为补一层统一的成像参数**，否则每镜各自生成、各自直出，拼起来就是"一堆漂亮图片"。

**核心原则：这一层必须全片统一，逐镜微调是灾难。** 单镜加颗粒不难看，36 镜各自加不同强度的颗粒，观众会立刻感到"抖"。

### 5.1 两次落地：生成期带一半，后期统一另一半

光学层不能全靠后期救，也不能全指望提示词。分工如下：

| 阶段 | 负责的参数 | 为什么 |
|---|---|---|
| **生成期（G4 提示词）** | 景深/焦外、光源具名、镜头呼吸、胶片感与颗粒感、动态模糊 | 这些是画面内容的一部分，后期加不进去（后期虚化边缘会露馅） |
| **后期（G6 时间线）** | 颗粒强度与尺寸、暗角、色温/色调偏移、对比与高光滚降、锐度、色散、统一帧率 | 这些是介质属性，必须在时间线上全片统一施加 |

> 只用提示词：全片不一致，逐镜漂移。
> 只靠后期：景深和高光质感救不回来。
> **两条都要做，且生成期先把"底子"做对，后期只做统一与微调。**

### 5.2 通用参数表（每片必填，进项目 `00-立项` 或装配单）

| 参数 | 作用 | 取值口径 | 常见失误 |
|---|---|---|---|
| **颗粒 grain** | 消除数字纯净感，统一全片"材质" | 强度（弱/中/强）+ 尺寸（细/中/粗） | 逐镜强度不一；在已有点噪的 AI 素材上叠加导致脏 |
| **暗角 vignette** | 把注意力收回画面中心，压掉边缘的"渲染感" | 强度（0–10）+ 过渡柔和度 | 加太重像滤镜；**强度按画幅校准：横屏 16:9（默认）用基线强度，竖屏 9:16 减半** |
| **色温偏移 temp** | 全片冷暖基调 | 整体偏移值 + 暗部/亮部分离偏移 | 全片一个温度值，没有做暗冷亮暖的分离 |
| **色调分离 split tone** | 暗部偏一色、亮部偏另一色 —— 电影感最便宜的来源 | 暗部色 + 亮部色 | 跳过；或两色对比过猛像 Instagram 滤镜 |
| **对比与高光滚降 rolloff** | 高光不死白、暗部不死黑 | 对比档位 + 滚降柔和度 | 直接拉对比导致高光切平，细节全丢 |
| **锐度 sharpen** | AI 画面普遍过锐，往往要**减**锐 | 增减方向与幅度 | 继续加锐，塑料感更重 |
| **光晕与色散 halation / CA** | 亮部溢光、边缘色偏，模拟老镜头 | 强度（关/弱/中） | 全片开大，像镜头坏了 |
| **动态模糊 shutter** | 运动模糊幅度，对应快门角 | 180° 为基准，动作片可更慢 | 运动无模糊 → 抖动感；过度 → 拖影糊 |
| **帧率 fps** | 全片统一，决定"电影感"的基础 | 24（默认）/ 25 / 30 | 素材混帧率直接拼，节奏抽搐 |

> **参数只规定效果与口径，不规定软件。** 具体在哪个调色/剪辑工具里实现、用什么节点或插件，由能力登记与适配层映射，本文件不绑定任何供应商。

### 5.3 按风格基线卡的参数套（对号入座，再微调）

卡 A–D 见 `导演视觉圣经.md`；卡 E–I 为本节新增的中式与类型化基线。
**先选卡，再抄本表参数，最后只做 ±20% 微调。**

| 卡 | 名称 | 颗粒 | 暗角 | 色温/色调分离 | 对比与滚降 | 锐度 | 光晕色散 | 快门角 |
|---|---|---|---|---|---|---|---|---|
| A | 光影叙事系 | 中·细 | 中 4 | 暗部青绿 / 亮部暖金 | 中对比，软滚降 | 略减 | 弱 halation | 180° |
| B | 炫技系 | 弱·细 | 轻 2 | 青橙对撞（暗青 / 亮橙） | 高对比，硬滚降 | 保持 | 弱 CA | 90–120°（运动更利） |
| C | 清道夫系 | 中·中 | 轻 2 | 写实灰绿，几乎不分离 | 中对比，中性滚降 | 减 | 关 | 180° |
| D | 真实剧集系 | 弱·细 | 轻 1 | 近乎中性，微暖 | 低对比，软滚降 | 减（去塑料感） | 关 | 180° |
| E | 水墨留白系 | 中·粗 | 中 3 | 整体去色，仅留一点朱红 | 低对比，极软滚降 | 减 | 弱 halation | 180° |
| F | 黑色悬疑系 | 强·中 | 重 6 | 冷灰 / 微 sepia 亮部 | 高对比，硬滚降（暗部留细节） | 保持 | 关 | 180° |
| G | 赛博霓虹系 | 弱·细 | 中 4 | 暗部蓝紫 / 亮部霓虹点缀 | 中高对比 | 保持 | 中 halation | 180° |
| H | 粗粝纪实系 | 强·粗 | 中 3 | 去饱和土色 | 中对比，硬滚降 | 减 | 弱 CA | 180° |
| I | 史诗自然光系 | 弱·细 | 轻 2 | 暗部微冷 / 亮部日光暖 | 低中对比，软滚降 | 减 | 弱 halation | 180° |

### 5.4 生成期提示词该带什么（中性描述，不绑实现）

写进 G4 提示词的光学部分，用效果描述而非某个平台的字段名：

- **景深**：`浅景深，主体实焦，背景柔和虚化（焦外过渡自然，不是模糊滤镜）`
- **光源**：光源必须具名并写明方位色温（沿用 `导演视觉圣经.md` 照明卡）
- **介质感**：`轻微胶片颗粒感、柔和的高光过渡、无色带`
- **镜头瑕疵**：`极轻微的呼吸感与边缘柔和，不要锐化过度的数码感`
- **动态**：`运动带自然动态模糊`（动作片可写"更明显的运动拖影"）

> 具体字段写法与平台差异，由 `04-视频生成/平台提示词契约.md` 与 `04-视频生成/平台提示词契约.md` 映射；
> 提示词预检走 `tools/validate_video_prompt.py`。**本文件不规定任何平台的字段名。**

### 5.5 装配期检查清单（交剪前必过）

- [ ] 全片颗粒强度与尺寸**一致**（不是逐镜看着加）？
- [ ] 暗角强度按画幅校准（横屏用基线，竖屏减半），且竖屏暗角没有吃掉字幕区？
- [ ] 做了暗冷亮暖的**色调分离**，而不是整体套一个色温？
- [ ] 高光有滚降、不死白？暗部有细节、不死黑？
- [ ] AI 素材原生过锐的镜头做了**减锐**？
- [ ] 全片**统一帧率**，无混帧率素材直接拼接？
- [ ] 光学参数与所选风格基线卡对应，没有出现"卡 D 真实系套了赛博霓虹的分离"？
- [ ] 生成期已带景深/具名光源/介质感，没有把全部希望压在后期？

### 5.6 常见坑

1. **在已有噪点的素材上叠颗粒会变脏** —— 先看清素材本身有没有点噪，有就减半强度。
2. **暗角在竖屏上会吃掉字幕区** —— 竖屏暗角强度建议减半，且过渡更柔。
3. **色调分离过头就是滤镜味** —— 分离幅度以"看不出刻意"为准，能一眼看出就过了。
4. **减锐不等于糊** —— 减的是边缘白边与塑料感，不是整体清晰度；皮肤与布料纹理要保留。
5. **不要每场一套参数** —— 光学层是全片常量，场与场的区别交给色彩脚本和照明卡（见视觉圣经第二、三节），不交给光学层。

## 6. 成片导出规格

### 6.1 基础规格

| 项目 | 建议 | 说明 |
|---|---|---|
| 画幅 | 16:9（默认）；9:16（竖屏备选） | 横屏电影感短片默认 16:9；竖屏平台才用 9:16 |
| 分辨率 | 1920×1080（横屏）；1080×1920（竖屏） | 素材更高可降采样导出，不要直接放大低清素材 |
| 帧率 | 24 fps（电影感默认）；素材为 30 则跟随 | 与素材保持一致，避免混帧抖动 |
| 编码 | H.264 | 兼容性最好；对体积敏感时用 H.265 |
| 码率 | 8-12 Mbps（H.264） | H.265 可降至 6-8 Mbps |
| 音频 | AAC 48 kHz 立体声 | 峰值不超过 -1 dBTP，整体响度约 -14 ~ -16 LUFS |

**核心原则**：各平台都会对上传视频做二次压缩，因此上传码率要**略高于**平台推荐值，给二次压缩留余量；同时上传前不要自己再压一遍（微信、网盘传输会压缩，尽量用原始文件直传）。

### 6.2 各平台差异要点

以下为内容与上传层面的差异要点，具体数值以平台官方最新规范为准：

| 平台 | 内容侧重 | 上传与呈现要点 |
|---|---|---|
| 抖音 | 强钩子、单集短、反转密集 | 9:16 全屏；封面帧可自选；底部约 15% 被文案与按钮遮挡，字幕必须避开该区 |
| 快手 | 人设连续性、口播感强 | 竖屏全屏；标题与话题影响分发；系列化更新更吃「追更」习惯 |
| 红果（免费短剧） | 追更型长剧集 | 按平台的集数与片头片尾规范打包上架；画面内不得带第三方平台水印 |
| 视频号 | 中老年受众、社交推荐 | 前 3 秒信息要直白；依赖社交转发，可配公众号做剧情延展 |
| 小红书 | 女性向、审美权重高 | 竖屏；封面与标题审美权重高，可同步发图文版解说引流 |

**统一注意**：导出前检查画面内是否有第三方平台水印、剪辑软件水印、试看字样、时间码残留。

## 7. 成片质检清单

- [ ] **音画同步**：逐条检查台词口型与声音无明显漂移，肉眼可见偏差即需修（不必追求逐帧级）。
- [ ] **无黑帧/无白闪**：转场与切点处无意外空白帧，无上一段素材首尾帧残留。
- [ ] **音量统一**：全片人声最高、SFX 居中、BGM 垫底；镜头切换处无音量跳变；无爆音与削波。
- [ ] **字幕无错别字**：人名、称谓、数字、成语逐条校对；字幕与口播内容一致。
- [ ] **字幕不遮挡关键画面**：证据特写、手机屏幕、表情特写处已让位。
- [ ] **封面帧**：已选定情绪最高点或冲突瞬间的一帧，无模糊、无闭眼、无水印。
- [ ] **前 3 秒**：第一帧就有信息（不是黑屏或空镜），第一句台词或字幕在 1 秒内出现。
- [ ] **结尾钩子**：停在情绪最高点，无冗余收尾镜头，无「下一集预告」压过正片钩子。

## 8. 自动化后期管线（开源工具加持）

> 人手不足时的提效手段：AI 负责粗剪与重复劳动，人只修节奏与审美。自动化产物必须过 §7 质检清单，不允许"自动剪完直接发"。

### 8.1 字幕自动化（最成熟，优先接入）

`Whisper/WhisperX 转写 → SRT → 封装或烧录`：

```bash
# 转写（多说话人/长音频用 WhisperX，带分块与说话人分离）
whisper in.mp4 --model small -f srt

# 封装为可选字幕轨（不重编码，秒级完成）
ffmpeg -i in.mp4 -i in.srt -c copy -c:s mov_text out.mp4

# 烧录硬字幕（需要重编码，注意字体与字号过一遍 §4 字幕规范）
ffmpeg -i in.mp4 -vf subtitles=in.srt out.mp4
```

产出 SRT 后**必须人工校对**人名、数字、成语——转写错字直接上字幕等于公开处刑。样式与烧录参数按 §4.4–4.6 走，本节的 ffmpeg 直烧是 §4.6.2 之外的备选入口。

### 8.2 文本驱动剪辑（mli/autocut）

理念：**改稿子 = 剪片子**。把素材转写成文字稿后，删除文字稿里的废句/口误/重复段落，工具自动删除对应的视频段落并重排时间轴。适合口播、讲解、访谈类素材的粗剪；剧情短剧只用它删废镜头，叙事节奏仍由人定。

### 8.3 J-Cut / L-Cut——AI 粗剪给不了的"呼吸感"

- **J-Cut**：下一场戏的声音提前 0.3-1 秒进（人还没看见，先听见），用于场景过渡，剪辑不生硬。
- **L-Cut**：上一场戏的声音延后 0.3-1 秒出（画面已切走，声音还在），用于对话接反应镜头。
- 卡点剪辑（§2.2）追求"准"，J/L-Cut 追求"顺"，两者不冲突，分别用在节拍点与场景缝。

### 8.4 长片切短（一母片多平台）

AI 高光侦测（找冲突峰值/爽点段落）+ 人脸追踪居中重构图（横屏母片自动裁 9:16 并跟脸），一次产出多平台多比例版本。适合把横屏母片批量改成抖音/视频号竖屏分发。

### 8.5 人机分工的最优解：AI 粗剪 + 剪映精修

部分开源端到端管线支持把素材与粗剪时间轴**导出为剪映草稿**：AI 排好素材顺序与字幕，人进剪映只调节奏、转场与封面帧。这是目前效率最高的分工边界——别让 AI 硬扛最后一公里的审美决策。
