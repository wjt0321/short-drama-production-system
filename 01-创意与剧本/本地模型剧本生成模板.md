> **体系定位**：本文件是《短剧编剧引擎.md》的**执行层补充**——只回答「怎么把规则喂进本地模型」，不修改任何创作规则。规则的唯一权威仍是 `短剧编剧引擎.md`（尤其 §10.2 交付模板、§11 反 PPT 纪律、§12 检查清单）。
> **实测环境**：RTX 3070 8GB / i5-12400F / 32GB RAM / LM Studio + `llama.cpp-win-x86_64-nvidia-cuda12-avx2` 2.64.0。
> **变更**：v2 依据 2026-10-25 本机 12 组对照实测重写；v1 的「模板 B 因果四句一次写完」已废弃（实测会把正文挤成 0 字，见 §零）。

# 零、v2 为什么这样改（实测结论）

同一素材、同一模型、只改提示词形态，四种结果：

| 提示词形态 | 实测产出 | 结论 |
|---|---|---|
| 自由模式，一句话 | 1435 字，25 个粗体标签，`【幕落】`＋两段旁白总结 | 不是戏，是**剧本文档** |
| system 里写考核项（`须能通过 check_*.py`、钩子密度、三要素） | `# 剧本：…G1 阶段执行报告`＋`> 钩子提取`／`> 真实变化`＋`【自检】✅` | 不是戏，是**验收报告** |
| 模板里带字段（因为/所以/但是/于是） | 3 场 × 4 行字段＝12 行，**`戏：` 正文 0 字** | 不是戏，是**空表格** |
| 素材＋体裁声明＋3 条可指认约束＋样例锚 | 355 字，有闲话台词、有未完成结尾、0 情绪标签 | 这才是**可拍场次** |

**三条 PPT 成因，全部可复现：**

1. **考核语言进生成 prompt**——只要出现"必须/须/通过/机检/自检/三要素"，模型的目标就从"写戏"变成"证明自己合格"，它交证明，不交戏。
2. **字段即交付物**——模型逐项满足清单，格子填满即完成，正文预算被字段吃掉。
3. **thinking 开着**——实测同一任务：开 223 秒 / 22833 字（其中 22k 是英文逐条核对要求），关 17 秒 / 388 字，质量不降反升。

**所以 v2 的总原则一句话：交付物 ≠ 生成步骤。**
`短剧编剧引擎.md` §10.2 的模板是**最终 `剧本.md` 长什么样**，不是**模型怎么生产它**。模型只写「戏」这一段，其余字段第二轮补、或人工补。

# 三、生成段（模型只做这一件事）

## 3.1 单场戏 prompt（照抄改素材即可）

```
你在写一场能直接拍的戏的正文，不是分析、不是大纲、不是方案。

素材：
题材：（…）
人物：（姓名＋身份＋关系＋各自想要什么）
道具：（本场关键物件）
冲突：（谁和谁因为什么对上）
上一场留下的：（一句话；本集第一场写"无"）

这一场只有一个因果：（一句话说清谁做了什么、卡在哪）。
情绪只能从手、呼吸、视线落点上看出来。
台词短，允许一句答非所问。
结尾停在动作中间。

直接开始写，第一行就是场景，写完就停。

【参考文风——只学语感，不抄内容】
（贴 200–300 字你自己认可、且干净无旁白的成稿）
```

**为什么是这三条约束**：字数、情绪落点、结尾方式是 9B 最容易崩的三处；其余要求（因果、潜台词、道具）由素材和样例锚承载，写成条款反而挤掉正文。

## 3.2 三条约束的替换菜单（每次只选三条，不许加第四条）

| 想解决的问题 | 换成这条可指认约束 |
|---|---|
| 人物在"说情绪" | 情绪只能从手、呼吸、视线落点上看出来 |
| 全是功能对白 | 台词短，允许一句答非所问 |
| 结尾收得太圆 | 结尾停在动作中间 |
| 人物站着说话 | 每个人说完话都要动一样东西（放下碗／擦桌／转身） |
| 五块并列 | 动作和台词按发生顺序写成连续段落，不换行分栏 |
| 写成小说旁白 | 只写摄影机能拍到的东西 |

**禁止使用否定式**（"不要写…""不许…"）：9B 会把被否定的内容当成话题。一律改写成"只能……"。

## 3.3 样例锚（性价比最高的一条）

同一个模型，带锚与不带锚的差别大于换模型：

- **锚从哪来**：你认可的一场成稿，200–300 字，**必须干净**——无 `【幕落】`、无 `（场景定格）`、无"仿佛…"式收尾旁白、无"眼眶红了"类标签。
- **锚怎么用**：贴在 prompt 最末，标注"只学语感，不抄内容"。
- **代价**：锚的毛病会一起传染（实测里"仿佛那是个能吞下秘密的黑洞"就是从锚学来的比喻腔）。所以锚要人工筛，一次只放一段。

## 3.4 生成段禁用词（出现一个就开始 PPT）

```
必须 / 须 / 确保 / 需通过 / 验收 / 机检 / 自检 / 检查表 / 打分
check_script_causality.py / check_hook_density.py / G1 / 三要素 / 钩子密度
报告 / 汇总 / 表格 / 栏目 / 字段 / 第 X 集执行 / 作为编剧你应该
```

也不要在生成段写"你是短剧编剧，按以下 8 条要求"这类**任务书句式**——它是"合规寄存器"的开关。

## 3.5 多场 = 链式调用（不要一次写三场）

实测：一次要三场，9B 只交了一场还漏了开场；字段模板则直接把正文清零。

**做法**：每场单独一次调用，本场输入 = 上一场那个"于是"（一句话）。

| 轮次 | 输入 | 输出 |
|---|---|---|
| 1 | 素材＋`上一场留下的：无` | 场景 1 正文 |
| 2 | 素材＋`上一场留下的：（场景 1 结尾那个未完成动作）` | 场景 2 正文 |
| 3 | 同上 | 场景 3 正文 |

集尾卡点在最后一轮单独要：`把这场结尾改成停在一个未完成的瞬间，其余不动`。

## 3.6 大纲 / 分集表（允许 PPT，但必须单独调用）

大纲本来就该是表——**它不算 PPT 问题**，问题是别和写戏放在同一次调用。

- 分集总表用引擎 §10.1 的全剧总表八列，单独一次调用。
- 出完大纲**另开新会话**再写戏，避免语域被表格带走。
- 单集大纲条目（时间地点/集首钩子/核心冲突/情绪蓄积点/关键新信息/反转/集尾卡点/承接/道具）同样是**记录形态**，放在 §四补全。

# 四、字段补全段（记录，不是创作）

`短剧编剧引擎.md` §10.2 的模板要求每场有：人物、本场因果（因为/所以/但是/于是）、本场变化、谁在瞒谁、种子落点、戏。**「戏」由 §三产出，其余字段第二轮补。**

## 4.1 场记调用（推荐）

另起一次调用，system：

```
你是场记，只做记录，不写戏、不改台词、不加评价。
按下面格式逐项填写，填不出来的写"未定"，不许编。
```

user：`【场景正文】…` ＋格式骨架（人物／因为／所以／但是／于是／本场变化／谁在瞒谁／种子落点）。

**要求**：输出里不许出现"以下是""总结""分析"；每项一行，不加解释。

## 4.2 或人工填

九行字段人工填通常比模型快，且"因为/但是"的质量直接决定 G1 是否通过（引擎 §11.1）。**只有你自己知道这场戏到底想说什么**，所以这两个字段建议默认人工。

# 五、验收段（绝不进生成 prompt）

## 5.1 脚本机检（先跑，零成本）

```bash
python tools/check_script_causality.py <项目目录>
```

退出码不为 1 才算过（见 `AGENTS.md` G1）。机检只抓结构，抓不到"好不好看"。

## 5.2 人工自检表（每稿必过）

**因果与可读性**（任一项不过 = G1 不通过）

- [ ] 每场都能填出「因为 / 所以 / 但是 / 于是」，且「因为」「但是」不是空话
- [ ] 前一场「于是」能接上后一场「因为」
- [ ] 正文没有镜头参数（刀号、时间码、机位、焦段、景别、光比、色温、mm）
- [ ] 每场至少发生一项真实变化：新事实 / 关系 / 选择 / 情绪
- [ ] 朗读测试通过（见 5.3）

**台词与场景**

- [ ] 台词口语化，没有书面语、没有无功能寒暄
- [ ] 每句重要台词至少承担一项功能；**全集至少有一句不推进、只暴露人的台词**
- [ ] 没有连续三句以上的纯信息对白
- [ ] 人物除了嘴还有别的动作（站位、视线、接触、遮挡、受力）
- [ ] 没有"她很难过"这类**裸情绪标签**；但允许且鼓励写人物怕什么、想瞒什么（引擎 §11.3）

**合规**

- [ ] 反派靠利益剥夺 / 收回资源 / 公开羞辱 / 逼迫签字，不靠连续粗口
- [ ] 反击走合法追责、证据揭露、规则内竞争，不靠私刑
- [ ] 无未成年人不当内容、无赌博/迷信/血腥细节、无真实机构与公众人物

**本地模型专属坑**

- [ ] 结尾没有「（完）」「【幕落】」「以下是」、没有总结句
- [ ] 角色没被替换、没被凭空增加（Gemma 常见：把男主换成管家、凭空多出"小儿子"）
- [ ] 没有英文思考过程混进正文（确认 `--reasoning off` 生效）
- [ ] 判定是否截断**以 `finish_reason` / `Stop Reason` 为准**，不看终端视觉位置

## 5.3 朗读测试（引擎 §11.5 的落地）

只把「戏」的正文，不带大纲和字段，交给一个新上下文读者，让他复述：谁想要什么、被什么挡住、最后卡在哪、哪一处细节只属于这个故事。复述原话照抄进剧本，**对不上就改剧本，不改复述**。

# 六、返修段（一次只改 1–2 项）

```
下面这场戏有一个问题：〔一句话，必须具体到可指认〕
只改这一点，其余原样保留。
改完直接给新正文，不要说明改了什么。
【原文】…
```

- **一次只改一项**：9B 同时改三处会整体重写，把好的地方也改掉。
- **不要"改动说明"**：那句话一旦粘回 `剧本.md` 就是 PPT 腔；改动理由写在 `变更记录.md`，不进剧本。
- 改完仍不过 → 回 §三重写一场，比反复返修便宜。

# 七、模型分工（v2 修订）

v1 的"Gemma 写人 / Qwen 写局"是**过度拆分**。实测 Qwen3.5-9B 在单场里能同时扛人物细节和结构伏笔（保温壶的体温＋借舅舅的嘴埋"遗嘱"），它真正的边界是**一次只能写一场**，不是"只会写局"。

| 场景 | 用谁 | 理由 |
|---|---|---|
| 日常写戏 | **Qwen3.5-9B** | 单场全能，不丢角色，中文对白最像人话 |
| 要更文艺的语感 | Gemma-4-12B | 细节更细，但中文欧化、显存只剩 374 MiB |
| 机器还要跑别的软件 | Gemma-4-E4B | 4806 MiB，但**会丢角色**，必须逐场核人名 |
| 草稿 / 改名 / 改台词 | Qwen3.5-4B | 快，但爱堆比喻（"瞳孔地震"级） |

**保守默认：Qwen3.5-9B + 16384 + thinking off。**
