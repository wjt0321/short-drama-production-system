# 题材取材与角色卡

## 〇、一句话

**角色卡的价值在于"锁死"，不在于"写得好"。先从剧本、视觉圣经和题材常识确定身份，再把需要的维度写成可执行字段；只有在用户提供或维护任务明确授权时，才分析外部参考。**

---

## 一、核心原则：借结构，不抄句子（合规底线）

**整段复制别人的提示词会把别人的角色和风格一起带进来。** 角色设计按以下顺序执行：

1. **定意图**——从剧本、人物目标、关系、权力位置和行为习惯确定角色身份；
2. **拆字段**——用体系内词表和角色卡模板，把身份、服装、道具、动作习惯写成可见事实；
3. **做取舍**——只保留能形成记忆点、能跨镜复现、能服务剧情的字段；
4. **查参考**——只有用户提供参考或维护任务明确授权时，才提取结构，不复制原文、成图或独特设计，并登记来源与借鉴点。

| 允许 | 禁止 |
|---|---|
| 研究题材通常由哪些维度构成 | 把外部提示词原文整段抄进资产文件 |
| 把抽象审美改写成材质、边界、方向、受光和动作 | 搬运外部成图作为本项目资产 |
| 记录来源、授权状态和不适用处 | 把外部样片当作本片的默认风格答案 |

---

## 二、角色字段的三条来源

### 来源 A · 剧本与导演视觉圣经（默认）

先读取 G0 风格基线、G1 人物设定和项目资产。角色的脸部结构、体态、服装层级、固定道具、动作习惯和色彩归属，都必须能解释其身份、目标或关系。

### 来源 B · 体系内方法与词表（默认）

使用 `02-分镜与镜头/影视视听语言速查.md`、角色卡模板、`角色造型与写真.md` 和 `角色一致性.md`，把抽象词改成可检查、可复现的字段。缺少信息时采用保守默认并记录，不以外部库填空。

### 来源 C · 用户提供或维护任务授权的参考（可选）

参考图、提示词、教程或研究资料只用于提取结构和验证方法。完成拆解后回到本剧语境重写；记录来源、授权状态、借鉴点和不适用处。外部参考数据不属于普通制作入口。

---

## 三、从角色意图推导提示词字段

角色卡先由剧本和导演视觉圣经确定，再把身份事实翻译成可执行字段。默认使用体系内的 `02-分镜与镜头/影视视听语言速查.md`、角色卡模板和本项目已冻结资产；用户提供的参考可用于理解结构，但不作为角色脸、服装或风格的答案。

推荐顺序：

1. 写清角色的身份、目标、关系、权力位置和行为习惯；
2. 提取不可变特征：脸部结构、发型轮廓、体态、服装层级、常用道具和动作习惯；
3. 把抽象形容词改写成可见事实：材质、边界、方向、受光、磨损、视线和动作幅度；
4. 用角色参考板与小样检查跨镜一致性，把通过版本写入项目资产，不依赖外部提示词库。

角色卡需要可执行的字段，不需要复制任何外部提示词。若确需研究外部资料，单独登记来源、授权和借鉴点，完成结构抽象后立即回到本剧语境重写。

## 四、从对标反推角色卡字段

这是本文件的核心方法。没有外部参考时，用题材常识、体系词表和本剧设定完成同样的字段拆解。

### 4.1 为什么不能抄提示词

别人的提示词是为**他的角色**写的，字段混着三样东西：
- **身份字段**（长什么样）——这才是角色卡要的；
- **场景字段**（在哪、什么光）——这属于场景卡；
- **画面字段**（景别、角度、质感）——这属于分镜表。

整段抄过来，三样混在一起，**没法锁**。所以必须拆。

### 4.2 拆解流程

拿 5–10 条用户提供或经授权的同题材参考，逐条拆；没有这类参考时，直接从题材常识与体系词表建立维度表：

| 拆出来的维度 | 归到哪 | 角色卡里的字段 |
|---|---|---|
| 脸型/骨相/年龄感 | 身份 | 年龄感/骨相 |
| 发型轮廓、发际线 | 身份 | 发型/发色 |
| 眼型眼距、眉形 | 身份 | 眼睛/眉形 |
| 身高体态比例 | 身份 | 体态/身高关系 |
| 服装版型、主色 | 身份 | 固定服装 |
| 饰品、纹样、器物 | 身份 | 固定配饰 |
| 标志色（这个角色专属的颜色） | 身份 | 色彩归属 |
| 背景环境 | **场景** | → 场景卡，不进角色卡 |
| 光线、色调 | **视觉圣经** | → 色彩脚本/照明卡 |
| 景别、机位、画幅 | **分镜** | → 分镜表 |

**统计这一步的价值**：统计 10 条提示词里"敦煌风角色"最高频出现的 5 个维度，那就是这个题材的**通用维度集**。**你自己角色的特征，就从这 5 个维度里选 3 个做主、2 个做辅**——这比凭空捏脸准得多，也比抄别人的有原创性。

### 4.3 主辅关系

`角色造型与写真.md` 定妆分支已经确立了"**锁一个主记忆点，其余五官做陪衬**"的原则。取材时把这个原则放大：

- 从对标里统计出该题材的**常见主记忆点**（敦煌风多是"头光形状"与"飘带"；神怪多是"眼睛/额饰"；市井多是"身形与衣着层次"）；
- 本角色的主记忆点，**要么选该题材的常见项**（观众一眼认得出是这类），**要么明确反着来**（产生辨识度）；
- **不允许**落在"既不常见、也不反差"的中间地带——那是"没记忆点"。

## 五、角色卡自动生成流程

### 5.1 触发条件

满足**任意一条**时启动本流程：
- 用户要新建角色，但只给了"一个会武功的道士"这类粗略人设；
- 用户说"角色卡怎么自动生成"；
- 用户提供了参考，需要把维度落成字段。

### 5.2 执行步骤

**第 0 步 · 补齐人设缺口**
按 `角色造型与写真.md` 定妆分支的"用户输入信息"七项检查：年龄感、性别、气场、身份、画面类型、背景诉求、风格诉求。缺的**按选项问用户**，不要自行发挥（体系铁律：有矛盾就提出来，别自己拍脑袋）。

**第 1 步 · 取对标维度**
按 §四 拆 5–10 条参考（若用户未提供，直接依据剧本、题材常识和体系内词表建立维度表）。
产出：《对标维度表》——题材通用维度集 + 高频项排序。

**第 2 步 · 选主辅**
从通用维度集里定 **1 个主记忆点 + 2–3 个辅维度**，写明选择理由（"选头光形状为主，因为本片是敦煌题材，观众预期在此"）。
**主辅选择必须让用户确认**——这是创作决策，不是执行细节。

**第 3 步 · 落字段**
把选定维度填进 `模板/短剧项目模板/02-资产/角色/角色卡.md` 的对应字段。每个字段写成**可直接嵌进提示词**的表述（对齐 `角色造型与写真.md` 定妆分支的"给出结论时要写成能直接嵌进提示词的表述"）。

**第 4 步 · 生成身份合同**
按 `角色一致性.md` §八 的"身份合同"格式，把角色卡里的不可变项转成**锚句**（可跨镜头复用的定长字符串），登记进《锚句表.md》。

**第 5 步 · 出角色双参考板**
按 `角色造型与写真.md` 定妆分支确认身份，按 `角色资产参考板.md` 先出身份造型合板（左半身定妆、右正/侧/背全身），再从同一身份派生日常表情九宫格；允许分图核对后拼板，保留源图。走 `02-分镜与镜头/图片生产清单.md`（指针→模板 `模板/短剧项目模板/03-分镜/图片生产清单.md`），两板共同冻结、统一版本，按镜头选择整板/裁图并验证，不默认两板每镜全上。
**出图策略用 `02-分镜与镜头/分镜工作流.md` §十四 的并行候选**（同提示词换 seed，出 3 张选 1）。

**第 6 步 · 过检与冻结**
走角色卡自带的 G2 审核项。通过后状态置「冻结」，进入 G3。

### 5.3 自动化边界

| 可自动 | 必须用户裁决 |
|---|---|
| 维度统计与排序 | 主记忆点选哪个 |
| 字段填充的技术性表述 | 角色身份的整体方向 |
| 锚句生成 | 是否冻结（G2 关卡不可逆） |
| 双参考板出图、同身份核对与候选筛选 | 成图是否达到"过检"水准 |

**G2 之后角色冻结**（`AGENTS.md` 关卡不可逆规则）——自动生成流程可以一路跑到"待审"，**不能自己按下冻结**。

## 六、题材专项：中式神怪角色设计（十要素）

用来设计中式神话、神怪、仙侠类角色（神将、护法、妖、仙、异兽等），并生成可用的角色图或生图提示词。核心逻辑：**身份决定一切视觉元素**——先定角色是谁，再让服装、武器、纹样、环境都服务于身份；全程用文化母体锁住东方美术风格，防止滑向西方奇幻。

**工作流程**：

1. **定身份**：先弄清角色是谁（见 6.1），信息不足先补齐，别急着写外貌。
2. **逐要素设计**：按十要素清单（见 6.2）逐条给出可直接使用的设计决策。
3. **合成提示词**：把十要素决策拼成一段完整提示词（见 6.3）。
4. **出图**：调用 generate_image 生成。
5. **自查迭代**：出图后对照十要素检查，弱的要素单独改，再重新生成。

### 6.1 定身份（动笔前必做）

拿到需求先回答四问。答不上来就按文化常识给合理默认并请用户确认，不要跳过：

- **身份与名号**：具体是谁（如北方多闻天王、门神秦琼、龙王敖广）。
- **神话体系**：出自哪套体系（佛教护法、道教神祇、民间传说、山海经、西游封神等）——体系决定后续可选的文化母体与纹样。
- **方位与阵营**：镇守/管辖什么（方位、司职、所属阵营）。
- **职责与气质**：管什么（财富、风雨、护法、征伐），气质是威严、慈悲、凶悍还是诡谲。

身份越明确，后面的服装、武器、纹样、环境越容易围绕同一主题展开。**不是先造一个怪人再套名字，而是让所有视觉元素都服务于身份。**

### 6.2 十要素设计清单

逐条给出设计决策。每条写能直接进提示词的描述短语，不要写"要有神秘感"这类空话。

1. **身份设定**：定身份四问的结果，作为全文主线，其余九要素都围绕它展开。
2. **文化母体（美术风格的锁）**：主动指定视觉来源，把风格锁死在东方宗教/民间艺术里，例如：中国佛教壁画、敦煌彩塑、寺庙护法神像、古代彩绘雕塑、青铜器纹饰、木版年画、戏曲脸谱。中式神怪最容易生成成西方奇幻，文化母体是防止跑偏的第一道闸——冠饰、甲胄、面部结构、色彩、材质体系都从母体里取。
3. **身体比例（神性与压迫感来自尺度）**：神不用普通人体比例。写：巨大体型、宽肩、厚重胸腔、强壮四肢、夸张比例、威严站姿、低机位全身视角。"神"很大一部分来自尺度与比例，而不是光效堆叠。
4. **面部结构（结构＋情绪＋混合来源，三件套）**：不要只写"凶恶的脸"。先拆结构：高额头、厚眉骨、怒目、宽鼻、微张嘴、短獠牙；再写情绪：怒目圆睁、不怒自威；最后给混合来源，如"武将＋夜叉＋护法神＋青铜祭祀神像"的混合形态。混合来源保留人形又产生中式怪诞感，不会滑向纯怪兽。
5. **古老材质（古老感的核心是时间痕迹）**：金色不产生古老感，时间痕迹才产生：剥落彩绘、氧化铜锈、香火熏染、细小裂纹、旧金属磨损。底色用青铜、暗金、石青、赭红。材质里加入历史，角色才像"从壁画神像里活过来的"，而不是 3D 游戏皮肤。
6. **冠饰甲胄（呼应身份与司职）**：按身份与体系选择：兜鍪、束发冠、璎珞、披帛、法衣、金甲……每个部件都要能回答"为什么是他戴的"。
7. **专属武器与道具（符号即身份）**：武器道具直接讲职责：四大天王里持琵琶（东方持国）、持剑（南方增长）、缠龙蛇持长兵器（西方广目）、托宝伞宝塔（北方多闻）。其余角色同理：门神配鞭锏，龙王配玉圭或分水刺，雷神配锤凿。
8. **宗教纹样（按角色重新组合，不堆砌）**：从母体里取：雷纹、云纹、莲花、法轮、火焰、兽首、眼纹、回纹……按角色司职组合，管风雨的多云纹水纹，护法的多火焰兽首，不要全往上堆。
9. **神性环境（角色与背景同一世界观）**：补上与环境互动的描写：火焰背光、天云、经幡、鬼气、残破邪祟能量、香火缭绕、电闪雷鸣。环境不是装饰，是角色身份的延伸。
10. **镜头语言**：低机位仰视全身、广角近景强调体量、背景虚化聚焦面部、逆光轮廓光……按你想突出的重点选一到两种。

### 6.3 合成提示词

把十要素决策按顺序拼成一段连续提示词，句式：身份＋文化母体＋身体比例＋面部＋材质＋冠饰甲胄＋武器＋纹样＋环境＋镜头。示例（北方多闻天王）：

> 北方多闻天王，镇守北天门，统御财富与天军，中国佛教壁画与敦煌彩塑风格，寺庙护法神像质感；巨大体型、宽肩、厚重胸腔、夸张比例、威严站姿；高额头、厚眉骨、怒目圆睁、宽鼻、短獠牙，武将与夜叉的混合面相；青铜与暗金甲胄，剥落彩绘、氧化铜锈、香火熏染、细小裂纹；束发冠、璎珞、金甲；右手托宝伞、左手托宝塔；甲胄上雷纹、云纹、莲花、兽首纹样；火焰背光、天云翻涌、经幡飘动、残破邪祟能量环绕；低机位仰视全身，广角，逆光。

若所选生图模型对英文更友好，把关键描述词（身份、文化母体、材质、纹样）译成英文关键词混排，保持结构不变。

### 6.4 出图与迭代

- 调 generate_image，prompt 填合成好的提示词；用户明说的画幅（如 9:16、16:9）原样填 aspect_ratio，张数填 count，不要自行改参数或凑上限。
- 出图后用 view_image 检查（也可请用户确认），对照十要素自查：身份一眼可辨吗？有没有滑向西方奇幻？材质有没有时间痕迹？哪条弱就只改哪一条，重新合成再生成。
- 用户要多个角色或一组变体时，用 items 一次并行生成；同套提示词要多张变体用 count。

### 6.5 边界

- 用户只给角色名或一句话时，先补齐身份四问（给默认值请确认），不要直接开写外貌。
- 涉及真实宗教造像时按文化尊重原则处理：可以庄严、可以神性，不丑化、不恶搞、不歪曲其宗教含义。

## 九、注意事项与检查清单

### 9.1 注意事项

1. **合规**：库内提示词来自公开作品，**学习其结构可以，直接照搬出图商用需自行判断授权风险**。建议只取结构、换内容（§一）。
2. **参数别盲抄**：`steps/cfg/seed` 是原作者的模型和分辨率下的值，你换模型后要重调。
3. **模型依赖**：部分提示词依赖特定 LoRA/Checkpoint，换模型效果会崩，先看条目里的模型引用。
4. **多语言混用**：中文提示词与英文提示词各有优势——中文适合意境与文化专有名词，英文适合精确控制构图与光照。**同一镜头不要中英混写**，参见 `04-视频生成/平台提示词契约.md` 的语法对照。
