# 场景与道具资产

G2 不只是生成好看的背景和物件，而是确认后续镜头可复用的空间、物件身份及允许状态。参考板组织信息，不自动保证生成一致；静图检查不代替运动和跨镜小样。

## 一、输入与输出

### 输入与阶段顺序

- G0 风格基线、色彩脚本与照明卡；G1 剧本中的地点、道具、文字及关键动作。
- **G2 使用预拆镜估计机位、景别、人物活动及交互需求，不要求 G3 最终分镜先冻结。**
- G3 最终分镜核对资产覆盖：增加所需视角可从冻结基准派生并登记/检查；不得借补图改布局、物件身份或冻结的核心设定。确需改变时按 `AGENTS.md` 授权与解冻规则处理。

### 默认交付

| 资产 | 核心产物 | 按需补充 |
|---|---|---|
| 反复使用或承担叙事的场景 | 场景卡、**空间总览图 + 所需机位参考板**、空间/光源基准 | 复杂走位的简单空间示意图；重要局部、日夜或灯光等状态图 |
| 重要道具 | 道具卡、**身份细节合板**、尺寸/识别点及状态记录 | 手持/佩戴/操作的交互尺度图；剧情需要的状态图或状态板 |

只需一个机位时，总览或该机位单图可承担参考职责，记录覆盖范围，不为凑板重复出图。不强制场景九宫格、道具三视图，也不将所有背景小物件单独建包。角色沿用 `角色资产参考板.md` 的双参考板规则。

## 二、场景空间与机位参考

### 2.1 场景卡的稳定基准

每个会在两个以上镜头出现或承担叙事功能的地点建立场景卡，至少记录：

| 字段 | 记录内容 |
|---|---|
| 场景 ID / 版本 | 稳定地点身份、设计版本、通过文件 |
| 固定空间参照 | 采用墙面/入口编号、固定地标或方位；门窗、楼梯、通道、家具的位置关系。**必须产出"命名地标清单"**：每个会被分镜引用的固定物件给稳定短名 + 一句话画面描述（例：`地标A=红木书桌，靠 W2 窗墙，桌面常置铜台灯`）。锚点四子项（见下）只能从这张清单里取词——清单为空，G3 的"固定地标"列就无从填起 |
| 空间尺度 | 门高、桌面、通道等必要尺寸或相对比例；人物活动范围 |
| 机位 | CAM 编号、位置、朝向、景别/焦段及服务镜号 |
| 人物与道具位置 | 所在区域、朝向、相对出口与接触物的位置；当前状态另记 |
| 光源基准 | 具名光源在空间中的位置、高度、硬柔、色温与照亮范围。光源也要有短名（例：`主光=西窗斜阳`），G3 锚点"光位基线"引用短名 |
| 时空状态 | 日夜、天气、门开关、灯亮灭、桌面陈设变化及触发事件 |
| 固定识别点 / 禁止变化 | 门窗数量、主要结构、固定地标及不能无故新增/消失的物件 |

### 2.2 固定空间方位，不固定每个机位的画面左右

先描述场景实际位置，再描述当前机位的画面投影。可以采用“入口墙 W1、对面窗墙 W2、桌子靠 W2”这样的局部参照，不强制测绘或真实地理坐标。

- CAM01 朝窗墙拍，窗可能在画面左侧；反向 CAM02 拍时窗可能转到画面右侧或出画。这是投影变化，不是窗换了位置。
- **锁的是具名光源在空间里的位置，不是每镜都从画面左侧打光。** 换机位后顺逆光、受光面及画面内阴影方向可改变，但应与同一光源和当前机位相容。
- 地标因遮挡/出画不可见时说明原因；不能为“每镜都看见”而移动门窗。画面左右、视线和运动方向结合机位、轴线判断，不靠锁死屏幕坐标代替空间连续。

### 2.3 总览、机位板与空间示意图

1. **先做清晰空间总览**：确认出入口、主要家具/地标、通道、人物活动区与光源。总览看不到的背面不视为已经设计好。
2. **按预拆镜选择所需机位**：从同一空间基准派生正反打、侧机位、入口或重要局部。新增可见区域先确认其布局与既有空间相容，再登记；不允许各角度独立重抽成不同房间。
3. **核对后拼成所需机位参考板**：每格对应 CAM 编号，保留高清单机位源图；格数和布局按需求与实际输入可辨识度决定，不强制九格，不为填空编造角度。
4. **复杂走位补简单空间示意图**：标出门窗、固定地标、人物位置、轴线和机位朝向即可，不要求3D工程。示意图默认用于规划与核对，不自动投喂视频模型；确需作为输入要先验证适配。
5. **空场与人物身份分开**：场景底图不混入陌生清晰正脸。环境群众按需要远景化、背影化；互动关键帧再加入正确角色，检查尺度、遮挡、接触、视线和受光。
6. 日夜、灯光开关、门开合或物件位置变化，只补实际用到的状态图，沿用同一空间设计。按镜序核对总览、机位与状态，长镜头技术分段额外检查接缝。

### 2.4 场景提示词内容模板

```text
使用{场景基准ID/版本及真实参考输入}，输出{当前空间状态}下的{CAM编号}单机位场景图。
固定关系：{入口/墙面/门窗/地标编号与相对位置、必要尺度}。
机位位于{空间位置}，朝向{目标区域}，{景别/焦段/高度}。
当前可见：{前中后景与画面左右投影}；{哪些基准地标出画或被遮挡及原因}。
主光来自{具名光源的空间位置}，{硬柔/高度/色温/照亮范围}，本机位的受光与阴影为{说明}。
沿用{材质、陈设、风格}，只改变机位或已登记状态，不移动固定门窗/家具来凑构图。
{空场/背景人群限制}；不添加未经设计的叙事物件或乱码。
```

> 模式分流（依据 `04-视频生成/平台提示词契约.md` §2.4 图生/多参考模式图文分工，2026-10-13 立）：
> - **文生图路径**（无场景基准参考图接入）：代码块第 71 行「沿用{材质、陈设、风格}…」**全写**；提示词头部写 `模式：文生图`。
> - **参考编辑路径**（场景基准图已作为参考图接入生成）：第 71 行「沿用{材质、陈设、风格}…」可省——图已承担材质/陈设/风格；提示词头部写 `模式：图像编辑`；但参考图未覆盖的陈设/状态变化仍必须写。
> 闸门 `tools/check_style_lock.py` 据此分流校验；缺头部模式声明一律按文生图从严。

先生成/检查单机位，必要时再拼板；直接生成多机位板也须逐格核对。提示词中的 ID 不等于平台标签，实际输入映射按能力登记执行。光型和层次取法见 `导演视觉圣经.md` 照明卡，保留主辅光、反射/遮挡、阴影与时间依据，不只写“暖光/电影感”。

## 三、道具身份细节合板与交互

### 3.1 重要道具卡

重要道具回答“它是哪件物品、现在是什么状态、在哪里/谁持有、下一镜怎样变化”。

| 字段 | 记录内容 |
|---|---|
| 道具 ID / 设计版本 | 稳定身份、轮廓、结构部件、材质、主辅色与固定识别点 |
| 尺寸/比例 | 绝对尺寸（已知时）或与人物手、身体、桌面、环境的相对比例 |
| 文字/标识 | 原文、朝向、位置、可辨识要求及必要的独立文字资产 |
| 必要角度/局部 | 服务辨识或操作的正背/侧/内部、纹样、扣件、铰链等，不固定数量 |
| 交互方式 | 握、拿、放、佩戴、打开、递交；接触部位、朝向、左右手 |
| 新旧/使用痕迹 | 按剧情设定，区分固定特征与后续破损/沾污状态，不统一做旧 |
| 状态与禁止变化 | 允许的开合/完整/数量/亮灭状态，以及不能无故变形、换色、换材质的部分 |

### 3.2 身份细节合板

- 以一个清晰主体大图为核心，在旁边放必要角度及识别细节局部。具体分区比例按物件结构与可辨识度调整，不机械照搬人物左半身右三视图。
- 同一件道具、同一设计版本、同一基准状态；多角度和放大局部不代表多个实体。放大图用于细节，不作为尺寸比例依据。
- 玉佩可能需要正背面及纹样；箱子可能需要外观、锁扣和铰链。打开后的内部结构若属于另一状态，在状态图中明确登记，不将两种开合状态含糊混在身份基准里。
- 可直接出板或同基准派生单图后拼板；保留高清源图。不同区域先核对形状、零件数、材质、纹样和文字，再用于后续参考。

### 3.3 交互/尺度参考与状态图

- 有手持、佩戴、操作的镜头，按需生成**实际角色 + 同一道具**的交互图，检查大小、握持位置、左右手、接触/遮挡及佩戴方式。避免陌生手部、衣袖或脸被误当角色基准。
- 单纯尺寸示意应标明其作用，不自动当成场景首帧。正式互动关键帧须加入当前场景与正确受光。
- 剧本确有开关、破损、沾水或缺件时派生对应状态图；状态板可用于整理和审核。**生成某个瞬间时选择当前状态，不把互斥状态同时当起始参考。**
- 表达状态变化过程时分别写起始状态、触发动作、可见过程与结果；支持首尾帧或其他状态输入时明确各自角色，不让模型自行挑状态。

### 3.4 道具提示词内容模板

```text
基于{道具身份ID/设计版本及真实参考输入}制作身份细节合板。
主体大图完整展示{形状、结构、材料、颜色、基准状态、固定识别点}。
旁边仅补{必要角度/细节局部}，均属于同一件物品，不是多件道具。
尺寸依据为{尺寸或比例}；放大局部不用于判断整体大小。
文字/纹样为{原文、位置、方向}，不要自行增删部件、镜像文字或改变材质。
使用{项目美术风格}与干净背景；新旧和磨损程度按{剧情设定}，不默认做旧。
```

> 模式分流（依据 `04-视频生成/平台提示词契约.md` §2.4 图生/多参考模式图文分工，2026-10-13 立）：
> - **文生图路径**（无道具基准参考图接入）：代码块末行「使用{项目美术风格}…」**全写**；提示词头部写 `模式：文生图`。
> - **参考编辑路径**（道具基准参考图已接入）：末行「使用{项目美术风格}…」可省——参考图已承担美术风格与材质基调；提示词头部写 `模式：图像编辑`；但局部材质变化、文字/纹样改动、使用痕迹等参考图未覆盖的细节仍必须写。
> 闸门 `tools/check_style_lock.py` 据此分流校验；缺头部模式声明一律按文生图从严。

交互图沿用该身份，另写角色 ID、当前状态、左右手/佩戴处、接触位置、相对尺度、场景受光；不直接套用独立道具图的“无人物无手部”要求。重要文字无法可靠生成时单独制作并适配画面，不接受乱码，不宣称后期随意叠字即可处理所有运动遮挡。

## 四、设计版本、剧情状态与跨镜连续性

**设计版本回答“是哪一个资产”，状态编号回答“这一刻是什么样”。** 同一箱子从关闭 P0 到打开 P1，不自动升级设计版本；改变箱体尺寸、材质或铰链位置才涉及设计变更。场景同理：同一房间开灯/关灯是状态变化，不是新建一个房间。

| 状态编号 | 可见状态/数量/缺件 | 触发事件与镜号 | 下一状态 | 允许回退及依据 | 状态图/基准版本 |
|---|---|---|---|---|---|
| P0 | | | P1 | | |
| P1 | | | | | |

| 镜号 | 资产ID/设计版本 | 起始状态→结束状态 | 持有者/左右手或接触部位 | 所在空间位置/摆放朝向 | 变化事件/下一镜约束 |
|---|---|---|---|---|---|
| S01 | | | | | |

- 状态变化落在分镜“镜前/镜后状态”、执行清单或既有首尾状态快照中，允许引用同一记录，不重复造表。
- 未发生触发事件就换手、变数量、开关或破损恢复，视为连续性问题；有意时间跳跃/空间切换按 `跨镜连续性与帧链法.md` 说明。
- 同一实体的不同状态沿用稳定 ID 与设计版本。多个相同款式物件同时出现且需区分时，加实例标识与数量，避免把多视图当多件，也避免多件被合并。
- 新设计/新地点创建新 ID；对旧身份的改动按冻结/解冻与版本规则处理。新增同设计的状态图、机位图或裁图登记来源和修订，不自动重开身份设计。

## 五、分级完整性，不追求无差别“细节拉满”

1. **强约束项**：叙事道具、固定地标、接触物件、观众需读懂的文字必须在资产和相关首帧中明确，不能留给视频阶段凭空补。
2. **背景装饰**：在场景基准中稳定呈现，逐镜继承可见部分；不为每个杂物建包，不强制每镜提示词逐项重复，但仍检查无故消失/新增的显眼元素。
3. **不可见项**：不为镜头外的物件堆提示词。换机位露出新区域时再设计核对，不声称一张总览已覆盖整个空间。
4. **新旧程度**：按时代、用途、人物经济条件与剧情决定。新礼物可以崭新，旧工具可以磨损；真实不等于一律粗糙、做旧或禁止光泽。
5. **清晰度按叙事需要**：证据纹样/文字特写须能辨认，背景无需全都锐利；景深、遮挡与暗部符合构图，不能把合理模糊误判为缺资产。

## 六、按镜头选择参考与最小验证

资产包不是固定上传列表。先判断本镜最不能错的是人物身份、空间、道具识别点还是接触关系，再按当前实现的输入名额和类型分配参考职责。

| 参考 | 默认职责与选择 |
|---|---|
| 角色双参考板/相关裁图 | 身份、服装、当前所需表情，不决定场景布局 |
| 场景总览/目标 CAM 单图或机位板 | 固定空间与当前机位、光源/时空状态；优先选与本镜相关的图 |
| 道具身份板/局部/当前状态图 | 物件身份、文字、比例和当前状态，不覆盖角色身份 |
| 同框交互关键帧 | 当前角色、场景、道具的实际位置/接触与受光 |

- 参考名额不足时，先分阶段生成并核对角色、场景与道具关系正确的正式关键帧，再进入视频；不靠塞满大拼图假装绕过输入限制。
- 机位板或状态板理解不稳定时，选择对应高清单图/裁图；登记父资产 ID、设计版本、CAM/状态编号和文件修订。裁图放在对应资产的项目目录内，不依赖散落中转文件。
- 仅支持首帧驱动时输入正式场景首帧，**不直接把多机位板、道具展示板或状态板当剧情首帧**。
- 输入参考职责、真实上传映射、实际缩放/裁切条件记在现有能力登记与镜头提示词中；示意标签不等于工具真实支持的引用协议。

批量投入前的小样按实际风险选择，不增加固定样片数量：

1. 查看实际输入文件，确认缩放后空间锚点、道具识别点/文字及局部仍可辨。
2. 有正反打/跨机位时核对门窗、通道、地标、人物关系与光源的空间一致性，不只比风格。
3. 有互动时核对握持/佩戴、左右手、大小、数量、零件与接触；有状态变化时验证过程和结果，不只验证静图。
4. 检查是否出现复制房间/物件、网格入镜、镜像标识、互斥状态混用；记录输入、结果、查看记录、已验证与未覆盖范围。

失败先定位本镜输入、状态或局部问题；同一路线按 `AGENTS.md` 重抽预算与回退链处理，不无限重试。若根因在冻结资产设计，按授权解冻后修复并重查受影响镜头，不默默改布局或物件身份。

## 七、资产合同、登记、冻结与验收

- 场景卡/道具卡作为可读取的**资产合同**，记录稳定 ID、设计版本、恒定/允许变化/禁止变化字段、通过文件及来源。机位、状态与裁图可追溯到该基准；G3/G4 记录设计版本与当前 CAM/状态，不只记文件名。
- 场景文件示例：`02-资产/场景/LOC01_空间总览_v1.png`、`LOC01_机位参考板_v1_r1.png`、`LOC01_CAM02_夜灯开_v1_r1.png`；道具示例：`02-资产/道具/PROP01_身份细节板_v1.png`、`PROP01_P1_打开_v1_r1.png`。后者均放在对应资产目录；v 表示设计版本，r 表示同设计派生文件修订，不覆盖旧文件。
- G2 按授权模式完成确认并冻结：全权委托由 Agent 自查记录，阶段审核由用户裁决。设计变更按 `AGENTS.md` 办理，不新增哈希审批链或重复台账。
- 与《项目状态摘要.md》《分镜表.md》《首尾帧衔接表.md》的现有记录互相引用即可，不额外建立一套连续性系统。

### G2 场景/道具审核包

用户重点看：地点是否对味、空间是否连贯、道具是否可辨、交互是否可信、状态变化是否讲得通。

- [ ] 场景总览与所需机位已覆盖预拆镜；单机位减量及未覆盖区域有说明，无固定九格门槛。
- [ ] 出入口/家具/地标在固定空间中一致；各 CAM 的画面投影、人物关系与光源合理。
- [ ] 重要道具身份细节板清楚，各角度同一物件；尺寸、零件、文字、材质与新旧设定一致。
- [ ] 交互尺度图和状态图按需齐备，设计版本与状态编号分开，左右手/位置/朝向/数量及触发镜号可追溯。
- [ ] 强约束可见资产无遗漏，背景继承合理，不以无差别堆细节代替叙事与构图。
- [ ] 实际输入、参考职责、裁图来源和风险小样已记录；静态通过不冒充动态通过，未验证范围已明示。
- [ ] 场景/道具锚句、照明基准、文件路径和版本已登记；按项目授权确认，不强制每次新增审批。
