> **定位**：本文件是 `双模型接力编剧流水线.md` 的**第 3 棒重构版**。前两棒不变，第 3 棒换架构。
> **不修改引擎结构**：规则的唯一权威仍是 `短剧编剧引擎.md`。
> **实测环境**：RTX 3070 8GB / i5-12400F / 32GB RAM / LM Studio + llama.cpp CUDA 2.64.0 / 2026-10-25。
> **实测样本**：《离谱日常》EP02 第 2 棒产出（23 个括号表演提示组 / 28 条台词 / 8 句因果四句）。

# 一、为什么要换第 3 棒

第 3 棒原本的职责：清掉心理副词与比喻，改写成能拍的动作。
问题是**四种方案全部失败**，而且失败方式各不相同：

| # | 方案 | 实测结果 | 失败性质 |
|---|---|---|---|
| ① | Qwen 直接改写长稿 | 几乎不动；**把「因为/所以/但是/于是」四句整句删掉** | 长文本编辑能力不足 |
| ② | 检查器模式（全文→清单 `<原句>\|<改后>`） | 模型按整句重写 → **吞台词**（"按流程来，先立项。"被整句删）、**改四句**（"彻底打乱逻辑闭环"→"打乱"） | 输出粒度错 |
| ③ | 逐组重写 batch=6 | 模型**每批重新从 1 编号** → 内容整体错位（一组被换成别组答案） | 编号对齐不可靠 |
| ④ | 逐组重写 batch=1 | 模型输出格式不稳，20/23 解析失败 | 自由文本不可靠 |

**共同的根因**：让 9B 模型做「长文本 → 结构化输出」的链路，本身就不在它的可靠区间。

# 二、第 3 棒 v2：三层架构

```
阶段1 规则层   分句级删/剥高置信度心理副词与比喻    零风险、可审计、秒级
   ↓  规则没吃干净的少数几段
阶段2 模型层   只处理残留的疑难段，一次一段         模型只做它擅长的语义替换
   ↓
阶段3 校验层   台词逐字不变 = 硬约束，不满足则整篇回滚
```

**关键设计：把"保护台词"从「求模型听话」改成「脚本硬拦截」。**
模型不再看到完整剧本，也不再有机会碰台词；台词与因果四句**物理上不进入模型的编辑范围**。

## 2.1 双模式（重要）

第 2 棒的输出格式不固定，会影响清理策略：

| 模式 | 触发条件 | 处理单元 | 规则强度 |
|---|---|---|---|
| **括号模式** | 稿里有 `（表演提示）` | 逐个括号组 | 可做整段删除（组是独立单元） |
| **正文模式** | 稿里没有括号，表演提示直接写在正文 | 逐行段落 | **只能删词，不能删整个分句** |

正文模式必须限制规则强度：删掉整个分句会让前后两个动作黏在一起，
或者把台词前的引导语吞进引号里（实测出现过
`「目光抬起，"这不叫事」` 这种台词被正文并进去的破坏）。
所以正文的整分句删除交给模型层，规则层只删词。

## 2.2 校验层的四条红线

| 检查 | 判定 | 触发后 |
|---|---|---|
| 台词内容 | 引号内文本序列**逐字**相同 | 整篇回滚 |
| 台词引号数 | 数量相同（配对没被打乱） | 整篇回滚 |
| 引号前结构 | 开引号前紧邻字符**不是汉字**（否则正文被并进台词） | 整篇回滚 |
| 因果四句 | 括号模式允许**词级**修正（如"试图构建"→"要搭"）；正文模式绝对不动 | 如实标记 |

模型层每条输出还要过**段级校验**：台词逐字相同 + 引号数相同 + 不含括号 +
不造原文没有的动词（"攥紧""挑眉"这类凭空出现的词直接丢弃该条）。

# 三、可执行脚本

| 文件 | 作用 |
|---|---|
| `tools/hybrid_cleaner.py` | 第 3 棒本体。规则层 + 模型层 + 校验层，双模式 |
| `tools/dual_model_drama.py` | 三棒流水线。第 3 棒已改为调用 `hybrid_cleaner.clean()` |

```powershell
# 单独跑第 3 棒
python tools\hybrid_cleaner.py <第2棒产出> <输出> --model gemma

# 跑完整三棒
python tools\dual_model_drama.py <任务文件> <输出目录>

# 只跑规则层（不调模型，秒级，用于验证规则表）
python tools\hybrid_cleaner.py <输入> <输出> --no-model
```

模型调用走 LM Studio CLI（`lms chat <modelKey> -p <prompt> -y --reasoning off`），
硬参数 `--context-length 8192` + `--reasoning off`（开 thinking 实测 7217 tokens / 129s，
关掉 96 tokens / 2.5s，质量无差别）。

# 五、为什么第 3 棒现在能用（与 v1 的差别）

| | v1（第 3 棒 = Qwen 改写） | v2（规则+模型+校验） |
|---|---|---|
| 模型看到什么 | 完整剧本 | 只有规则没吃干净的 2–10 段 |
| 模型要做什么 | 全文重写 | 单段重写 |
| 台词安全 | 靠 prompt 求模型听话（实测被吞） | 台词不进入模型范围 + 脚本校验 + 整篇回滚 |
| 因果四句安全 | 靠 prompt（实测被删） | 括号模式词级修正 / 正文模式绝对不动 |
| 可审计性 | 只能看 diff | 每条规则命中、每段模型改写都有记录（`_report.json`） |
| 心理副词残留 | 44 → 41（几乎无效） | 44 → 4 |

# 六、人工终审清单（缩小到两处）

第 3 棒现在能清掉大部分问题，但**仍不能省人工终审**，只剩两处要看：

1. **「试图…」式心理推断** —— 把心理伪装成动作
   漏网实例："试图用亲近感压制她的审视"
   改法：直接写他做了什么。对："身体前倾，手臂搭上桌沿"

2. **语义层的替换是否合理** —— 规则和模型做的是"删词"和"换动作"，
   但"换得对不对"要人来判断。例：人工稿把
   "他的呼吸明显变浅了一点，眼神从调查模式切换到困惑模式"
   改成"他俯身，鼻尖凑近冰箱缝隙"（把解释换成动作），
   自动清理只能做到"删掉前半句"，后半句要人判断该换成什么。

**判定口诀**：把"像/仿佛/似乎/试图/带着一种…的/"全圈出来，
不能直接拍出来的，一律改成动作或删掉。

# 七、局限

- **规则表是项目资产，不是通用方案**。`STRIP_RULES` / `BODY_SAFE_RULES` 里的词
  来自《离谱日常》的实际用词。换项目要按新稿的用词补规则，
  否则模型层要处理的段数会上升（但不会失控，校验层兜底）。
- **规则层的整分句删除只在括号模式可用**。正文模式删整句会破坏句子结构，
  这也是为什么正文模式的清理效果（9→2）不如括号模式（44→4）细致。
- **模型层用 Gemma 而不是 Qwen**。第 3 棒原本指定 Qwen（认为它语感更"功能化"），
  实测发现：**在"单段改写"这个具体任务上 Gemma 明显更稳**。
  Qwen 在这个任务上更爱原样输出。
- **3 场以上需重新验证**。因果链在第 3 棒清洗后可能产生新断裂，链越长风险越大。
- **整集成稿不要走这个流水线**。多集结构超出单次上下文承载，
  应先用 Qwen 单跑分集大纲，再逐集走本流水线。
