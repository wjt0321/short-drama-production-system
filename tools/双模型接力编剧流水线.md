> **定位**：本文件是《短剧编剧引擎.md》的**执行层工具**——把引擎规则拆成两棒接力，交给两个本地模型分工完成。
> **不修改引擎结构**：规则的唯一权威仍是 `短剧编剧引擎.md`。本文件只解决"怎么让两个模型接力写"。
> **配套**：`本地模型剧本生成模板.md`（单模型 prompt 模板与题材派活表）。
> **实测环境**：RTX 3070 8GB / i5-12400F / 32GB RAM / LM Studio + `llama.cpp-win-x86_64-nvidia-cuda12-avx2` 2.64.0 / 2026-10-25。

# 一、为什么要接力而不是单模型出稿

单模型一次性写完整剧本，有两个反复出现的病：

| 病 | 表现 | 单模型成因 | 接力解法 |
|---|---|---|---|
| **PPT 五块并列** | 场景头/人物/动作/台词/结束状态各占一段 | 模型在"填表"而不是"写戏" | 第 1 棒就要求动作与台词交织的段落 |
| **比喻句散文感** | "眼神像在扫描每一个字符""像被无形的力量钉住" | 加表演细节时，模型倾向于用比喻代替动作 | 第 2 棒加厚细节，第 3 棒专门清比喻 |
| **角色跑偏** | 凭空多出"小儿子"，把男主角换成管家 | 小模型对"人物名单"的约束弱 | 第 2 棒明写"人物名单封闭"，第 3 棒复核 |

**关键分工逻辑**：

- **Qwen3.5-9B 赢在「写局」**（结构、因果链、信息操作、角色不跑偏），但细节偏功能描述。
- **Gemma-4-E4B 赢在「写人」**（微表情、肢体、潜台词、生活质感），但会跑偏、会加比喻。
- 于是：**Qwen 搭骨架 → Gemma 填血肉 → Qwen 拆比喻**。两个模型的长处接力，短板互相兜住。

# 二、三棒流水线

```
第1棒  Qwen3.5-9B      素材 + 模板B           → 结构 + 因果四句 + 台词（骨架）
   ↓
第2棒  Gemma-4-E4B     第1棒产出 + 增强指令    → 表演层加厚（血肉）
   ↓
第3棒  Qwen3.5-9B      第2棒产出 + 审校清单    → 清比喻句、复核角色（拆刺）
   ↓
人工终审              —— 只看两处（见 §五）
```

**为什么是 Qwen → Gemma → Qwen 而不是 Qwen → Gemma**：
第 3 棒必须有"干净的手"。Gemma 加的比喻句，只有 Qwen 那种偏功能描述的语感才认得出来是"该拆的散文"；
让 Gemma 自己拆自己的比喻，它会舍不得。

**换模型会怎样**（实测）：

| 组合 | 结果 |
|---|---|
| Qwen → Gemma → Qwen（推荐） | 最佳。比喻句清掉约 80%，但仍有"试图…"式心理推断残留 |
| Qwen → Gemma | 比喻句全留，散文感重 |
| Gemma 单棒 | 细节最好，但必跑偏（换角色/加角色） |
| Qwen 单棒 | 结构最稳，但细节是功能描述，PPT 感明显 |

# 三、可执行脚本

存为 `tools/dual_model_drama.py`（用 Python 3.14 跑，无需第三方包）。

```python
#!/usr/bin/env python3
# 双模型接力编剧流水线
# 用法: python dual_model_drama.py <任务文件> [输出目录]
# 任务文件里第一行写题材与人物设定，之后是素材说明。
# 脚本自动完成: Qwen(结构) -> Gemma(表演增强) -> Qwen(审校)
import subprocess, sys, os, time, re

LMS = os.path.join(os.environ["USERPROFILE"], ".lmstudio", "bin", "lms.exe")
QWEN = "qwen3.5-9b-uncensored-hauhaucs-aggressive"
GEMMA = "google/gemma-4-e4b"
CTX = "8192"

def lms(*args, capture=True):
    r = subprocess.run([LMS, *args], capture_output=capture, text=True,
                       encoding="utf-8", errors="replace")
    return r.stdout if capture else ""

def load(model):
    lms("unload", QWEN); lms("unload", GEMMA)
    time.sleep(2)
    lms("load", model, "--gpu", "max", "--context-length", CTX, "-y")
    for _ in range(40):
        if model.split("/")[-1] in lms("ps"):
            return
        time.sleep(2)
    raise RuntimeError(f"加载超时: {model}")

def chat(model, prompt, outfile):
    load(model)
    txt = lms("chat", model, "-p", prompt, "-y", "--reasoning", "off")
    txt = re.sub(r'\x1b\[[0-9;]*[A-Za-z]', '', txt)
    with open(outfile, "w", encoding="utf-8") as f:
        f.write(txt)
    return txt

STEP1 = """【任务】为一部短剧写第 1 集的第 1 场和第 2 场。
【设定】{SPEC}
【格式】每场按此顺序：场景 N：地点／时间／内外 → 因为： → 所以： → 但是： → 于是： → 戏：（动作与台词交织的段落，台词前标说话人）
【纪律】1. 只写这两场，无大纲无说明 2.「因为」必须是上一场留下的具体事 3.「但是」写清谁挡住主角 4.「于是」成为下一场「因为」 5. 戏是连续段落不是五块并列格子 6. 台词口语化短句，至少一句不推进剧情只暴露人的台词 7. 不写解释性旁白与情绪标签 8. 结尾落在未完成状态 9. 全文 700 字以内
"""

STEP2 = """【任务】下面是短剧初稿，结构与因果链已成立。**只做表演层增强**，不改结构、场次、人物关系、剧情走向。
【初稿】{DRAFT}
【要求】1. 人物名单封闭：只允许出现原初稿中的人，不得新增或替换任何角色 2. 四句因果链一字不改 3. 场号/时间/地点不动 4. 引号里的台词原句保留，只在台词前补表演提示（语气/动作/停顿） 5. 重点加厚：站位、视线、接触、遮挡、受力、微表情、手上动作 6. 台词里不出现镜头参数 7. 不写解释性旁白与情绪标签 8. 全文 900 字以内 9. 只输出增强后剧本本身，无说明文字
"""

STEP3 = """【任务】下面是已做表演层增强的短剧剧本。做最后审校清理。
【待审校文本】{DRAFT}
【审校项】1. 清理比喻式副词：所有"像…一样""仿佛…""像是被…"改为直陈动作或状态。例："眼神像在扫描每一个字符"→"她的目光从条款第一行扫到最后一行"；"像被无形的力量钉住"→"她的手指僵在半空" 2. 删除替观众下结论的解释性括号，改为纯动作描写 3. 人物名单封闭：不得新增或替换角色 4. 引号里的台词一字不改 5. 四句因果链一字不改 6. 场号/时间/地点不动 7. 不写镜头参数 8. 不写情绪标签 9. 结尾仍落在未完成状态 10. 全文 850 字以内 11. 只输出清理后剧本本身，无说明、无改动清单
"""

def main():
    spec_file = sys.argv[1]
    outdir = sys.argv[2] if len(sys.argv) > 2 else "."
    os.makedirs(outdir, exist_ok=True)
    spec = open(spec_file, encoding="utf-8").read()

    print("[1/3] Qwen 出结构…", flush=True)
    s1 = chat(QWEN, STEP1.format(SPEC=spec), f"{outdir}/step1_qwen.txt")

    print("[2/3] Gemma 加厚表演…", flush=True)
    s2 = chat(GEMMA, STEP2.format(DRAFT=s1), f"{outdir}/step2_gemma.txt")

    print("[3/3] Qwen 审校清理…", flush=True)
    s3 = chat(QWEN, STEP3.format(DRAFT=s2), f"{outdir}/step3_qwen.txt")

    final = f"{outdir}/final.txt"
    with open(final, "w", encoding="utf-8") as f:
        f.write(s3)
    print(f"完成 → {final}")
    print("⚠️ 必看：终审两处 = ①『试图…』式心理推断 ② 仍残留的比喻句")

if __name__ == "__main__":
    main()
```

# 四、实测数据（2026-10-25）

任务：《逆袭重生》EP01 第 1–2 场（苏晚重生回到签合同当天 / 郑凯劝签）

| 棒次 | 模型 | 显存 | 速度 | 产出 |
|---|---|---|---|---|
| 第 1 棒 | Qwen3.5-9B | 7430 MiB | 60.5 tok/s | 结构 + 因果四句 + 10 句台词 |
| 第 2 棒 | Gemma-4-E4B | 5324 MiB | 82 tok/s | 表演层加厚约 60% |
| 第 3 棒 | Qwen3.5-9B | 7430 MiB | 60.5 tok/s | 比喻句清掉约 80% |

**三棒合计约 3 次模型加载 + 40 秒生成**。显存始终单模型占用，不叠加。

**第 1 棒的高光**：模型自己把"重生"设定埋进了台词——
苏晚一句"前世……也是这么说的"，把重生事实变成了对手戏里的暗语，
而不是靠旁白交代。这是模板没有明说、模型自发做到的。

**第 2 棒的高光**：加出了可拍的微动作序列——
"她的食指微微蜷曲"（拿到证据）、"手指迅速收拢"（藏起文件）、
"右脚后撤半步，鞋跟压住地毯边缘"（身体先于嘴承认心虚）。

**第 2 棒的副作用**：也加进了散文式比喻（"眼神像在扫描每一个字符"），
这正是第 3 棒存在的理由。

# 五、人工终审清单（只查两处）

第 3 棒仍会漏两类问题，**必须人工过**：

1. **"试图…"式心理推断**
   漏网实例："试图用亲近感压制她的审视""目光试图重新占据主导"
   ——"试图"是把心理活动伪装成动作。改法：直接写他做了什么。
   正确："身体前倾，手臂搭上桌沿"；错误："试图用亲近感压制她的审视"。

2. **残留的比喻句**
   第 3 棒清掉了"像被无形的力量钉住"这类，但漏了
   "眼底那抹不易察觉的冷光一闪而过"（"那抹"是散文词，改"他眼底闪过一丝冷光"）
   与"带着一种不容置疑的笃定"（心理修饰，改"他的食指慢慢扣住合同一角"）。

**判定口诀**：把所有"像/仿佛/似乎/试图/带着一种…的…"圈出来，
凡是不能直接拍出来的，一律改成动作或删掉。

# 六、局限

- 第 3 棒的清理依赖它自己判断"什么算散文"，**不完全可靠**——这就是必须人工终审的原因。
- 换题材后需重测：第 1 棒在"逆袭重生"上自发埋了重生伏笔，
  但这依赖模型对类型的先验，换成甜宠/喜剧未必复现。
- 单集 2 场是当前验证过的规模。**3 场以上**需重新验证——
  因果链在第 3 棒清洗后可能产生新的断裂，链越长风险越大。
- 整集成稿（20–60 集大纲）**不要走这个流水线**——多集结构超出单次上下文承载，
  应先用 Qwen 单跑分集大纲（模板 C），再逐集走本流水线。
