# 图片生产清单

## 〇、一句话

**清单 = 一张表，每行一张图：告诉出图工具"画什么、画多大、参考谁、存成什么名"。** 用户拿到清单，逐行复制提示词去搓图，搓完按文件名归档，审核通过后进视频段。

## 一、清单解决什么问题

| 痛点 | 清单的解法 |
|---|---|
| 图要出哪些，心里没数 | 清单强制"先枚举后出图"：资产图 + 每镜首帧全列出 |
| 提示词临时编、每张都不一样 | 清单统一用同一套八要素组合顺序（景别→机位→构图→动作→场景→光影→色彩→质感） |
| 搓完不知道存哪、叫什么 | 每行有固定文件名，直接对应后续视频段的输入路径 |
| 图与图之间不连贯 | 每行有"引用锁"字段（参考哪张资产/哪张图），搓图时锁死 |
| 没审核就往下走 | 清单自带状态列（待搓/已搓/待审/通过/打回），通过才进下一镜 |

## 二、清单结构（标准列）

| 列 | 说明 | 示例 |
|---|---|---|
| 图号 | 唯一编号，作为文件名与追踪锚点 | A-01 / A-02 / F-01 |
| 类型 | 资产（角色/场景/道具）还是 首帧/尾帧 | 角色资产 |
| 用途 | 这张图具体干什么 | 女主定妆照·正面 |
| 宽高比 | 出图比例（默认横屏 16:9；竖屏短剧 9:16；资产卡可 3:4 或 1:1） | 16:9 |
| 目标尺寸 | 像素级或档位（与视频段一致，见 §四） | 768P 档（16:9） |
| 提示词（中文） | 完整中文提示词，按八要素顺序 | 中近景，平视，三分法… |
| 提示词（英文） | 需要英文模型时用（H3 首帧必填英文） | medium close-up, eye-level… |
| 引用锁 | 必须参考的既有图/资产编号 | 参考 A-01（女主定妆） |
| 输出文件名 | 搓完图保存的文件名（含目录） | 短剧/首帧/SHOT_001.png |
| 状态 | 待搓 / 已搓 / 待审 / 通过 / 打回 | 待搓 |
| 备注 | 审核要点、风险、衔接说明 | 首帧必须与 S02 尾帧衔接 |

> 模板文件：`模板/短剧项目模板/03-分镜/图片生产清单.md`（复制到项目后填写）。

## 三、如何自动生成清单（Agent 动作）

### 第 1 步：枚举资产图

从 `03` 阶段资产卡读出每个角色/场景/道具的"三件套"需求，各列一行：

- 每个角色：按 `03-角色与视觉资产/角色资产参考板.md` 的完整资产包（定妆 / 多视图转身图 / 服装 / 材质 / 表情 / 手持），**依据分镜表该角色会出现的视角、景别、服装、情绪逐行枚举**，不只列一张定妆；一次性/剪影角色按对应文件减量。
- 每个场景：**主场景全景** + **关键局部**（按分镜表需要）。
- 每个道具：**道具独立图**（只在有特写/证据镜头时才需要）。

### 第 2 步：枚举每镜首帧（+ 需要的尾帧）

遍历分镜表的每个生成段：

- 每镜一行**首帧图**，提示词直接来自分镜表该镜的"景别/机位/构图/主体动作/场景/光影"列——**不要重新创作**，只是把分镜语言翻译成出图语言。
- 只有当分镜表明确"本镜尾帧是下一镜衔接关键"时，才额外列**尾帧行**（默认不列，减少出图量）。
- 引用锁 = 该镜涉及的角色资产号 + 场景资产号。

### 第 3 步：统一写提示词（八要素顺序）

每张图的提示词按固定顺序组装（权重即顺序），要素不全就从 `影视视听语言速查.md` 对应小节补默认值：

```
①景别（离多远）→ ②机位/视角（从哪看）→ ③构图（怎么摆）
→ ④人物动作/表情/表演（在做什么）→ ⑤场景（在哪）
→ ⑥画面内动态（环境里什么在动）→ ⑦光影（怎么亮）→ ⑧色彩（什么调）→ ⑨质感/风格（什么质）
```

**规则**：
- 一镜一构图法则、一主一辅两色、光源必须具名（详见速查文件）。
- 资产图提示词**不写**动作与情绪（那是表演变量，留给分镜）；只写身份特征 + 场景 + 光影 + 质感。
- 首帧图提示词 = 资产身份（引用锁）+ 该镜的动作/情绪 + 场景 + 光影。
- 中文提示词为默认；凡是给 H3 用的首帧，**必须附英文版**（H3 只吃英文）。

### 第 4 步：给文件名与状态

- 文件名规范对齐 `AGENTS.md` 产物规范：`短剧/资产/<角色ID>_<用途>.png`、`短剧/首帧/SHOT_<镜号>.png`。
- 所有行初始状态 = **待搓**；逐张搓完标"已搓"→ 用户审核标"通过/打回"。

### 第 5 步：输出与审核

把清单交给用户（或贴到项目 `03-分镜/` 下）。**用户先审清单本身**（图齐不齐、提示词对不对味），通过后用户才动手搓图。搓完的图回到清单逐行审核，全部"通过"才允许进入视频段。

## 四、执行层的衔接（能力描述）

> 体系只描述**能力与契约**，不绑定任何具体出图工具或工作流。执行层的具体对接（用哪个工具、哪个工作流、怎么批量填参）由 Agent 按项目《能力登记.md》运行时落地，且只登记在执行层文档，不写进本体系。

- **出图能力**：需要"文生图/图生图能力，输入提示词 + 宽高比 + 输出文件名，产出图片文件"——具体实现查《能力登记.md》。
- **文件名契约**：清单"输出文件名"是体系侧契约，执行层必须原样使用（保证搓完的图能被后续视频段按名读取）。
- **比例一致铁律**：清单"目标尺寸"必须与后续视频段的分辨率档位一致（默认横屏 16:9 768P 档；竖屏短剧为 9:16 720P 档），否则首帧进视频会被裁切变形。这是体系侧约定，各执行层必须遵守。

## 五、审核闸门

| 节点 | 谁审 | 通过标准 |
|---|---|---|
| 清单本身 | 用户 | 图齐、提示词对味、文件名与后续路径一致 |
| 单张图 | 用户 | 无一眼假、符合该行提示词、与引用锁资产一致 |
| 全部图 | 用户 | 角色/场景/道具全部冻结，首帧逐镜通过（对齐 G2/G3 关卡） |

> 注意：模型生成的首帧/尾帧只能作为衔接参考，**不得直接作为下一镜首帧**（体系铁律，见 `AGENTS.md` 与 `跨镜连续性与帧链法.md`）。
