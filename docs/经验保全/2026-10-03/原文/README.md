# 短剧成片体系

一套面向通用 Agent 的短剧、漫剧与剧情型短片生产 skill。它负责把需求推进到可审核、可续跑、可复现的成片项目；不绑定具体模型、平台或本机路径。

> **命令速查** → `命令速查.md`（想干什么 → 敲哪条命令 → 什么时候跑）
> 改完代码必跑：`python tools/run_all_checks.py`（16 道闸）

默认执行见`07-端到端管线/生产证据与片型路线.md`：先看少量seek参考，明确整片线索，按顺序制作，检查并修具体问题；无哈希审批、无固定片型限制。其他专项文件的关卡签核措辞只适用于用户选择阶段审核模式。

## 渐进式入口

日常只需先读本 README 与 `SKILL.md`；要做全流程再读 `从这里开始.md`、`AGENTS.md` 和 `07-端到端管线/生产证据与片型路线.md`；只做单点任务，直接读对应阶段文档。根目录其他文件是运行辅助、事实登记或历史资料，不是默认上下文。已完成的会话 TODO 记录归档于`archive/`，不参与日常加载。

## 从哪里开始

1. Agent 先读 `SKILL.md` 与 `skill-manifest.json`。
2. 端到端任务再读 `从这里开始.md`、`AGENTS.md`、`通用Agent短剧生产规范.md`。
3. 续跑项目优先读项目内的《项目状态摘要.md》《执行清单.md》和当前审核包。
4. 单点任务只加载对应阶段文档，不必通读全库。

> `01–07` 是知识库分类，不是生产顺序。端到端项目始终按 G0–G6；先在 G2 锁定视觉资产，再在 G3 完成最终分镜。

## 两种使用方式

| 任务 | 路线 |
|---|---|
| 从想法做到成片 | 全权委托按简明流程自主制作和检查；用户要求阶段审核时才等待裁决 |
| 只写剧本、分镜、角色、镜头、音频或后期 | 从 `从这里开始.md` 的单点路由直达对应文档 |
| 中断后继续 | 读取项目状态摘要，只恢复当前关卡所需上下文 |

## G0–G6 生产关卡

| 关卡 | 核心产物 | 冻结点 |
|---|---|---|
| G0 立项对标 + 风格立项 | 对标拆解表、回本测算、产能模式、风格提案 | 方向确认 |
| G1 剧本 | 大纲、剧本、钩子与合规审查 | 故事确认 |
| G2 视觉资产 | 角色卡、场景卡、道具卡、锚句表 | 资产冻结 |
| G3 分镜与首帧 | 分镜表、状态交接、首帧审核包 | 分镜冻结 |
| G4 逐镜生成 | 生成段、镜头审核包、重抽日志 | 镜头逐批通过 |
| G5 音频 | 配音、音效、BGM 审核包 | 音频确认 |
| G6 成片交付 + 首集验证 | 剪辑装配单、字幕、成片、质检、复盘、首集验证结论 | 终版交付 |

用户裁决统一使用：**通过 / 修改（指出项） / 暂停**。冻结后的方向性变更必须先说明代价并登记。

## 目录

- `01-创意与剧本/`：选题、立项对标、结构、剧本与合规
- `02-分镜与镜头/`：分镜、镜头语言、视听语言速查（景别/机位/构图/光影/色彩/场景/声音字典）、图片生产清单（资产+首帧的可执行出图清单）、连续性、文戏对白节奏与状态交接
- `03-角色与视觉资产/`：角色、场景、道具、写实人像与对白微表演、3D 漫剧与跨镜一致性规则
- `04-视频生成/`：生成段设计与按能力适配的提示词方法、重抽与回退决策手册
- `05-音频/`：配音、音效、BGM 与音画同步、音频生产清单
- `06-后期与发布/`：剪辑装配单生成器、时间线装配、字幕、多语言版本、质检、发布包、首集验证与止损
- `07-端到端管线/`：真人短剧与小说漫剧总控路线
- `模板/短剧项目模板/`：新项目可复制的完整目录
- `tools/`：15 道验收闸（`run_all_checks.py` 一条命令跑完）
- `对标参考库/提示词库/`：全链路自动化脚本（`run_all.py` 出 5 份材料 + `review_gate.py` 签核）+ `lib_locator.py` 素材库定位器
- `seek库/`：**素材库**（采集脚本 + 1234 张封面 + 59747 条提示词 + 技法检索表）。2026-10 并入本项目，生产侧直接读这一份，不再有副本
- 根目录 `新会话启动卡.md`：新会话/断点续跑的唯一入口（三步接续 + 一句话模板 + 关键路径清单）

## 素材与生产的关系

```
seek库/                      ← 素材：采集脚本 + 库数据
   ↓ lib_locator.py 定位（环境变量 → 项目内 → 同级目录）
对标参考库/提示词库/          ← 生产：选卡→剧情→脚本→分镜→技巧→清单
```

- **只有一份素材**。并入前 `对标参考库/提示词库/` 下有一份 4.31GB 副本，已删除。
- 采集只写 `seek库/`，生产只读 `seek库/`，**互不反向写**。
- 要把素材库挪到别的盘：设 `AI_SEEK_ROOT`，不用改任何代码。
- 想知道它现在解析到哪：`python 对标参考库/提示词库/lib_locator.py`


## 核心纪律

- 能力与实现分离：运行时发现实现，登记事实，不把工具写死为体系前提。
- 用户只做方向审核；格式转换、参数、排队与普通重试由 Agent 处理。
- 生成段不等于剪辑镜头；通过稳定 ID 和剪辑装配单关联。
- 上一段尾帧只能作为衔接参考；进入下一段前必须审核，必要时修复成新的首帧资产。
- 所有通过版本、用户裁决、成本、授权与失败原因都落到项目目录。

## 校验

**最常用的一条命令**（改完代码跑这个就够）：

```powershell
python tools/run_all_checks.py
python tools/run_all_checks.py --quick   # 跳过最慢的边界测试
```

它依次跑 16 道闸，任何一闸失败即退出码 1：

| # | 闸 | 查什么 |
|---|---|---|
| 1 | 结构校验 | frontmatter / 外链 / 绝对路径 / 断链引用 |
| 2 | 数字一致 | 文档写的数量 == 磁盘实况 |
| 3 | 体系可移植 | 清空 `AI_*` 后 skill 仍能跑 |
| 4 | 素材库可移植 | 清空 `AI_*` 后采集工具仍能用 |
| 5 | 流水线边界 | 极端参数 / 特殊字符 / 非法输入不崩 |
| 6 | 样例新鲜度 | `示例/` 里的成品与当前代码一致 |
| 7 | 闸的自检 | 独立复算磁盘，不信子进程自述 |
| 8 | 搬家验证 | 整个项目复制到临时位置后仍完整 |
| 9 | 闸完整性 | 检查器没被改坏/被删 + 素材无残留外链 |
| 10 | 语料质量 | 36 镜抽样，提示词真能喂给出图模型 |
| 11 | 安全性能 | XSS / 路径穿越 / 非法协议；耗时与体积 |
| 12 | 素材对齐 | 封面与候选表匹配（双侧），孤儿 < 1% |
| 13 | 未提交提醒 | 有没有该提交却没提交的改动（**只提醒不失败**）|
| 14 | 闸集合完备性 | 关键维度**有没有闸漏掉**（声明式，改代码时自动核对）|
| 15 | 产物自洽 | 四份材料的镜头/时长/时间线/ID/景别互相对得上 |
| 16 | 切点均质度 | 刀长**有长有短**吗（std<0.2s 判为节拍器）+ 提示词里有没有生成内多刀 |

> **跳过不算通过**——有闸被跳过时会明确报「⚠ 有闸被跳过，不算全绿」，
> 避免出现「报 5/5 但实际只跑了 4 项」的假绿。

单独跑某一项：

```powershell
python tools/validate_system.py      # 结构
powershell -ExecutionPolicy Bypass -File tools/validate_system.ps1
```

**素材增长后还要跑一次数字一致性检查**——素材库会持续变大，文档里手写的
「N 条提示词 / N 张封面 / N 条成片」会悄悄过期（历史上曾漂移 25 处）：

```powershell
python tools/check_doc_numbers.py           # 检查，不一致则退出码 1
python tools/check_doc_numbers.py --fix     # 自动按磁盘实况修正
```

它以磁盘为唯一真值，覆盖提示词条数/作品数、封面张数、成片条数、静帧张数五类。

**可移植性自检**——验证「拿到哪台机器都能用」不是口号：

```powershell
python tools/selfcheck_system.py            # 体系侧（生产体系 + 自动化 skill）
```

它会**清空所有 `AI_*` 环境变量**再跑一遍，断言 8 件事：素材库在位、核心脚本齐备、
零厂商语法、零硬编码盘符、`run_all` 仍出全套材料、产物零占位符、整项目无库可降级、
未签核时门禁真拦。

> 配套：素材库侧有 `harvest/selfcheck_portable.py`，同思路查采集工具。
>
> **为什么这样测**：曾经给 `covers_dir()` 加了跨项目探测，看起来解决了重复下载，
> 但只有设了环境变量才有效——清空后指向空目录，下载器会从零重下 1800 张。
> 测试时环境变量是我自己设的，所以没发现。**能跑 ≠ 可移植，测试环境本身就是设计的一部分。**

外部源档案核验必须显式传入根目录，项目本身不保存绝对路径：

```powershell
python tools/check_source_archive.py --root "<源档案目录>"
```
