# 通用 Agent 短剧生产规范

> 本文件是 `SKILL.md` 的执行补充。它只描述能力、输入、输出、约束和决策方式，不规定具体实现。具体实现必须在项目的《能力登记.md》中登记。

## 当前执行优先规则

用户全权委托时采用`07-端到端管线/生产证据与片型路线.md`简明流程；下文候选等待、审核包、冻结解冻手续仅用于用户明确要求阶段审核的模式。默认自主定方案和修具体问题，不要求哈希批准或额外审批。剧情专用字段按实际作品需要取用，不强加给展示、广告、音乐影像等任务。

## 1. 总体目标

把用户的想法或剧本，逐步推进为可审核、可复现、可剪辑、可交付的短剧成片。Agent 负责拆解、执行、记录、回退和交接；人类主要负责方向、审美、预算、合规和不可逆决策。

生产链不是“一次性生成”，而是：

```text
需求理解 → 方案候选 → 关卡确认 → 资产锁定 → 弹性拆镜 → 首尾状态交接
→ 逐镜执行 → 质量归因 → 音频与后期 → 成片质检 → 复盘反哺
```

## 1.1 生产模式分级（G0 立项时选定）

同一套能力层，跑两种生产节奏。模式在 G0 立项时选定并写入《立项决策表》，影响后续所有环节的审核密度与交付粒度。

| 维度 | 精品单集模式 | 量产连载模式 |
|---|---|---|
| 适用 | 单集 3-8 分钟，重质不重量；广告/精品剧 | 连载漫剧/短剧，日更或高频更新，几十到数百集 |
| 关卡审核 | 每关标准审核包，逐镜审核 | 只审 G0 立项、首集剧本与资产、里程碑集（每 5-10 集），中间集按冻结资产自动推进 |
| 分镜 | 逐镜人工过审 | 首集分镜人工过审，后续集按冻结的分镜模板与资产批量展开，只抽查 |
| 质量回退 | 单镜最多 2 次重抽后走回退链 | 单镜同样遵守回退链，但批量任务不因单镜卡死整批；废镜先标记，批次末统一重出 |
| 首集验证 | 可选 | **必做**：首发集 24h/72h 数据达标后才放行批量生产（见 `06-后期与发布/首集验证与止损.md`） |
| 成本纪律 | 单集成本上限由立项回本测算决定 | 单集成本上限按量产目标倒推，超支镜头优先降规格而非加重抽 |

**模式切换**：量产中途发现单集质量下滑，先暂停放量、回质量归因（见 §9），而不是继续灌水；精品模式中途若用户要求提速，需先评估资产与分镜冻结范围是否支持，不支持则按候选决策协议给方案。

**统一底线**：无论哪种模式，身份锚定铁律、链长限制、两级验收、语法不串台、能力登记五条铁律不变——量产只是把“逐镜人工审核”替换为“里程碑审核 + 资产冻结约束下的自动执行”，不是放松质量闸门。

## 2. 不确定性与候选项协议

### 2.1 先判断不确定性类型

| 类型 | Agent 行为 | 是否必须问人 |
|---|---|---|
| 执行细节不确定 | 采用稳妥默认值并记录 | 否 |
| 有多个同等可行方案 | 给出 2–4 个候选项，标出推荐项 | 通常是 |
| 风格、叙事、预算、合规取舍 | 给候选项并等待决策 | 是 |
| 高成本或不可逆变更 | 先给影响范围和回退代价 | 是 |
| 普通信息缺失且不影响执行 | 做保守设计，保持本阶段统一 | 否 |
| 输入互相矛盾或剧情无法成立 | 给最小修正版 + 说明冲突 | 是，不能默默改方向 |

### 2.2 候选项格式

每次需要决策时最多给 2–4 个候选项，使用以下格式：

```markdown
## 需要决策：{事项}

### A · {方案名}（推荐）
- 效果：
- 代价：
- 风险：
- 可逆性：高 / 中 / 低

### B · {方案名}
- 效果：
- 代价：
- 风险：
- 可逆性：高 / 中 / 低

### 当前建议
推荐：A
原因：
请回复：选择 A / 选择 B / 修改方向 / 暂停
```

不能把技术名词当成候选项名称。先描述用户能感知的效果、速度、价格、稳定性和返工代价；实现名称只登记在项目能力表中。

### 2.3 默认选择规则

如果用户授权 Agent 自主决定：

1. 优先选择可复现、可回退、风险较低的方案；
2. 优先保证剧情成立、人物身份、空间连续和声音理解；
3. 其次才优化电影感、复杂运动和生成效率；
4. 在项目《用户裁决日志.md》中记录 Agent 选择的理由；
5. 用户之后要求改变方向时，按当前关卡的冻结规则处理，不偷偷覆盖旧产物。

## 3. 渐进式加载协议

### 3.1 加载层级

| 层级 | 默认读取内容 | 进入条件 |
|---|---|---|
| L0 识别 | `SKILL.md`、`skill-manifest.json` | 每次收到需求 |
| L1 路由 | `从这里开始.md`；端到端再加 `AGENTS.md` 和本文件 | 判断为本体系任务 |
| L2 当前关卡 | 当前 G0–G6 需要的阶段文档 + 项目状态摘要 | 已确定任务和关卡 |
| L3 专项能力 | 角色、场景、运镜、音频、后期等专项文档 | 当前产物确实需要 |
| L4 证据与复盘 | 案例、历史资料、失败日志、参考附录 | 需要查证、对比或解决失败 |

### 3.2 加载纪律

- 不要因为目录存在就读取整个目录。
- 每次只打开完成当前动作所需的最小文件集合。
- 读完专项文档后，提炼结论写入当前项目产物，不要求下次重新加载原文。
- 断点续跑优先读取《项目状态摘要.md》、当前关卡审核包和执行清单。
- 如果上下文快满，先写状态摘要，再结束本轮；下一轮从摘要恢复。
- 原始参考资料只作为 L4 证据，不作为每次生产的默认输入。

### 3.3 推荐读取顺序

```text
SKILL.md
→ skill-manifest.json
→ 从这里开始.md
→ AGENTS.md（端到端任务）
→ 项目状态摘要.md
→ 当前关卡模板
→ 当前关卡专项文档
→ 必要时才查历史资料和案例
```

## 4. 阶段交接的最小接口

每个阶段必须明确：

```text
输入：当前阶段真正需要的文件和决策
动作：Agent 在本阶段做什么
输出：可被下一阶段直接读取的产物
审核：用户需要看什么
通过：什么条件成立才继续
回退：失败时回到哪里
```

阶段输出不能只存在聊天记录中。重要决定、通过版本、失败原因和用户意见都要写入项目目录。

## 5. 资产先锁定，再拆镜

### 5.1 资产范围

进入分镜前，至少锁定：

- 主要角色身份特征、服装、配饰和体态；
- 主要场景的固定空间、机位、时间、天气和主光；
- 关键道具的外形、材质、文字、尺寸关系和状态变化；
- 全片或本场的色彩、颗粒、景深和画面质感；
- 资产 ID、版本和使用范围。

### 5.2 冻结规则

G2 通过后，角色、场景、道具和锚句进入冻结状态。后续只允许：

- 在明确的变量区改变表演、动作和机位；
- 通过升版本的变更记录修改资产；
- 发生重度漂移时回到 G2，而不是逐镜继续打补丁。

## 6. 弹性拆镜：镜头数量服从理解和剪辑

### 6.1 两种单位必须分开

- **真实剪辑镜头**：最终剪辑中观众看到的一次镜头切换。
- **视频生成段**：一次提交给某种生成能力的连续视频片段，可以承载一个或多个连续的真实剪辑镜头。

二者不必一一对应。不要因为某能力支持某个时长，就强行把剧情填满；也不要为了所谓稳定性把一个完整动作切成无法表演的碎片。

### 6.2 何时切镜

当以下任一项发生明显变化时，优先评估切镜：

- 观众必须理解的主要信息；
- 观看主体或主次关系；
- 人物情绪或表演阶段；
- 动作目标或动作结果；
- 空间方向、轴线或站位；
- 道具状态；
- 声音理解重点；
- 剪辑节奏或反应落点。

如果多个动作共同服务同一个结果、观看重点没有改变，可以合镜。任何镜头都必须有功能：推进事件、传递信息、放大情绪、展示反应、完成结果、制造期待或为下一镜建立因果。

### 6.3 每镜最小字段

| 字段 | 说明 |
|---|---|
| 镜头功能 | 这一镜删掉后会损失什么 |
| 观看重点 | 观众此刻首先看谁/什么 |
| 起始状态 | 人物、空间、道具、声音在镜头开始时的状态 |
| 主要动作 | 一个主要动作目标，不堆多个同等重点 |
| 结果状态 | 动作完成后发生了什么 |
| 机位与景别 | 为什么用这个画面承载信息 |
| 声音 | 台词、环境声、音效或静默 |
| 首帧/尾帧 | 画面锚点和交接依据 |
| 资产版本 | 角色、场景、道具、色调锚的版本 |

## 7. 首尾状态交接

### 7.1 状态快照

每个视频生成段都要有可验证的首状态和尾状态：

```markdown
## 首状态
- 人物：位置、姿态、朝向、视线、手部和表情
- 空间：机位、轴线、前后景、主光方向
- 道具：持有者、位置、朝向、开合/破损等状态
- 声音：正在说什么、环境声、是否有音乐

## 尾状态
- 人物：动作停在哪个可复现阶段
- 空间：镜头位置、人物相对方向和光线
- 道具：动作结果后的状态
- 声音：台词是否结束、声音是否需要延续
```

### 7.2 交接规则

- 下一段首状态必须能从上一段尾状态复现；
- 不用“延续上一镜”“保持一致”替代具体状态；
- 姿态、朝向、视线和道具状态不能靠段间跳切无说明地重置；
- 末帧可以作为衔接参考，但下一段首帧仍需经过人工或审核闸门；
- 每 3–5 个镜头或一次场景/主光变化后重新回到已审核资产锚定；
- 允许越轴、跳时空或状态跳变时，必须写明叙事理由。

## 8. 分镜转执行提示词

已经通过的分镜进入执行层后，Agent 不得重新导演。只做必要的翻译和参数适配：

1. 保留镜头功能、主体、动作目标和结果；
2. 将抽象情绪翻译成可见动作、表情、视线和环境反应；
3. 逐字继承冻结的角色、场景、道具和色调锚；
4. 明确镜头运动、光影、声音和时长边界；
5. 将不可生成或有风险的部分标记为问题，不私自改变剧情；
6. 输出的提示词和资产版本一一对应，并保存通过原文。

## 9. 质量归因与回退

失败后先归因，再决定是否重抽：

| 现象 | 优先怀疑 | 首选处理 |
|---|---|---|
| 换脸、发型或服装漂移 | 资产锚/参考图/版本 | 回到资产锚，重做当前镜头 |
| 空间或人物左右关系错 | 状态快照/轴线/机位 | 修正交接表，重出当前段 |
| 动作变形或结果不清 | 动作目标过多/复杂度过高 | 拆动作、降低复杂度或换方案 |
| 画面好看但剧情看不懂 | 镜头功能或观看重点不清 | 回 G3 重做分镜，不继续抽卡 |
| 声音对不上动作 | 台词时长/表演节奏/音频交接 | 回 G5 调整声音或镜头时长 |
| 合规或授权风险 | 内容/素材来源 | 改写或更换素材，不重复提交 |

默认遵循 `AGENTS.md` 的质量重抽与回退链；任何 E 级换方案都要交用户决策。

## 10. 交付前最小自检

- [ ] 每镜都能说明镜头功能和观看重点；
- [ ] 每个生成段有首状态、尾状态和资产版本；
- [ ] 角色、场景、道具和色调没有跨版本混用；
- [ ] 重要信息已视觉化，不只依赖解释性台词；
- [ ] 台词后有必要的可见反应，但没有机械逐句切反应；
- [ ] 动作有开始、过程和结果，没有用段间跳切掩盖缺失；
- [ ] 用户裁决、变更、失败和通过提示词已落盘。
