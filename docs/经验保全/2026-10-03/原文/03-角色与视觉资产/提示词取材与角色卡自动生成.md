# 提示词取材与角色卡自动生成

## 〇、一句话

**角色卡的价值在于"锁死"，不在于"写得好"。所以取材的正确姿势是：从大量对标里提取"这个题材的角色通常由哪几个维度定义"，然后用本剧的人设把这些维度填满——而不是抄一段别人的提示词。**

---

## 一、合规底线（先读，不然后面白做）

| 允许 | 禁止 |
|---|---|
| 研究别人**用了哪些维度**（"敦煌风角色通常靠：头光形状 + 飘带走向 + 矿物色层"） | 把别人的**提示词原文**整段抄进自己的资产文件 |
| 统计别人**的参数配置**（分辨率、出图张数、比例） | 搬运别人的**成图**进本项目资产库 |
| 从公开教程里**读方法**（怎么写运镜、怎么定光比） | 把别人的**角色设计**改几个字当自己的原创 |
| 记录**数据来源与授权状态**到《素材与授权台账.md》 | 不登记来源就用 |

**一句话原则**：**学维度，填自己的料，登记来源。**

> 体系已有《素材与授权台账.md》与《能力登记.md》的"授权/商用状态"列——任何外部取材都必须在台账里留一行，否则项目复盘时说不清资产从哪来。

## 二、提示词取材的三条路

### 路线 A · 公开社区对标（主力）

国内 AI 绘图社区的作品页通常公开展示提示词与参数，是最直接的取材场。

| 平台 | 特点 | 适合取什么 |
|---|---|---|
| **哩布哩布 LiblibAI**（`liblib.art`） | 国内最大的 AI 绘图社区，作品页带提示词与参数，**国风/敦煌/水墨/古风题材最全** | 国风角色、场景、配色方案 |
| **吐司 TusiArt**（`tusiart.com`） | 国内社区，风格标签细 | 风格参考、构图参考 |
| **即梦 / 可灵的作品广场** | 偏视频 | 动态质感、运镜感觉 |

**取材方法（不写脚本，手工即可）**：

1. 搜题材关键词（如"敦煌""志怪""古风道士""非遗刺绣"）；
2. 按**点赞/收藏**排序，只看头部作品——头部说明这个提示词被验证过；
3. **只记结构不抄字**：把提示词拆成维度，记"这条提示词里出现了哪几个维度、按什么顺序"；
4. 记下让你觉得"对了就是这个调子"的那几张的**图**，作为**对标图**（不作为资产）。

**产出物**：《对标提示词维度表》——见 §三。

> **访问说明**：这两个站国内直连可达，不需要代理。作品详情页的提示词字段需要登录才能完整查看（未登录通常只显示截断版）。**是否提供登录态由用户决定，见 §六。**

### 路线 B · 教程视频里读屏幕提示词（补充）

大量 AI 绘画/分镜教程会把完整提示词打在屏幕上。这条路的独特价值是：**提示词和"怎么用它的讲解"同时出现**，比干看一串词有用得多。

**操作方法**：
1. 找到相关教程（题材 + "提示词"或"工作流"）；
2. **按固定间隔抽帧**（例如每 5 秒一帧），拼成时间轴接触表；
3. 逐帧读，把屏幕上出现过的提示词原样记下；
4. 记录该提示词**出现在教程的哪个环节**（是定稿用的？还是初稿用的？参数有没有调过？）。

**为什么这条对体系有用**：教程作者会明说"这个提示词是初稿，正式出图前要把它拆成三段"——这类**加工方法**比提示词本身更值钱。

> 本体系已采集过一批此类素材（见 §六），可直接翻阅，不必重复劳动。

### 路线 C · 结构化词表（不依赖外部）

`02-分镜与镜头/影视视听语言速查.md` 已经是体系内的结构化词表。**角色卡取材时先查自己的词表**，缺什么再外部找——这样大部分情况根本不需要外部取材。

## 三、从对标反推角色卡字段

这是本文件的核心方法。

### 3.1 为什么不能抄提示词

别人的提示词是为**他的角色**写的，字段混着三样东西：
- **身份字段**（长什么样）——这才是角色卡要的；
- **场景字段**（在哪、什么光）——这属于场景卡；
- **画面字段**（景别、角度、质感）——这属于分镜表。

整段抄过来，三样混在一起，**没法锁**。所以必须拆。

### 3.2 拆解流程

拿 5–10 条同题材的高赞对标提示词，逐条拆：

| 拆出来的维度 | 归到哪 | 角色卡里的字段 |
|---|---|---|
| 脸型/骨相/年龄感 | 身份 | 年龄感/骨相 |
| 发型轮廓、发际线 | 身份 | 发型/发色 |
| 眼型眼距、眉形 | 身份 | 眼睛/眉形 |
| 身高体态比例 | 身份 | 体态/身高关系 |
| 服装版型、主色 | 身份 | 固定服装 |
| 饰品、纹样、器物 | 身份 | 固定配饰 |
| 标志色（这个角色专属的颜色） | 身份 | 色彩归属 |
| 背景环境 | **场景** | → 场景卡，不进角色卡 |
| 光线、色调 | **视觉圣经** | → 色彩脚本/照明卡 |
| 景别、机位、画幅 | **分镜** | → 分镜表 |

**统计这一步的价值**：统计 10 条提示词里"敦煌风角色"最高频出现的 5 个维度，那就是这个题材的**通用维度集**。**你自己角色的特征，就从这 5 个维度里选 3 个做主、2 个做辅**——这比凭空捏脸准得多，也比抄别人的有原创性。

### 3.3 主辅关系

`人物定妆设计.md` 已经确立了"**锁一个主记忆点，其余五官做陪衬**"的原则。取材时把这个原则放大：

- 从对标里统计出该题材的**常见主记忆点**（敦煌风多是"头光形状"与"飘带"；神怪多是"眼睛/额饰"；市井多是"身形与衣着层次"）；
- 本角色的主记忆点，**要么选该题材的常见项**（观众一眼认得出是这类），**要么明确反着来**（产生辨识度）；
- **不允许**落在"既不常见、也不反差"的中间地带——那是"没记忆点"。

## 四、角色卡自动生成流程

### 4.1 触发条件

满足**任意一条**时启动本流程：
- 用户要新建角色，但只给了"一个会武功的道士"这类粗略人设；
- 用户说"角色卡怎么自动生成"；
- 已有对标素材，需要把维度落成字段。

### 4.2 执行步骤

**第 0 步 · 补齐人设缺口**
按 `人物定妆设计.md` 的"用户输入信息"七项检查：年龄感、性别、气场、身份、画面类型、背景诉求、风格诉求。缺的**按选项问用户**，不要自行发挥（体系铁律：有矛盾就提出来，别自己拍脑袋）。

**第 1 步 · 取对标维度**
按 §三 拆 5–10 条对标（若用户未提供，执行方去 §二 取材，或直接查体系内词表）。
产出：《对标维度表》——题材通用维度集 + 高频项排序。

**第 2 步 · 选主辅**
从通用维度集里定 **1 个主记忆点 + 2–3 个辅维度**，写明选择理由（"选头光形状为主，因为本片是敦煌题材，观众预期在此"）。
**主辅选择必须让用户确认**——这是创作决策，不是执行细节。

**第 3 步 · 落字段**
把选定维度填进 `模板/短剧项目模板/02-资产/角色/角色卡.md` 的对应字段。每个字段写成**可直接嵌进提示词**的表述（对齐 `人物定妆设计.md` 的"给出结论时要写成能直接嵌进提示词的表述"）。

**第 4 步 · 生成身份合同**
按 `多镜头角色一致性.md` 的"身份合同"格式，把角色卡里的不可变项转成**锚句**（可跨镜头复用的定长字符串），登记进《锚句表.md》。

**第 5 步 · 出三件套**
按 `人物定妆设计.md` 出定妆照/肖像特写/三视图，走 `02-分镜与镜头/图片生产清单.md`。
**出图策略用 `02-分镜与镜头/分镜故事板与批量出图.md` 的并行候选**（同提示词换 seed，出 3 张选 1）。

**第 6 步 · 过检与冻结**
走角色卡自带的 G2 审核项。通过后状态置「冻结」，进入 G3。

### 4.3 自动化边界

| 可自动 | 必须用户裁决 |
|---|---|
| 维度统计与排序 | 主记忆点选哪个 |
| 字段填充的技术性表述 | 角色身份的整体方向 |
| 锚句生成 | 是否冻结（G2 关卡不可逆） |
| 三件套出图与候选筛选 | 成图是否达到"过检"水准 |

**G2 之后角色冻结**（`AGENTS.md` 关卡不可逆规则）——自动生成流程可以一路跑到"待审"，**不能自己按下冻结**。

1. **分镜句式**：`镜头NN 【景别】+【构图】+【光线】+【人物表情动作】+【场景互动】+【台词】+【饰品】+【转场】`

3. **八要素法**：`谁 在哪里 什么时间 做什么 ＋ 景别 机位 视觉风格`
