# 短剧成片体系 · SKILL（通用 Agent 总入口）

> 一套"从想法平推到底成片"的 AI 短片工作流。任何 Agent 拿到本文件，应当能够不看作者解释，直接识别体系结构、路由到正确文档、把流程一段一段串起来执行。
> **范围说明**：当前 G0–G6 完整闭环以横屏 16:9 剧情短剧、电影感短片、漫剧和剧情型短片为核心（**画幅默认横屏 16:9，竖屏 9:16 仅作竖屏平台备选**）；广告、MV、口播、纯视觉概念片可使用对应单点模块，但在没有专用路线模板前，不自动假设它们拥有同等的端到端默认参数。
> 本文件只做**路由与串联协议**，具体方法论在 01–07 各阶段文件里，不要在本文件里重复造轮子。

## 一、体系是什么

按**流水线阶段**编号（不按素材类型）：

```
01–07 是知识库目录：创意/剧本、分镜/镜头、角色/视觉资产、视频生成、音频、后期发布、端到端总控；实际端到端生产顺序以 G0–G6 关卡为准。
```

根目录配套文件：

| 文件 | 角色 |
|---|---|
| `SKILL.md`（本文件） | 通用 Agent 识别与串联入口 |
| `从这里开始.md` | 需求路由：开工五问、全流程路线图、单点直达表 |
| `导演视觉圣经.md` | 大片感总控：三张风格基线卡、色彩脚本、照明、焦段语法 |
| `AGENTS.md` | 端到端自动模式：能力动态获取（不绑定工具）、G0–G6 关卡制、失败回退链、产物规范 |
| `README.md` | 体系总览、G0–G6 路由、校验方式 |
| `知识库维护清单.md` | 版本敏感内容、来源类型和复核周期 |
| `01-创意与剧本/AI短片全链路流水线.md` | **自动化主控**：题材 → 选卡/剧情/脚本/分镜/技巧/清单一条命令出，人只审 5 个节点 |

## 二、Agent 串联协议（拿到需求后怎么做）

**第 0 步 · 识别模式**
- 用户需求是"一句话想法 / 帮我做一部片" → 端到端模式：先读 `AGENTS.md` 建立关卡计划，再按 `从这里开始.md` 开工五问补全关键决策。
- 用户需求是单点任务（"写个分镜""配个 BGM"）→ 单点模式：查 `从这里开始.md` 的单点直达表，打开对应文件只做这一件事，不要拉着用户走全流程。
- 用户给了题材、想要**一次拿到完整制作包**（剧情+脚本+分镜+清单，不想逐阶段被问）→ 走 `01-创意与剧本/AI短片全链路流水线.md`，一条命令产出六件套，人只在末尾 5 个审核节点签字。

**第 1 步 · 逐阶段执行**
每个阶段：读当前需要的方法 → 制作实际产物 → 检查结果 → 修具体问题或继续。用户全权委托时Agent自主推进；用户明确要求阶段审核时才提交并等待裁决。执行方式以简明流程为准，不被专项文档的旧签核措辞阻塞。

**第 2 步 · 跨阶段交接**
- 上游产物是下游的输入，命名与目录规范以 `AGENTS.md` 的产物规范为准。G0–G6 是生产关卡，01–07 只是查找知识的目录编号；G2 资产锁定后才进入 G3 最终分镜与首帧。
- 每个阶段开工前先读本文件顶部的「体系定位」块（写明上游、下游、配套文件），断点处知道翻哪本。
- 用户已拍板的事项（风格基线、平台、画幅、工具链）记入任务清单，后续阶段不得漂移。

**第 3 步 · 出问题时**
按 `从这里开始.md` 末尾"出问题时的处理顺序"：一致性→语法→合规→问用户。拿不准就停下来问，不要猜。

## 三、生产铁律（实战踩坑换来的，任何阶段不得违反）

1. **身份锚定铁律**：每个视频镜头的首帧必须来自**人工过目过的资产**（定妆图 / 过检关键帧 / 图生图修正帧）。模型生成的末帧只能作为下一镜的**衔接参考**（构图、光线、位置），**不得直接作为下一镜的首帧**——链式直传必然导致换演员/换机体。
2. **链长限制**：如采用帧链衔接法，每 **3–5 镜**必须强制回到人工资产重新锚定一次，把漂移锁死在观众无感的长度内。
3. **两级验收**：镜头级验收分两层——接缝级（相邻两镜首尾是否连续）与身份级（人物/机体/服装是否与定妆资产一致）。**两层都过才算过**；只验接缝会让漂移漏网。
4. **语法不串台**：H3 用英文官方结构、即梦中文分段、Seedance 中文标签＋@引用，三家不得混用（详见 `04-视频生成/平台提示词模板.md`）。
5. **与本地工具零耦合**：体系只描述能力、登记能力，不绑定任何具体软件/路径/账号；本地耦合只允许登记在项目的《能力登记.md》里。
6. **一致性靠机器查，不靠人记**：任何"两个地方应该一样"的关系（文档数字 vs 磁盘、样例 vs 代码、状态 vs 内容）都必须有对应检查项。改完代码跑 `python tools/run_all_checks.py`——16 道闸全绿才算改完。**跳过不算通过。**

> 第 6 条是踩坑换来的：开发中连续三次栽在"靠记忆维护一致性"上——
> ① 两个项目被绑在一起（拷走一个另一个就废）
> ② 审核状态不绑定内容，改参数重跑后旧结论仍显示"通过"（比丢失更危险）
> ③ 改了代码没同步样例，而每次都声称"样例已更新"
>
> 三次都是同一个病：**依赖记忆而不是依赖检查**。现在全部转成了自检闸。

## 五、渐进加载与通用能力层

本体系的稳定正文入口只有 `SKILL.md`；`skill-manifest.json` 只帮助不擅长中文目录发现的 Agent 识别入口，不替代本文件。

端到端任务按以下最小读取链执行：

```text
L0：SKILL.md + skill-manifest.json
L1：从这里开始.md；端到端再读 AGENTS.md + 通用Agent短剧生产规范.md
L2：项目状态摘要.md + 当前 G0–G6 关卡文件
L3：当前产物需要的专项文档
L4：仅在查证或解决失败时读取案例、历史资料和失败日志
```

- 不确定涉及风格、叙事、预算、合规或不可逆返工时，按《通用Agent短剧生产规范》的候选项协议给出 2–4 个方案。
- 执行参数、文件格式、重试和普通细节由 Agent 自主处理并记录。
- 断点续跑先读项目《项目状态摘要.md》，不要重新加载全量知识库。
- **新开会话 / 断点续跑 / 跨会话接续**：先读根目录 `新会话启动卡.md`（三步接续法 + 一句话模板 + 关键路径清单），不复制长对话上下文。
- 中文目录可以保留；识别兼容由根目录 `skill-manifest.json` 的 ASCII `id` 和 `entry` 字段提供。

## 生产证据门禁补充

先读 `07-端到端管线/生产证据与片型路线.md` 的简明流程。Agent自行判断任务、定内容并按顺序制作，类型不限。用户全权委托时不要求逐关签核，不要求production.json或哈希证据。检查实际结果，发现问题修当前环节；不要用文件手续代替制作与质检。

### 默认先看 seek 参考

视觉制作任务默认先按需求检索seek库、实际查看少量贴题作品，再创作；不要求读完整库。执行细节以`07-端到端管线/生产证据与片型路线.md`第2步为准。检索出卡片不算完成参考；镜头简表记录参考文件与借鉴点即可，不增加审批。

### 前后逻辑试行

默认在现有流程中检查整片组织线索、相邻镜头的观看关系、顺序首帧与连续粗剪；具体做法见`07-端到端管线/生产证据与片型路线.md`的“前后逻辑小检查”。不新增审批，不把独立漂亮镜头直接拼盘；导出器的通用描述和转场建议不代替Agent对实际内容的判断。

### 时长与切点

不平均分配镜头时长，不把AI生成段自动当成剪辑切点。先定段落连续呈现/切镜方式，按内容估时，再适配工具；一镜到底需要实际验证跨段连续性。细节以`07-端到端管线/生产证据与片型路线.md`“时长、切点与连续呈现”为准，自动草案时长和转场不代替导演判断。

### 资产图按镜头需要先准备

人物与场景一致性不能只靠文字或多抽图。反复出现的主体先定身份、服装与需要的视角；空间先总览，再派生所需机位与状态；互动先做正确站位的同框关键图，修静帧再做运动。成套参考板（多视图/服装/材质/表情/手持）做法与崩脸像素预算见`03-角色与视觉资产/角色资产参考板.md`；锚定纪律见`03-角色与视觉资产/多镜头角色一致性.md`；场景见`场景与道具资产.md`。不设统一张数、不增加审批、不绑定供应商。

### 分镜必须有实际画面过程

写视频提示词前读`02-分镜与镜头/分镜叙事工作流.md`“写出能发生的画面”。围绕观看重点写可见行为、触发与反应、空间/道具状态及结束理由；不要只写站姿、景色和慢推，不用情绪标签或旁白代替表演。对白按剧情与工具能力安排，不一律禁用。分镜不按单次生成秒数平均分配，静帧起点与视频变化分开写；丰富的是有效细节，不是词数。

### 光线也要有层次

光线不是全片统一的“暖光/电影感”。制作前读`对标参考库/方法论/光线设计库.md`，按场景需要选择主光来源、硬/柔性质、辅光/反射/轮廓、色温对比、阴影落点和变化理由；同一时空继承主光方向，只有剧情或光源改变才改变光线。不要求每镜换光，不随机堆灯。

### 全链路保留有效细节

立项把看点落成可拍内容，剧本写事件与反应，资产写稳定识别与空间/状态，镜头写具体变化，不在逐层摘要中丢掉原有行动。分别按`立项对标拆解.md`、`短剧编剧引擎.md`、人物/场景资产手册和`04-视频生成/平台提示词模板.md`新增说明执行。提示词遵守当前工具真实字段及长度单位；优先动作、关系、关键反应、状态与声音，删除重复美辞而不是删剧情。不要求写满上限，不增加审批。

### 细节补查

有效细节还包括：动作先后与持续性、人物注意力/视线、互动双方站位与接触遮挡、重量摩擦等可见反馈，以及必要的声音/光影同步。写进剧本、分镜和视频提示词的对应层，不堆在风格段落。技术分段要带上一段的完成状态和本段结束状态，不能复制首帧加泛化慢动作。

### 低成本字幕规范

默认用清晰统一的普通字幕轨；关键词少量变色；片名/章节简单淡入淡出；场景文字后期单独叠加。字幕在配音时间确定后制作，不让视频模型生成长句，不做高成本粒子/复杂跟踪。字段和流程见`06-后期与发布/剪辑字幕与成片.md`。

### 镜头语言、画面语言与色调路线

细节检查还要看观众站位、视线/运动方向、轴线、第一视觉焦点、前中后景、引导线/留白/遮挡和色彩阶段变化。色调不是每镜换滤镜；同一时空统一白平衡与肤色，只有内容节点改变才改变色温、饱和度、明暗或对比。执行细节见`02-分镜与镜头/影视视听语言速查.md`及分镜工作流，不增加审批。

### 渐进式加载

默认只读 `README.md` 与本文件；全流程才读 `从这里开始.md`、`AGENTS.md` 和 `07-端到端管线/生产证据与片型路线.md`；单点任务直接读对应阶段文档。不要把根目录全部资料、项目文件或归档 TODO 一起加载。
