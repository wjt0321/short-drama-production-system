# 知识库维护清单

- 原来源核验日期：见各条记录；2026-10-03 进行了文档分层整理，不代表重新核验外部规格。
- 维护原则：官方文档优先；实测结论与官方规则分开；平台参数不可视为永久不变。

## 文档职责与去耦边界

| 内容 | 唯一维护位置 | 其他文档怎么用 |
|---|---|---|
| 加载与任务识别 | `SKILL.md`；`skill-manifest.json` 对应机器路由 | 只引用，不另写读取顺序 |
| 能力获取、授权、重抽、冻结、命名 | `AGENTS.md` | 简明生产路线细化执行，不复制第二套回退链 |
| 实际生产、参考、切点与粗剪检查 | `07-端到端管线/生产证据与片型路线.md` | 入口只路由 |
| 视觉基线与交付画幅 | `导演视觉圣经.md` 及项目确认值 | 不混入某工作流的生成像素 |
| 专项创作方法 | 对应阶段文件 | 上下游引用产物，不绑定实现 |
| 当前实现与配置索引 | 体系/项目《能力登记.md》 | 项目选择优先，体系记录是候选 |
| 本机参数、失败与效果经验 | `技术资产_环境事实.md` | 不推广成所有项目的门槛或排名 |
| 供应商语法与实现教程 | 标注“适配层/按需适配资料”的文档 | 选定实现后按需读，复核版本，不倒灌通用模板 |
| 采集数据、历史来源和旧版本 | 参考库、源资料与历史快照 | 保留来源；不默认加载，不当成当前规范 |

“去耦”不是删除所有品牌名或禁止引用项目内文件，而是不让通用流程依赖某品牌、账号、安装目录或脚本。参考库与工具可替换；效果、产物和质量要求不随替换丢失。

### 新增内容收敛自检

- 同一规则是否已有权威出处？有则补在那里，入口只加路由。
- 模型时长、分辨率、语言、节点、提示词标签是否混入通用模板？移到实现记录，模板只留能力字段。
- 替换供应商后，是否必须改剧本/分镜 schema 或角色 ID？如是，应把提交格式另作映射。
- 是否把当前机器的一次结果写成“必然、最强、永久可用”？保留原记录及失败样本，明确条件和待验证项。
- 是否用整理日期替代实测日期，或模板预填日期造成假验证？未验证写“待验证”。
- 被收敛的经验是否有原文和去向？本次快照与变更索引见 `docs/经验保全/2026-10-03/README.md`，只作历史参考，不默认加载。

## 维护操作

1. 先查官方来源，再记录版本、页面标题和日期。
2. 若只有实测，标记 `observed`，同时写清输入、输出和环境。
3. 旧结论不要直接删除：改为“历史结论”，写明失效原因。
4. 新旧规则冲突时，优先更新能力登记和模板，不在聊天中口头覆盖。
5. 发现外部链接失效时，移入“待复核”表，不伪造替代来源。
