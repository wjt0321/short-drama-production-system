# AGENT 执行协议（能力层 · 不绑定工具）

> **文档边界**：本协议只规定能力获取、授权、登记、回退与产物契约。具体实现可记录在体系/项目《能力登记.md》、技术档案及明确标注的适配资料中；这些资料不是所有项目的强制前提。经验保留，未经本次核验的历史记录不得冒充当前保证。

## 一、总原则（五条，按优先级排序）

1. **能力层思维**：本协议与体系内所有文件只描述"需要什么能力"（如"生成一张 9:16 角色定妆图"），**永不指定具体工具**。工具由 Agent 在运行时按 §二 协议动态获取。工具会过时（具体实现会迭代），能力不会。
2. **人只审核与决断**：用户不参与任何粘贴复制、格式转换、重试排队。Agent 干完一个关卡，把"审核包"递给用户，用户裁决“通过 / 修改（指出项） / 暂停”，然后 Agent 继续。
3. **产物本地化**：一部片子一个项目文件夹，所有产物落在其中，命名规范见 §五。用户随时能打开文件夹看到进度，不依赖聊天记录。
4. **拿不准就问**：风格取舍、预算取舍、合规取舍一律问用户；执行细节（参数、格式、重试）一律不问。
5. **协议文件名固定**：本体系的端到端执行协议文件名就是 `AGENTS.md`；其他文档不得引用不存在的别名文件。

## 二、能力获取协议（四步，每次需要新能力时执行）

```
① 明确能力需求：要干什么 + 输入 + 输出规格（如"文生视频：9:16，4-8s，吃首尾帧图"）
② 探测环境：本地有没有可用实现？（询问用户 / 探测已知端点 / 检查本机服务）
③ 检索决策：没有就问用户倾向（本地部署 / 平台 API / 云端），然后现场检索该方案的
   当前文档（官方文档优先，版本必须对齐当下），选定实现
④ 登记：把结果追加到项目文件夹的 《能力登记.md》（模板见 §六），之后本片复用
```

**纪律**：②③ 两步的结论必须登记，不允许"这次用 A 工具下次凭记忆换 B"；登记过的能力直接复用，除非用户要求更换。

**用户不懂技术的处理**：Agent 向用户描述能力时只说效果和代价（"这个方案本地免费但一张图要 40 秒；平台方案每张几毛钱、10 秒出图"），不提实现细节；让用户在"效果/速度/价格"上做选择，而不是在工具名上做选择。

## 三、关卡制执行流程（G0–G6）

> **顺序说明**：本文件的 G0–G6 是实际生产顺序；根目录 01–07 是知识库目录。G2 先锁定角色/场景/道具等视觉资产，G3 再做最终分镜与首帧，避免先拆镜后换资产。

每关的标准动作：**产出审核包 → 等用户裁决 → 通过后登记产物 → 进入下一关**。审核包 = 该关产物 + 一页"看点说明"（告诉用户看什么地方、什么算好、什么算不过）。

| 关 | Agent 做什么 | 审核包内容 | 用户看什么 | 通过标准 |
|---|---|---|---|---|
| **G0 立项对标 + 风格立项** | ① 走 `01-创意与剧本/立项对标拆解.md`：拆 2-4 部目标平台当期对标作品（题材公式/钩子/视觉规格/成本模型），完成回本测算并定产能模式；② 用《导演视觉圣经》选基线卡 + 填色彩脚本、照明卡初稿 | 对标拆解表 + 回本测算 + 产能模式 + 风格提案一页（基线卡 + 色彩走向 + 两个参考画面描述） | 方向有没有市场、账算不算得平、视觉基线是否一致 | 对标结论与回本测算经用户确认；相关字段锁定，用户裁决为“通过” |
| **G1 剧本** | 走 `01-创意与剧本/短剧编剧引擎.md`（含改编管线） | 大纲 + 剧本 + 钩子/卡点标注 | 主角目标、核心阻力、关键转折、情绪曲线、前3秒承诺、结尾钩子和合规项 | 相关字段锁定，用户裁决为“通过” |
| **G2 视觉资产** | 走 03 阶段（定妆/三视图/一致性锚 + 视觉圣经的妆造色彩） | 角色卡三件套 + 场景/道具图 + 锚句表 | 脸和场景对不对味 | 角色可定稿（此后全片冻结） |
| **G3 分镜 + 首帧** | 走 02 阶段（普通镜头按分镜工作流，炫技/无厘头按炫技镜头库，文戏/正剧/对白戏按 `02-分镜与镜头/文戏对白节奏.md`）+ 逐镜首帧图；对白镜头按 `03-角色与视觉资产/写实对白微表演.md` 定表演幅度/视线/口型；**分镜表逐刀填 `刀型`（长刀/短刀）与 `本刀新信息`，时长由内容定、不由模型档位定（重要 4–8 秒，不重要 1–2 秒），全片长短刀都要有** | 分镜表（含首尾帧列 + `刀型`/`本刀新信息`/`时长`）+ 每镜首帧缩略图拼版 | 每镜构图、风格统一性、**节奏有没有长短** | 分镜表逐镜过，首帧无一眼假；**整列时长几乎一样（切点等距）判为节奏失败，不通过** |
| **G4 逐镜生成** | 按 §四任务清单逐镜跑视频；每 2–3 镜递一次审核 | 新出炉镜头 + 与相邻镜头的衔接检查 | 动得对不对、漂没漂 | 全镜通过；废镜走回退链 |
| **G5 音频** | 走 05 阶段（配音/音效/BGM，口型按 lip-sync 选型表）；多语言版按 `06-后期与发布/多语言版本管线.md` 产双语台词表并定版本策略 | 配音试听 + 音效建议书 + BGM 候选 | 声音对不对脸、情绪对不对 | 分轨试听 + 音画粗混版试听确认 |
| **G6 成片交付 + 首集验证** | 走 06 阶段出成片；多语言版按 `06-后期与发布/多语言版本管线.md` 出双语字幕与口型适配；同时生成本片《执行清单》终版；连载型作品发布后按 `06-后期与发布/首集验证与止损.md` 做 24h/72h 首集验证 | 成片 + 剪辑装配单 + 清单（见 §四）+ 复盘一页 + 首集验证结论 | 整体回放 | 装配单完整、时间线已确认、渲染已登记、完整回放通过，用户裁决为“通过”；连载型作品首集数据达标或止损结论已登记 |

**关卡不可逆规则**：G2 之后角色冻结、G3 之后分镜冻结——默认只改当前关；若根因属于已冻结上游资产，必须提交解冻申请，列出受影响产物、返工成本和候选方案，经用户批准后回退到对应关卡，并重新通过受影响的审核包。不得默默换主角脸或改方向。

**生产模式分级（G0 立项时选定，影响全流程审核节奏）**：

| 模式 | 适用 | 审核节奏 | 首集验证 |
|---|---|---|---|
| **精品单集模式** | 单集 3-8 分钟、重质不重量 | 每关标准审核包，逐镜审核 | 可选 |
| **量产连载模式** | 连载漫剧/短剧（日更、几十到几百集） | 用户只审 G0 立项、G1 首集剧本、G2 首集资产、里程碑集（每 5-10 集），中间集由 Agent 按冻结资产自动推进 | 必做，作为放行批量生产的闸门 |

> 量产模式下"每 2-3 镜递一次审核"降级为"每里程碑批次递一次"，其余镜头按 G3 冻结分镜与 G2 冻结资产由 Agent 自主执行并记入《执行清单》，用户随时可查。

## 四、任务清单模板（G4 逐镜执行用，也作为用户监督进度的一页纸）

```markdown
# 《片名》执行清单

| 镜号 | 首帧 | 视频 | 状态 | 重抽 | 配音 | 音效 | 字幕 | 备注 |
|---|---|---|---|---|---|---|---|---|
| S01 | ✅ 09-24 | ⬜ 排队中 | 待审 | 0/2 | ⬜ | ⬜ | ⬜ | 尾帧接 S02 |
| S02 | ✅ 09-24 | ❌ 失败×2 | 回退链 | 2/2→换备选 | ⬜ | ⬜ | ⬜ | 见回退链 B |

状态机：待生成 → 生成中 → 待审 → 通过 / 重抽(≤2) / 回退链
```

- Agent 每完成一项更新清单；用户随时打开清单看进度，不看过程。
- "重抽"列预算默认 2 次，2 次不过自动进回退链并通知用户，不让单镜卡死全片（对齐 07 工程化机制）。

## 五、失败回退链（任一环节失败时按序执行，每步都登记）

同一实现默认最多 **2 次质量重抽/重生成**。第 2 次仍失败必须进入回退链，不允许单镜无限重抽。只有限流、排队超时、网络抖动等瞬态技术错误，才允许额外进行 1 次技术重试；这次不占质量重抽预算，但必须在重抽日志中标记为“技术重试”。

```text
A. 重试（质量重抽≤2 次；瞬态技术错误可额外技术重试 1 次）
B. 换同能力的备选实现（查《能力登记.md》的备选列）
C. 降规格（分辨率/时长/运动复杂度下调一档）
D. 换提示词语法或输入协议（按《能力登记.md》记录的当前实现要求重新适配，不沿用未登记的语法、标签或引用格式）
E. 换方案（静态帧 + KenBurns / 旁白带图 / 删镜改叙事，需用户点头）
```

**错误分类最低要求**：限流/超时、参数不支持、角色漂移、场景漂移、动作错误、口型/音画错误、合规拒绝、文件损坏、用户审美不通过，必须在重抽日志中区分。

## 六、产物目录与命名规范（项目文件夹内）

```
《片名》项目/
├─ 00-立项/      风格提案.md（G0 审核包）、对标拆解表.md、立项决策表.md（含回本测算与产能模式）、能力登记.md
├─ 01-剧本/      大纲.md、剧本.md
├─ 02-资产/      角色/（卡三件套）、场景/、道具/、锚句表.md
├─ 03-分镜/      分镜表.md、首帧/
├─ 04-镜头/      clips/、prompts/、重抽日志.md
├─ 05-音频/      配音/、音效/、BGM/
├─ 06-成片/      剪辑装配单.md、成片.mp4、字幕.srt、封面帧、复盘一页.md
├─ 用户裁决日志.md、变更记录.md
├─ 素材与授权台账.md、成本台账.md
└─ 执行清单.md   §四 的一页纸
```

- 镜号统一 `S01/S02…`，重抽版本 `_v2/_v3` 不覆盖旧版。
- 每个通过的镜头把“通过的提示词原文”存进 `04-镜头/prompts/`，可复现、可复盘。
- G1 通过后核心因果、人物关系、结局和卡点冻结；角色、场景、道具在 G2 通过后冻结；分镜在 G3 通过后冻结；若回退链涉及删镜或改叙事，必须回到 G1/G3 重新审核；解冻必须写入《用户裁决日志.md》和《变更记录.md》。
- 新建项目优先复制根目录 `模板/短剧项目模板/`，不要手工拼目录。

## 七、《能力登记.md》模板（每个项目自动生成）

| 能力 | 本片实现 | 备选 | 输入规格 | 输出规格 | 适用镜头 | 限制 | 单次成本 | 平均耗时 | 实测成功率 | 授权/商用状态 | 配置位置 | 最后验证 | 回退条件 |
|---|---|---|---|---|---|---|---:|---:|---:|---|---|---|---|
| 例：图生视频 | （运行时发现） | （运行时发现） | 9:16 首帧/尾帧 | 4–8s MP4 | 动作/衔接 | | | | | | 配置名，不写密钥 | 2026-09-25 | |

> 失败、耗时、成本和授权结论必须写实测事实；不要把未核验的社区说法写成官方保证。

> 本协议刻意不写任何具体工具名。第一个项目跑完后，《能力登记.md》就是你个人的"能力地图"——它记录的是你的环境事实，不是别人的教程。

## 八、候选决策协议

- 风格、叙事、预算、合规和冻结后的高成本变更：给出 2–4 个候选项，写明效果、代价、风险、可逆性和推荐项，等待用户裁决。
- 文件格式、命名、普通镜头参数、技术重试和不影响方向的细节：Agent 自主决定并记录，不把执行负担转给用户。
- 候选项用用户可感知的效果命名，不用实现名称代替方案；选定结果写入《用户裁决日志.md》。
- 如果输入矛盾导致剧情无法成立，先给最小修正版候选，不能默默改方向。

## 九、渐进加载与断点续跑

加载顺序唯一维护于 `SKILL.md`“渐进式加载”，机器路由对应 `skill-manifest.json`。本协议不再复制另一份文件清单。

- 项目续跑优先恢复当前状态，不重新加载全库。
- 每个关卡通过、资产冻结/解冻、失败回退或上下文接近上限时，更新《项目状态摘要.md》。
- 项目模板根目录保留《项目状态摘要.md》；“相关文件”最多保留当前需要的 8 个文件。

## 生产执行硬门禁

执行以 `07-端到端管线/生产证据与片型路线.md` 简明流程为准。用户全权委托时Agent自主选题、定方案、制作和质检，不等逐关签核，也不建立哈希审批链。仅记录简短镜头状态和当前问题。可直接使用已登记工具；发现明显缺陷修当前环节，同一路线两次失败换办法，避免无限循环。本文旧关卡审批描述只适用于用户明确要求逐阶段审核的任务。
