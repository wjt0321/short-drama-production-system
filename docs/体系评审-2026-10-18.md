# 短剧成片体系 · 全面评审（2026-10-18）

> 范围：根协议（`AGENTS.md` / `SKILL.md` / `从这里开始.md` / `命令速查.md` / `能力登记.md`）+ 01–07 知识层 + `tools/` 全部闸 + `模板/短剧项目模板/` + 两个真实项目（《千里江山》已交付、《第一次呼吸》在产）。
> 方式：**审读阶段只读**；阶段一的结论已按用户批准落成修改（见 §9），修改记录逐条对应到本文件条目，未列入 §9 的条目仍保持原状、待决。
> 四条独立子审计（闸门/协议/落地/知识层）+ 主审实测（ffprobe 实测成片、文件 `LastWriteTime` 排序、`run_all_checks.py` 实跑、场景切点检测、接触印相拼图、以及 19 组反例 fixture 直接喂给闸）。
> 全文引用格式 `文件:行`，标「实测」的均在本机复现过；**审计自身的误判也在 §9 如实列出**。行号为 2026-10-18 提交时点；后续改动后以文件内关键字检索为准。

## 0. 一句话结论

**这套体系的执行纪律已经很强，弱的是两处，而且两处同源：**

1. **所有判据都在验"文档写得对不对"，没有一条在验"片子成没成"。** 30 道闸（`--quick` 实跑 29 道，少的那道是慢测）全部只读 Markdown（`tools/*.py` 里除诊断工具外无一处 `ffprobe`）。于是字幕全丢、码率只有规范值 1/5、交付文件被换过、装配单与成片对不上，**全部照常"通过"**。
2. **复盘产出的经验没有回到体系的回路。** 《千里江山》复盘写了 5 条"需要回写的剧本规则"，全库 grep **零命中**；同一位作者随后两次写下"没人拿计算器加过一遍"，而 `成本台账.md:61` 至今仍把 3.3+4.6+0.3+0.4 汇总成 7.1h（真值 8.6h）。

结果就是：**同一类错误在两部片里重复发生，而每一次都被正确地记录、却没有一次被真正修复。**

## 1. 如果只改三件事

### A. 让复盘真的回写体系（收益最高，成本最低）

**现状（实测 grep 证明）**：《千里江山》`06-成片/复盘一页.md` 第五节列了 5 条"需要回写的剧本规则"——旁白不得解释画面已说清的事 / 每句旁白必须比画面多给一层 / 优先引宋人诗词与画论原句 / 科普信息不进旁白 / 旁白定位改"看过这卷画很多遍的人"。全库 markdown 搜 `旁白不得解释`、`比画面多给一层`、`讲解腔`、`宋人诗`、`诗词` → **一条都没有落地**，`01-创意与剧本/短剧编剧引擎.md` 至今未改一字。

系统里唯一的"反哺"回路是连载运营的发布数据 → 下一集（`06-后期与发布/标题钩子与发布.md:166`），且仅限连载。`docs/经验保全/` 的事故档案、`复盘一页.md` 的结论，**没有任何机制会去更新能力登记、风格卡或闸阈值**。

**改法（唯一权威不破裂）**：给 `模板/短剧项目模板/06-成片/复盘一页.md` 加一列必填 **`回写目标（文件:行）`**，并在 `AGENTS.md` G6 通过标准里加一句：「复盘一页中每条规则必须指向一个已修改的 `文件:行`；无回写目标的复盘不构成 G6 完成」。加一道文本闸校验该列非空且指向的文件确实存在、且被修改过（可用 `git diff --name-only` 比对）。**不再新增任何文档。**

### B. 至少让一道闸看一眼成片，并让质检表首行变成自动填的指纹

**现状（实测）**：

| 事实 | 文档写的 | ffprobe 实测 |
|---|---|---|
| `成片.mp4` 时长 | `成片质检表.md:30` = **120.167s** | **118.458s** |
| `成片.mp4` 码率/体积 | 4.63 Mbps / 69.97 MB | **4.69 Mbps / 66.25 MB** |
| `纯净版_无旁白无字幕.mp4` | 质检表称与主版 `-c:v copy` **逐帧一致** | **120.166s**（差 1.7s，不同时间线） |
| `成片_竖屏版.mp4` | 执行清单:53 指定"抖音主推" | **1080×1920 / 1.99 Mbps**，未进任何质检记录 |

体系自己在 `06-后期与发布/成片与字幕.md:404` 写的是 **8–12 Mbps（H.264）**、`:407` 要求上传码率略高于平台推荐值。四个交付变体实测 **1.99 / 4.65 / 4.69 / 5.44 Mbps，全部低于自家下限**，而没有任何一道闸会去看它。

同源问题还有两处：`G6终检报告.txt:74-75` 在 118.27s / **119.07s** 取样——119.07s 已超出当前文件长度；`剪辑装配单.md:4` 的 120.167s 时间线与成片实测切点（26 处）也对不上。

**改法**：新增一道 `check_render_probe.py`（注册为 `成片探针-真片`，进 `REQUIRED`）：对 `06-成片/*.mp4` 跑 `ffprobe`，把时长/分辨率/帧率/码率/音轨采样率与 `成片质检表.md` 的登记值比对，不一致即 FAIL；同时校验"质检表登记的文件名集合 == `06-成片/` 下的 mp4 集合"（现在登记 2 个、实存 4 个）。ffprobe 本机已有（`E:\AI\ComfyUI\tools\ffmpeg\bin\`），这是**设计选择，不是能力缺失**。
配套一条硬规则写进 `AGENTS.md` G6：**任何重渲使上一版质检失效**，质检表首行必须是自动填写的「文件名 + 时长 + 码率 + SHA256」。

> 若本轮不想加闸，最低成本替代：把 8 道 `-真片` 闸**改名或在闸表加一列「本条检查文档，不检查成片」**。当前状态是最坏的一种——名字叫"真片"，检查的是字。

### C. 给"文案"建立判据层（用户最痛、体系最空）

**现状**：用户原话「成片质量还行，**文案太水了**，我哪怕搞几句诗词也比读出来好的多」（`用户裁决日志.md` D005）；`复盘一页.md` 自评「技术链路全通，内容链路没通……但旁白稿是弱的」。而体系里：

- `短剧编剧引擎.md` §11「交付前检查清单」**没有文采/语域/文案维度**，只有台词口语化；
- `成片质检表` 五、内容判断 **没有文案裁决行**；
- 于是《千里江山》在把"文案太水"写进记录的同时通过了 G6；
- `短剧编剧引擎.md:448` 还引用了一个**不存在的**「§1.4 的 20% 上限」（§1.4 无此节；20% 规则的真实位置是 `05-音频/配音与音效设计.md:61` 和 `:255`）；
- 该 20% 上限**从未被校准**：项目实际 74%，用户知情接受 57.1%，体系始终只有一个未经检验的数字。

**改法（三步，都不新增文档）**：
1. `短剧编剧引擎.md` §11 增加「文案/旁白」四条检查项——是否复述画面已说清的事 / 每句是否比画面多给一层 / 是否有原创表达或引文 / 语域是否与片型一致；同时删掉 `:448` 的悬空引用、把 20% 改成"按片型给区间，且必须由项目复盘回填实测值"。
2. `成片质检表` 增加一行 `文案裁决：通过 / 不通过（原因）`，**这是 G6 唯一的"作品向"判决**。
3. G1 加一句"立意语域检查"：`复盘一页.md` 已给出根因结论——「解读腔从根上排除了诗意……定'讲解'就不可能写出诗」。

## 3. 内容与片型：体系承认、但还没解决的空档

1. **片型只有两条腿。** `07-端到端管线/片型全流程.md` 只有真人短剧（LibTV 公式版）与小说漫剧。`《千里江山》`（27 镜、无对白、旁白驱动）与 `《第一次呼吸》`（"剧情短片·无对白视听诗"）都是**第三条**，没有对应方法论文档。无对白意味着编剧引擎的钩子/反派/卡点体系整体失效，旁白成为唯一语言载体——而旁白只有一条"≤20%"的上限，**没有任何"怎么写"的标准**。
2. **风格卡是纯正向描述，天然趋同。** 体系自己承认这点（`对标参考库/开源导演技能体系研究-2026-10.md:63`），但 `AGENTS.md` §8.1 的反例法只落在提示词层，没有回落到风格卡层。已成片的现实印证：6s 采样拼图显示 21 个镜头里多数是"山在上、水面留白在下"的同一构图，约 40–50% 画面是空绢地/水面。**没有任何一道闸测构图重复度或主体占比**（`check_shot_structure.py` 只测时长、连击、镜型配比）。
3. **风格锁不含字体/排版。** 片名与落款用了现代黑体，与青绢底色气质冲突——九要素（构图/色彩/光/镜头/材质/表演/节奏/声音/质感）里没有文字层。
4. **刀型定义有空洞且与实现层打架。** `分镜工作流.md:27` 写长刀 4–8s / 短刀 1–2s，留下 **2–4s 的定义空洞**；而 `成片与字幕.md:31` 说竖屏短剧默认 2.4–4s，正好落在这个空洞里，`check_shot_structure.py` 若按刀型校验就无法通过自家标杆。
5. **实现层参数反向塑形导演层（违反体系自己的第一原则）。** `技术资产_H3.md:547-548` 把"静态镜头 5s 档 / 走位 10s 档"写成分镜规范，而 `分镜工作流.md:28` 明写"不按模型档位填"。更麻烦的是 `技术资产_H3.md:510` 自己写着"向下自动取整，不报错、不提示"——**请求 4 秒会被静默取整成 3.75 秒**，而"4–15 秒"这个合法下界在 `视频实现适配.md:174` 与 17k+5 的帧数序列并不一致。
6. **音效无现役实现**（`能力登记.md` 2026-10-09 缺口登记），但 `执行清单` 有音效列、G5 通过标准要求"音效建议书"——登记了缺口却没有降级路径。
