# 平台提示词契约（通用三层契约 + 官方规范审计）

## 〇、三层架构（先看这里）

| 层 | 写什么 | 谁负责 | 与平台有关吗 |
|---|---|---|---|
| **1. 导演意图层** | 这一镜要让观众看到什么、状态差五拍、摄影机起讫、环境异步、转场接力、声画事件、≤3 类硬约束 | 导演（分镜稿） | **无关** |
| **2. 生成模式层** | T2V / I2V / FLF2V / 参考生视频 / 运动参考 / 多镜原生 / 视频修改 | 选型（按本镜需求） | 模式名是平台无关术语 |
| **3. 平台适配层** | 把前两层翻译为具体实现语法（字段、引用、时长、参数） | 适配层（看 `视频实现适配.md` 与 `适配登记/`） | **强相关** |

**纪律**：

- 导演意图层一旦写定，**任何平台都不得改写其语义**；适配层只做翻译，不做改写。
- 模式选错（例如精确小物交互走 I2V 而非 FLF2V）属于 §四「失败改写」中的"模式错配"错误。
- 一份提示词先在第 1、2 层走通，再进第 3 层做平台语法映射；不要从平台反推导演意图。

## 一、导演意图层（强制骨架）

> 任何镜头都按以下 7 段填写。段间空一行；段内不堆叠形容词；只写观众能看见、听见、能用来理解动作的过程。

### 1. 镜头任务（一句话）

这一镜给观众什么**新信息 / 情绪变化 / 揭示**。一个生成段一个主事，不塞多个独立剧情事件。

### 2. 锚定对象

- 角色 ID + 资产引用（如 `<角色A v2>`，详见 `03-角色与视觉资产/角色资产参考板.md`）
- 场景版本 + 时空状态（详见 `03-角色与视觉资产/场景与道具资产.md`）
- 关键道具版本 + 当前状态 + 持有者/左右手

不写"那个男人""那把刀"。不写"同上"。锚句不替镜头说话，锚句只锁身份。

### 3. 起始状态

首帧定格的样子：构图、机位、视线方向、光源及方向、道具状态、人物姿态。**起始状态必须是动作开始前的可见状态**——不是"已完成的事"，不是"概念海报"。

> **首帧三禁**：① 不是动作结果海报；② 不是模糊远景或纯色块；③ 不暗示身份资产版本以外的额外特征（"中年男子" ≠ 资产 v2 的少年）。
>
> **中段衔接帧补充（2026-10-13）**：作为下一镜衔接参考的首帧，优先取上一镜"动作进行到一半"的中间态帧而非静止完成态，配套提示词写"继续……"；原理与限定见 `02-分镜与镜头/跨镜连续性与帧链法.md` §2.1「衔接帧取动作中间态」。

### 4. 状态差五拍（动作节拍）

把这一镜的动作切成五拍，**只写可观察过程**，不写"仿佛""似乎"：

```
触发 → 启动 → 发展/受力 → 结果 → 反应
```

- 触发：什么让动作开始（看见/听见/接触/物理推动/情绪触发）
- 启动：动作的第一可见动作
- 发展/受力：动作进行中的接触、空间、力量变化
- 结果：动作的可见后果（状态变化、位置变化、物品状态变化）
- 反应：人物或环境的可观察回应（呼吸、视线转移、表情变化、声音）

**缺任何一拍就视为未设计**。短镜头可以压缩其中一两拍，但必须显式说明哪一拍不写及理由（例如"本镜只有结果+反应，无触发——上一镜已触发"）。

### 5. 摄影机起讫四要素

- **起点**：机位相对主体的位置（距离/高度/朝向）
- **过程**：运动方式、速度、加速/减速/惯性（用专业词：dolly / orbit / tracking / pan / tilt / crane / handheld drift）
- **终点**：结束时相对主体的位置（同样写距离/高度/朝向）
- **焦点**：观众先看什么，最后看什么；焦点是否在过程中转移

**"cinematic camera movement" / "镜头慢慢推近" 不是合格式**。任何平台缺失其中任一要素就视为运镜未设计。

### 6. 环境异步响应

光线、空气、布料、液体、机械、尘埃、背景人物在镜头中的**异步表现**。环境响应不能与主体同步，否则画面会"木偶化"。

```
示例：女子撑伞走过青石板路——
光线：远处暖红灯笼在雨雾中泛光，女子侧脸受光随镜头绕动从暖到冷
空气：雨丝方向不变，镜头横移使雨面背景出现视差
布料：裙摆下缘被水汽沾湿，深色加重
背景人物：摊贩擦肩而过抬头望一眼即低头，与女子节奏不一致
```

每镜挑 1–2 类写**显式变化**，不堆"全部异步"。

### 7. 转场接力 + 声画事件

- **转场接力**：本镜**结束状态**如何把视觉/声音/动作接力给下一镜（视线、动作半成品、声音延续、遮挡、光线、形状）。详见 §三。
- **声画事件**：本镜需要的对白（原文语种）、环境声、音效、配乐与同步点。**只列事件，不写情绪**（"悲伤音乐"不写，写"低频弦乐渐强"）。

### 8. 硬约束（≤3 类）

通用模板只允许以下三类硬约束（与适配层平台能力无关）：

1. **身份连续**：`<角色A v2>` 面部/服装/身形在窗口内不漂
2. **人体/道具结构稳定**：六指、穿模、消失/凭空出现、违反机构学
3. **无画内可读文字**：避免在画面内出现可识读字符

**禁止堆叠** `preserve / locked / only / no / never` 等"防错合同"。**禁止**把硬约束写成"不要 X""不要 Z"清单（除非适配层已确认该平台支持负面提示词并能稳定生效）。

> 平台不支持负面提示词时，正向描述替代：想要"门牌保持空白"就首帧本身没有字；想要"无字幕"就不放字幕。

### 9. 演员调度与运动学合同（Blocking / Motion Contract）

> 这一节是一次 S03 A/B 实测的直接产物：状态差 / 摄影机路径 / 焦点转移 / 转场接力都是必要条件，但**仅靠它们镜头仍然会失败**——B 组 S03 出现了「人物面朝摄影机却随车向后退，手与车把接触、脚步方向和车轮运动没有形成可信推车动作」。本节补的就是「在画面里到底怎么动」的可观察机制。
> 来源与许可证：研究档不随本包提供；许可边界见根目录 `声明与许可边界.md`。

**适用范围**：任何含以下任一动作的镜头都必须填写本节：
- 主体在画面里移动（走 / 跑 / 推 / 拉 / 骑 / 持物走）
- 主体与道具接触（拿 / 放 / 翻 / 按 / 擦 / 拍）
- 主体有朝向变化（转身 / 抬头 / 回头 / 转向）
- 多主体互动（递物 / 对视 / 同框接触）

纯空镜 / 慢推 / 静帧 / 风光推拉可压缩本节（写一句"无运动"即可），但首帧图本身不能违反本节的世界坐标一致性。

**9 项必填**（按动作类型可压缩 1–2 项，但必须显式说明不写的理由）：

| # | 字段 | 写法 | 反例（不许这么写） |
|---|---|---|---|
| 1 | **屏幕坐标与向量** | 主体在画面里**绝对坐标** + 位移方向用屏幕向量 | "他走了几步"、"他往前走" |
| 2 | **主体初始朝向** | 脸朝画面右 / 背朝镜头 / 侧身 45°；过程朝向变化 | "他看了看" |
| 3 | **移动方向与世界坐标** | 沿画面右侧从前景走向远景；与摄影机方向关系（跟拍 / 静止 / 反向）| "他走过街道" |
| 4 | **脚步 / 重心** | 起步脚、承重脚、落脚方向（"左脚迈出 → 右脚承重 → 左脚落稳"）| "他走起路来" |
| 5 | **手 - 道具接触点 / 承重 / 解除** | 哪只手 / 哪根手指 / 哪个部位接触道具哪一处；承重方式；解除时机 | "他拿起杯子" |
| 6 | **道具 / 轮子从属运动** | 链式运动：手把 → 踏步 → 身体 → 轮转 → 远景视差，五项方向一致 | "他推车走了" |
| 7 | **摄影机方向与主体相对速度** | 摄影机不动 / 跟拍 / 反向移动 → 主体在画面内坐标变化 / 远景动 / 滑出画面 | "镜头跟着他" |
| 8 | **轴线 / 视线** | 角色左右关系始终一致；视线看向谁 / 哪个屏幕方向 / 何时回看 | "他们对视" |
| 9 | **结束状态** | 终点坐标 + 朝向 + 与下一镜接力关系；与起始状态必须有可见差异 | "自然结束" |

**正向机械示例**（CFG=1 / Wan2.2 / H3 等没有负向分支的模型必须这么写）：

- ❌ `doesn't walk backward`（模型复制关键词，反而走倒退）
- ✅ `right foot steps forward, body weight shifts to right leg, left heel lifts`
- ❌ `不要滑步`（同上）
- ✅ `left foot fully lifts before landing; no sliding of shoes on ground`
- ❌ `turn around`（模型可能直接换姿态）
- ✅ `head turns left first, then shoulders rotate 30°, finally hips follow to face new direction`
- ❌ `拿起杯子`（缺接触点与承重）
- ✅ `right thumb and index pinch cup handle, middle finger and ring finger support cup bottom; cup rises with palm rotation; fingers release handle at chest height`
- ❌ `推车走了`（缺车轮耦合）
- ✅ `left hand grips upper cart bar, right hand grips lower bar; arms extend forward then push back; body leans forward; wheels rotate forward; distant wall panels slide from right to left`

**首帧冲突的硬规则**：

> 提示词不能修复与目标动作冲突的首帧。
> 如果首帧是「已完成态」（车已停下 / 椅子被坐住 / 门已关上），模型不知道「从哪开始动」，文字硬拧不会改变走样方向。
> 必须三选一：
> 1. **重做首帧**——把首帧改为动作过程前状态（车未停 / 人未坐 / 门未关）；
> 2. **改 FLF2V / 运动参考**——让末帧 / 参考视频接管目标态；
> 3. **接受现状回退到其他方案**——按 `重抽与回退决策.md` §三 E。

写完 9 项后，按 §四.1 七条自检再走一遍（首帧三禁 / 五拍 / 摄影机起讫 / 环境异步 / 接力 / 硬约束 ≤3 / 9 项运动合同齐全）。

## 二、生成模式层（选型决策）

> 选错了模式，再好的提示词也只能救一半。本节只给出**模式选型表**与**典型错配警告**；每个模式的平台映射查 `视频实现适配.md` §0 模式路由决策树。

### 2.1 七种生成模式

| 模式 | 关键能力 | 适合什么 |
|---|---|---|
| **T2V**（纯文本） | 仅文字描述 | 氛围、空镜、概念预览、**无严格身份/空间约束** |
| **I2V**（图生视频） | 首帧锁身份与构图 | 单镜叙事推进；首帧已表达一切，文本写"接下来发生什么" |
| **FLF2V**（首尾帧） | 首帧是起点、尾帧是结果 | **精确物理过渡**（液体、烟雾、变形、插拔、接触、空间揭示、受控转场） |
| **L2V**（末帧） | 末帧锁定，逆向收敛 | 结果状态必须严格匹配（场景表、道具落点） |
| **参考生视频 / 元素绑定** | 参考图锁角色/道具/场景 | **跨镜头一致性**——锁身份，不靠文字复述 |
| **运动参考 / 控制视频** | 动作或摄影路径由参考视频提供 | **精确交互、复杂运动**——导演意图放在参考视频，不靠文字猜 |
| **多镜原生** | 一段 prompt 含多个切镜 | **连续空间 / 一镜到底感 / 跨镜一致**——不等于每段都必须多镜 |

### 2.2 选型快表（按生命阶段判断）

```
这一镜需要什么？
│
├─ 严格身份 / 跨镜角色一致？
│    └─ 是 → 参考生视频 / 元素绑定（参考图锁身份）
│
├─ 精确 A 状态 → B 状态（液体/接触/变形/受控转场）？
│    └─ 是 → FLF2V（首尾帧）；要求精确运动 → 运动参考
│
├─ 复杂多目标交互（≥2 主体接触、姿态对位、道具交接）？
│    └─ 是 → 运动参考 + 参考生视频（仅当本机支持）
│
├─ 一段 prompt 多镜头连续叙事（一镜到底感）？
│    └─ 是 → 多镜原生（确认平台支持：H3 / 即梦 3.0 Pro / Seedance 2.5）
│
├─ 只是单镜叙事、无身份走位、起点在首帧已写清？
│    └─ 是 → I2V（首选）→ 缺首帧时 T2V
│
└─ 修改已生成的某一段（换背景/换局部动作）？
     └─ 是 → 视频修改（角色不重抽）
```

### 2.3 模式错配警告（必看）

| 反模式 | 为什么错 | 改用 |
|---|---|---|
| 精确小物交互（泪滴、拔插头、按键）走单首帧 I2V | 模型不知道 A→B 路径 | FLF2V / 运动参考 |
| 长连续空间（追逐、镜内揭示）走单镜 I2V 拼接 | 拼接损失节拍与空间感 | 多镜原生（同一 prompt 内多镜） |
| 跨镜头同角色不同服装走参考生视频但不给参考图 | 文字不能锁身份漂移 | 给角色参考图 + 简短提一下 |
| 复杂打斗 / 多人接触走 T2V | 无任何锚定 | 运动参考 + 关键帧参考 |
| 主体已完成态（结尾帧）做 I2V 首帧 | 模型不知道发生了什么 | 把结束态拆为下一镜首帧 + 用 FLF2V 接回 |

### 2.4 图生/多参考模式的图文分工（官方依据，2026-10-13 立）

> 本节只回答一个问题：**有了首帧/参考图之后，文本还该写什么。** 依据是两家官方文档（核验日期 2026-10-13）：MiniMax 官方提示词工程仓库 `github.com/MiniMax-AI/MiniMax-H3`（`skills/h3-prompt-writing/references/base-en.txt` / `ref-en.txt`）与火山方舟《Doubao Seedance 2.0 系列提示词指南》（`volcengine.com/docs/82379/2222480`）。

**分工原则（两家官方一致）**：

| 信息 | 图生/多参考模式下由谁承担 | 文本怎么写 |
|---|---|---|
| 身份、外观、服装、五官 | **参考图/首帧** | 文本不复述；Ref2VA 用 `<Subject N>` 一行定义职责（官方："explicit assignments tend to work much better"） |
| 场景、构图、空间关系 | **参考图/首帧** | Seedance 官方："空间关系建议优先通过参考图表达，减少复杂文字描述" |
| 风格与色调 | **参考图/首帧 + 一句风格锚句** | 只写一句锚句（见 `导演视觉圣经.md` §一·补 分模式注入纪律），不再逐镜复述风格全文 |
| 动作、事件发展、反应 | **文本**（图给不了） | H3 官方 I2VA 结构：首帧锚定 → 动作启动 → 持续发展 → 结果/反应 |
| 运镜、切镜、时序 | **文本** | Seedance 官方：每镜一种运镜词；分镜时序写"镜头1/镜头2/镜头3" |
| 声音、对白、配乐 | **文本**（或参考音频） | H3 分字段；Seedance 用 `（）音乐` `<>音效` `{}台词` `【】字幕` |
| 全局约束（无字幕/无水印等） | **文本，只写一次放末尾** | Seedance 官方约束词模板；"不要X"在 Seedance 是官方支持的约束词写法；H3 无负面字段，用正向英文表达排除 |

**官方反冗余原话（本体系的精简依据）**：

- Seedance 官方："描述尽量简洁，避免冗余，避免语义冲突"、"请勿直接将完整剧本作为提示词使用，文案内容过度冗余易造成模型理解混乱"、"越需要精准参考的素材放在越靠前的位置"、"不建议用满素材上限"。
- H3 官方（Ref2VA）：`detailed_description` 写目标视频的时间线，**不复述参考图本身长什么样**；生成任务主体描述正常为 350–500 英文词，对白密集型以完整对白时间线优先。
- H3 官方（I2VA）：描述先"锁定图内的风格、主体、构图、场景锚点"，再写后续动作——**锁定 ≠ 复述**，一两句话点名一致性关键点即可。

**不变的部分**：本节只改变"文本里写什么"，不改变导演意图层九段的思考义务——状态差五拍、摄影机起讫、转场接力、运动学合同在图生模式下照样要写，因为它们本来就是文本的职责；省掉的是"把图里已有的东西再用文字抄一遍"。

**文生（T2V）不受本节影响**：没有图像条件时，风格、外观、场景仍全部由文本承担，维持原有完整写法。

## 三、转场接力（导演意图层硬要求）

> 转场靠**接力**，不靠插件或随机叠化。每镜必须明确：本镜结束状态如何接给下一镜。

### 3.1 六种接力机制

| 接力 | 怎么做 | 适用 |
|---|---|---|
| **动作接力** | 本镜动作未完成，下一镜接着做 | 跑步、开门、对话轮换 |
| **视线接力** | 本镜人物看某方向，下一镜给出被看物 | 反应镜头、信息揭示 |
| **遮挡接力** | 本镜被前景/人/物体挡住，下一镜从遮挡后开始 | 转场、跨空间、跨时间 |
| **形状接力** | 本镜尾帧的轮廓与下一镜首帧的轮廓重合 | 硬切遮瑕、专业电影感 |
| **光线接力** | 本镜结束于亮/暗，下一镜从同光线开始 | 时间跳转、空间跳转 |
| **声音接力** | 对白/音效在切点延续 | 跨场景对应白、连戏 |

### 3.2 写转场接力的格式

每一镜的导演意图层结尾，加一行**接力声明**：

```
接力：<机制> + <接力对象>
例：接力：遮挡（门关上）+ 声音（对白延续，下一镜回答）
```

无接力声明 = 视为未设计。

## 四、失败改写（每镜必看）

> 这一节是「成功案例的反面教材」。每镜生成前与最后对照一眼，能拦住八成翻车。

### 4.1 七类典型翻车与改写示例

#### ① 静态海报首帧

**症状**：首帧已是动作完成态（手已握紧、表情如终态）。模型无法知道从"起点"到"已完成"发生了什么。

**改写**：
- 把"完成后"做下一镜首帧
- 本镜改为"前 1–2 秒动作过程" + 末状态做下一镜
- 例：`少年握紧珠子神情失落` → `少年在人潮里刚发现珠子滑出指尖，正伸手去接，视线从前方落到掌心`

#### ② 形容词代替机制

**症状**：写"cinematic camera""epic lighting""dramatic moment"。模型把它当滤镜/情绪，不产生可观察动作。

**改写**：用具体动词替代：`镜头从少年右肩后方以 2 米高度、slow speed 小幅度推进，到胸口高度结束`。光源写具名：`便利店门口霓虹管闪烁，雨夜反光打在伞面`。

#### ③ 摄影机起点/过程/终点缺一

**症状**：只写"镜头慢慢推近"。模型不知道从哪里推、推到哪里、什么时候停。

**改写**：
- 起点：`从少年右肩后 2.5 米、高 1.6 米处`
- 过程：`以 slow speed 推进，绕过正面时距离缩至 1.8 米、高度降到胸口`
- 终点：`停在少年左前方 45°、距 2 米处`
- 焦点：`始终在少年眼睛`

#### ④ 缺动作节拍（无状态变化）

**症状**：写"女子撑伞走过巷子"，全程无事件、无受力、无结果。

**改写**：按五拍补：
```
触发：雨势加大，伞面接连被大风掀动
启动：女子左手扶紧伞柄，肩膀略微下沉
发展：裙摆下缘被水汽沾湿，深色加重；远处红灯笼在雨雾中泛光
结果：女子抵达巷尾台阶，抬脚迈上第一阶
反应：微微侧头望向身后，确认无人跟来
```

#### ⑤ 多目标同时发生

**症状**：一段写"少年发现珠子丢了 + 同伴叫他 + 他追同伴 + 摊贩让路"，全塞进 4–6 秒。

**改写**：拆镜。一个生成段一个主事；同时发生的事件按时间顺序排入五拍。

#### ⑥ 冻结/轻推当主体

**症状**：让静帧 + Ken Burns 承担叙事推进（"主体在说话时背景慢推"），全片切点变成叠化。

**改写**：见 `重抽与回退决策.md` §三 E 的限制——静帧/冻结/Ken Burns 只作**有意图的短插入**（<2 秒），主体叙事必须用真实生成动作；累计 ≥10% 时停并告知。

#### ⑦ 合同式反模式

**症状**：堆叠 `No / never / doesn't / no text or subtitle appears / No person enters` 等负面约束。Runway/H3 等模型可能没有可靠负面分支，`no subtitle` 甚至可能把 subtitle 激活。

**改写**：正向描述替代（见 §一.8）。硬约束只允许三类（身份连续、人体/道具结构、无画内可读文字），每类写 1 句，不堆叠。

#### ⑧ 首帧冲突 / 运动学失败（一次 S03 A/B 实测 实证）

**症状**：首帧图与目标动作冲突（车已停下 / 人已坐下 / 门已关上），或提示词未填 §一.9 运动合同 9 项，导致主体在画面里**朝向、步态、手-道具接触、车轮运动与世界坐标方向不一致**——人物面朝摄影机却随车向后退；手与车把接触、脚步方向和车轮运动没有形成可信推车动作。

**根因**：状态差 / 摄影机路径 / 焦点转移 / 转场接力只是必要条件，不足以保证镜头成立。当前两镜（S02 泪滴入管不清、S03 人物倒退与接触关系错误）都未通过——S03 此前判的「10/10 通过」作废。

**改写**：
1. **首帧冲突**：按 §一.9 「首帧冲突的硬规则」三选一（重做首帧 / 改 FLF2V / 改运动参考 / 接受回退）；**不要用文字硬拧**（"车还是动的""她其实在走"）。
2. **运动学失败**：补 §一.9 9 项必填字段。镜头方向 vs 主体相对速度不对就改 §一.7 摄影机起讫；脚步 / 重心不对就按 §一.9.4 写「起步脚→承重脚→落脚方向」；手-道具接触不对就按 §一.9.5 写「手指→接触点→承重→解除时机」；车轮 / 持物不对就按 §一.9.6 写「五项方向一致的链式运动」。
3. **姿态/朝向与目标动作冲突**：按 §一.9.2 写明「起始朝向 → 过程朝向 → 终点朝向」；不要只写"他看了看""他走过来"。
4. **轴线 / 视线漂移**：按 §一.9.8 写明角色左右关系始终一致 + 视线看向哪个屏幕方向；不要写"他们对视"。

**记录**：把首帧冲突与运动学失败区分开（前者改首帧 / 改模式，后者改 §一.9 9 项），按 `重抽与回退决策.md` §一.1 三层判定归类（提示词错 / 模式错 / 模型上限）。

### 4.2 改写纪律

- 改写只动对应"症状"那一两段，不整段重写——除非整段都是问题。
- 每次改写保留版本号（v1 / v2 …），记录改写理由与上一版差异，便于回归。
- 改写后再走一遍 §四.1 七条自检（首帧三禁、五拍齐全、摄影机起讫四要素、环境异步、转场接力、硬约束 ≤3、无静态海报）。

### 4.3 情绪词 → 物理量（AGENTS §8.1 详表）

只约束 G4 提示词，不上溯 G1 剧本。每维至少写一项可指认事实；先写“不要什么”作反例脚手架，再改写成画面/声音的肯定事实，反例本身不进正文。

| 维度 | 不要写 | 改写成可指认的物理量 |
|---|---|---|
| 面部 | 愤怒、悲伤 | 眉间收紧程度、嘴角朝向、下颌角度、眼睑开合、面部肌肉用力处 |
| 头发 | 凌乱、狼狈 | 哪几缕偏离、风向、发梢抬起高度、贴在皮肤上的位置 |
| 服装（每层） | 高级感、质感好 | 材质、垂坠、褶皱落点、受光面与阴影面、起球/磨损 |
| 道具 | 精致、破旧 | 材质、尺寸、反光/哑光、边缘磨损、握持手指位置与力度 |
| 湿·脏·血 | 战后、狼狈 | 范围与边界、走向、颜色深浅、反光/变暗 |
| 伤损·妆容 | 憔悴、狼狈 | 位置、面积、颜色、新旧程度、对表情动作的影响 |
| 光线方向 | 氛围感 | 主光方位、高度角、软硬、光比 |
| 时段 | 黄昏、深夜 | 色温倾向、光源高度角、天空与地面明度关系 |
| 天气 | 阴郁 | 能见度、雾/雨/尘、地面湿润程度、云层遮挡比例 |
| 地理 | 有味道、异域感 | 地貌、植被、人工痕迹、天际线、地面材质 |
| 银幕方向 | 紧张 | 人物朝画左/右、运动方向与轴线关系 |
| 视线 | 心虚 | 看向谁/哪里、停留时长、视线与头部转动是否同步 |
| 机位高度 | 压迫感 | 平视/俯仰高度、人物距离、镜头焦段 |
| 色彩调色板 | 高级冷调 | 主色与点缀色色相、明度走向、饱和度关系 |
| 镜头感 | 电影感 | 焦段、景深、像差/畸变、运动方式与速度 |

机检 `python tools/check_emotion_words.py <项目目录>` 只能抓裸词和部分假落点，不能替代语义审查与回放。

```text
- 起点：俯拍近景，灯盏上方 30 cm
- 过程：push in with small amplitude at slow speed 至灯面 15 cm
- 终点：低机位 30° 仰拍，油面与火焰占画面下半
- 焦点：火柴 → 灯芯 → 油面起泡

# 环境异步响应
- 空气：灯芯上方热气向上升起，方向与火焰一致
- 光线：火苗跳动，主光从灯芯位置辐射，桌面阴影向四周摆动

# 转场接力
接力：动作（油面起泡未停）+ 光线（火光稳定）

# 声画事件
- 对白：无
- 环境声：油泡轻响、火苗"噗"声
- 音效：火焰"嘶嘶"
- 配乐：低频弦乐渐强

# 硬约束（≤3 类）
1. 灯芯形态稳定（不消失、不凭空多根）
2. 油面起泡物理合理（不爆炸、不喷溅）
3. 无画内可读文字

# 模式声明
mode: FLF2V
references: <首帧 path> + <末帧 path>
```

## 九、官方提示词规范审计（证据等级 · 平台审计表 · 防串用）

> 核验日期：2026-10-06（Asia/Shanghai）
> 用途：区分官方规范、产品能力、本机实测与社区经验，供通用 Agent 路由和生成前校验使用。
> 证据等级：`OFFICIAL`=官方文档/官方仓库/API；`PRODUCT`=官方产品功能说明但不是提示词语法；`EMPIRICAL`=本机或项目实测；`COMMUNITY`=社区经验；`UNVERIFIED`=当前未取得足够一手依据。
> 纪律：只有 `OFFICIAL` 的字段、引用和限制才可写成平台硬规则；`PRODUCT` 只能写成入口能力；`EMPIRICAL` 必须绑定版本/工作流/日期；`COMMUNITY` 与 `UNVERIFIED` 不得冒充官方。
> 下游：`tools/validate_video_prompt.py` 的生成前预检。本节只登记能力与字段边界，不替代各平台实际接口核验，也不把任何供应商字段变成全体系强制 DSL。

### 9.1 总结结论

1. **H3 是结构化提示词实现**，但必须区分 Base 模式和 Ref2VA；项目旧文把自定义六段标题误称为官方字段，需要纠正。
2. **Seedance 与即梦不能共用一个语法适配器**。Seedance 的多模态引用和原生音频能力不自动等于即梦能力。
3. **Kling、Veo、Runway、Luma、Firefly 主要使用自然语言与产品/接口控制项**，不能把推荐写法包装成固定 DSL。
4. **Vidu 的引用字段和能力随模型/端点变化**；必须按 API 端点登记，不使用一条“全 Vidu”规则。
5. **当前只保留已登记且仍在用的实现**；未登记或已停用的实现不进入生产路由。
6. **PixVerse 当前不具备足够的一手提示词字段证据**；原文中的 Transition、Fusion、Ai-trace-id、积分状态等不得继续作为“提示词规范”。

### 9.4 使用契约

- 通用 Agent 先写平台无关的导演意图，再按本表选择适配器。
- 适配器必须注明 `platform_surface`（产品/UI/API/本地工作流）、`model_or_workflow`、`prompt_contract`、`evidence_level`、`verified_on`。
- 没有固定字段的平台，校验器只阻止语法串台和明显超容量，不强行生成伪 DSL。
- H3 对白镜必须先通过结构校验和一母一女/实际两角色探针，才允许批量。
- 任何平台的官方能力不等于本机已验证；项目《能力登记.md》仍是本片真实路由的最终记录。
