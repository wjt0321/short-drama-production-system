## 0. 模式路由决策树（先选模式，再选平台）

> 决策顺序：**镜头任务 → 生成模式 → 平台 → 提示词写法**。模式决定提示词骨架；平台只决定字段名、引用语法与时长上限。

```
镜头任务（导演意图层）
│
├─ 严格身份 / 跨镜角色一致？
│    ├─ 是 → 参考生视频 / 元素绑定
│    │        平台候选：H3 Ref2VA / Seedance 角色参考 / Kling 角色库 / Runway reference matrix
│    │        若本机只有 H3 + Wan2.2 5B → 优先 H3 Ref2VA
│    └─ 否 ↓
│
├─ 精确 A 状态 → B 状态（液体/接触/变形/受控转场）？
│    ├─ 是 → FLF2V
│    │        平台候选：H3 FL2VA / Seedance 首尾帧 / Veo 首尾帧 / Kling 首尾帧
│    │        若本机只有 H3 → 走 H3 FL2VA（确认参考图/末帧可用）
│    └─ 否 ↓
│
├─ 复杂多目标交互（≥2 主体接触 / 姿态对位 / 道具交接 / 武术）？
│    ├─ 是 → 运动参考 + 参考生视频
│    │        平台候选：Kling 物理强动作 / Seedance 运动参考 / Veo 3.x 物理写实 / ComfyUI 控制族
│    │        本机无 Wan 14B 控制族 / LTX / Hunyuan → 不得假定"运动参考已可用"
│    │        缺模型时降级：拆段 + 参考键补位（先建关键姿态首帧 FLF2V 接），
│    │        复杂武术升级到 Seedance 远程 API 或 Kling / Veo 远程平台
│    └─ 否 ↓
│
├─ 一段 prompt 多镜头连续叙事（一镜到底感）？
│    ├─ 是 → 多镜原生
│    │        平台候选：即梦 3.0 Pro 语义分段 / Seedance "镜头切换" / H3 [Shot N] At MM:SS.mmm
│    │        注意：仅当镜头间空间/人物一致，且每镜都有可观察接力时使用
│    └─ 否 ↓
│
├─ 单镜叙事推进，无精确物理？
│    ├─ 有首帧 → I2V
│    │        平台候选：H3 I2VA / 即梦 3.0 Pro I2V / Seedance 首帧 / Kling I2V
│    │                  Veo I2V / Runway Gen-4 I2V / Luma I2V I2V
│    │                  Firefly I2V / PixVerse I2V / Vidu I2V / Wan2.2 5B I2V
│    └─ 无首帧 → T2V
│             平台候选：H3 T2VA / 即梦 3.0 Pro T2V / Seedance T2V / Kling T2V
│                       Veo T2V / Runway Gen-4 T2V / Luma T2V T2V
│                       Firefly T2V / PixVerse T2V / Vidu T2V
│
└─ 修改已生成的某一段？
     └─ 视频修改
              平台候选：Seedance 视频编辑 / H3 Ref2VA(视频) / Runway Gen-4 modify / Pika modify
```

### 0.1 模式与平台强配表（避免错配）

| 模式 | 强配平台 | 反模式警告 |
|---|---|---|
| FLF2V | H3 FL2VA / Seedance 首尾帧 / Veo / Kling | 不要用 T2V-only 模型跑 FLF2V（如 Luma 原生 T2V 时代） |
| 多镜原生 | H3 [Shot N] 时间戳 / 即梦 3.0 Pro / Seedance | 不要在不支持多镜的模型（Gen-4、Firefly）强行写"镜头切换" |
| 参考生视频 | H3 Ref2VA / Seedance / Kling / Runway | 不要在 T2V-only 模型跑参考生视频（如部分 PixVerse 模式） |
| 运动参考 | Kling / Seedance / Veo 3.x / ComfyUI Wan 14B 控制族 | 不要在不支持的模型（Runway Gen-4 部分版本）写"参考 @Video" |
| 视频修改 | Seedance / H3 Ref2VA / Pika / Runway | 不要在不支持的模型（Veo）做局部修改 |

### 0A.1 写作语言

| 平台 | 官方写作语言 | 中文内容策略 |
|---|---|---|
| **MiniMax H3** | **英文** | 对白/画面文字保留原文；其余全英文 |
| **即梦 3.0 Pro** | **中文** | 中文原生；不要英译 |
| **Seedance 2.0/2.5** | **中文** | 中文原生；不要英译 |
| **Kling 3.0** | 以当前产品入口为准 | 推荐组织法：场景 → 角色 → 动作 → 镜头 → 声音；不是固定官方 DSL |
| **Veo** | 英文自然语言 | 主体/场景/动作/摄影机/光线/声音；不套 H3 固定字段 |
| **Runway Gen-4/4.5** | 英文自然语言 | I2V 文本主要写运动与摄影机；参考矩阵不是 prompt DSL |
| **Luma Dream Machine** | 英文 | `@character`/`@style` 引用；loop 关键词 |
| **Firefly Video** | 英文 | Content Credentials 自动加；UI style/composition preset |
| **PixVerse** | 入口待核验 | 不把产品工作流、追踪字段或积分状态写成 prompt grammar |
| **Vidu** | 按 API/模型 | 以 `subjects`、主体名称和当前模型限制为准 |
| **ComfyUI 本地** | 按节点模型 | Wan/LTX/Hunyuan/H3/伙伴云节点；本机能力见 §0B |

## 0C. 精确交互 / 复杂运动升级规则

> 当本机能力不足时，**先改模式再换平台**。改模式优先于换平台，因为模式改错的影响是叙事级的，平台只是载体。

### 0C.1 三步升级路径

```
第一步：模式降级
  当镜头需要"精确 A→B 物理过渡"或"≥2 主体接触"但本机不支持 FLF2V / 运动参考时：
    · 拆段：把这一镜按关键姿态切成 2–3 段
    · 每段用 I2V：上一段末帧 → 下一段首帧，强制首尾衔接
    · 每段写摄影机起讫 + 转场接力，避免拼接受挫
    · 这是"伪 FLF2V"，节拍可接受，物理精度损失

第二步：平台远程升级
  当模式降级无法承载（武术、复杂道具交接、多人共舞）时：
    · 切到远程 API（Seedance 2.5 / Kling 3.0 / Veo 3.x）
    · 远程路由：Seedance 运动参考 / Kling 物理强动作 / Veo 物理写实
    · 项目 `00-立项/能力登记.md` 必须登记远程 API 凭据与计费单元
    · 升级前先做最小样片（1 镜），不直接扩到全片

第三步：本地模型补充
  当远程 API 也无法满足（成本 / 时延 / 离线要求）时：
    · 下载对应模型到本地（Wan 14B FLF2V / LTX-Video / HunyuanVideo）
    · 更新本文件 §0B 表
    · 重做最小样片
    · 通过后方可扩大生产
```

### 0C.2 升级触发条件（什么时候必须升级）

| 触发信号 | 含义 | 升级路径 |
|---|---|---|
| 同一镜 2 次仍失败 | 提示词可能不是根本问题 | 第一步：拆段 + I2V 强制首尾 |
| 拆段后跨段成像拼接 | 物理精度损失过大 | 第二步：远程 API（首选 Seedance / Kling） |
| 远程 API 仍无法 | 模型上限真的不足 | 第三步：本地补模型 |
| 全片 ≥ 30% 镜需远程 | 远程成本/时延越界 | 第三步：本地补模型 |
| 用户要求"必须离线" | 安全/合规边界 | 第三步：本地补模型 |

### 0C.3 升级不做的事

- **不静默改写分镜**：升级是技术路径调整，分镜叙事不变；改叙事必须回到 `02-分镜与镜头/分镜工作流.md`
- **不静默删除重抽预算**：升级也不能重置项目总投入上限
- **不假装"已可用"**：未实际跑通最小样片的能力，禁止在 SOP/路线图/对外文档中宣称具备
- **不停留在"工具支持"的承诺层**：H3 平台"支持"不代表本片这一镜一定成功；以实际跑通为准

### 0C.4 升级记录

每次升级至少记录：

- 升级触发信号（哪一镜、什么症状、跑了几次）
- 选定的目标模式与目标平台（含远程/本地）
- 最小样片结果（覆盖条件、实测成功率、成本/时延）
- 是否回到默认路线继续开会
- 升级后该能力是否加入 §0B 表（标记已具备）

## 细节充分且遵守实际长度

先读当前实现/版本的实际说明，核实必填字段、语言、参考语法与长度单位（字、词、字符或token不可混同）。下文数值有官方/社区与版本差别，不视为全供应商硬限制；未规定长度时不自造统一上限。不要求写满最大长度，若需计数使用工具对应口径，不凭视觉估算宣称合规。

由剧本和分镜转写提示词时保留：引用资产与起始构图、主要行为的触发/过程/结果、人物反应与视线、关键空间和道具变化、摄影机如何观察及结束、必要对白/环境声。按工具字段分别放置，原生不支持的能力另选实现，不一律删除内容。多镜头段按真实节拍组织，时间足够说话和完成动作；生成档位不反过来决定内容秒数。

长度受限时先删重复风格词、万能质量词和无作用装饰，再压缩固定描述（只有工具真正支持引用时才可用引用省字）；保住主动作、关系、关键反应、状态和对白。仍装不下则按内容关系拆技术段，不能截断官方字段、对白或必要因果。细节写具体而有顺序，不让多种表情和动作同时发生。重点不是更长，而是模型知道这一段会发生什么。

最终对照上游：原剧本的关键事件是否还在、提示词里的动作是否真能从首帧开始、末状态能否承接下一段。补查动作的时间顺序与持续性、人物注意力/视线、接触与遮挡、受力与物理反馈，以及必要的同步声音/光影变化。光线提示写主光来源和方向、主体受光、辅光/轮廓/反射层、阴影落点与色温关系；连续镜头沿用光线基准，只有有内容理由才改变。只给首帧加推拉与背景微动不算完成转写；确实需要静止观察的段落则保留，不机械添加眨眼或动作。
